Dashboard — one cursor, pointer or keyboard

Every row is a control, and the highlight is driven by both the pointer and the keyboard cursor, the way Omarchy's own panels do it (hot = containsMouse || hasCursor, and the hover signal moves the panel's cursor so the two never disagree). Move the mouse over the rows; then use j / k or the arrows without touching the mouse — the same highlight moves. Click a switch row to stage it, click a list row to open its editor. Hover the day ramp to read any hour. Paint priority, fill alphas, the 120 ms colour transition and the 400 ms tooltip delay are the kit's, not invented. Border width never changes between states, so hovering never nudges a neighbouring row — the kit reserves the largest border for exactly that reason.

Editing a list — the four keys that could not be reached

The site list, the blocklist/allowlist mode, game blocking and the allowlist are classified by the signer already but were absent from the only sanctioned editor, so they were frozen. Here they are controls. A list editor is a SelectionList (click to strike an entry) plus an add field, and every pending change carries its own direction — struck entries loosen, added ones tighten — with the cost stated before anything is authorised. Cost rule: one token per list touched, per commit. Two lists in one commit is two tokens. Use the chips at the top to switch between the four lists; the entries are the real ones from the running config, and the games list is what the catalogue actually detected on this machine.

Staged & commit — the cost before the fingerprint

The tray holds everything staged, grouped by what it costs, with the running total against what is left. The commit control is refused with its reason visible rather than silently dead — hover it. Switch the state to locked in the bottom-left to see the whole tray go unauthorisable because the clock window is shut, which is the rule that has to be legible before any authentication, never after.
