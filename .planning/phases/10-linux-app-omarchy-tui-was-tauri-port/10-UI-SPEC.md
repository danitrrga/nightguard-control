# Phase 10 — UI Design Contract (omarchy Textual TUI)

> Visual and interaction contract for the **Linux thin-client TUI**. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **MEDIUM NOTE — read first.** This is **not** a web/browser UI and **not** a desktop GUI. It is a **terminal TUI built with Textual** (Python 3.14, Textual 8.2.7). Every dimension below is **re-mapped to the terminal medium**:
> - **"Typography"** = terminal cells + Rich text styles (bold / dim / reverse / italic), box-drawing characters, and Unicode glyphs. There are **no** web fonts, px, rem, or pixel spacing — the font is the user's terminal font (this contract does not own it).
> - **"Spacing"** = terminal **rows/columns** and Textual CSS units (`fr`, cells, `%`), not an 8-point pixel scale.
> - **"Color"** = **semantic roles** that bind to **omarchy live theme variables** (`~/.config/omarchy/current/theme/colors.toml` → Textual `Theme`). **No fixed hex is the brand.** The Windows "Moonlit Indigo" palette is **SUPERSEDED** (CONTEXT.md D-02). The hexes shown in the Color section are **today's live `everforest` values for illustration only** — they are NOT the contract; the role→variable binding is.
> - **"Components"** = Textual widgets / screens / Textual-CSS classes — **not** React/Tailwind/shadcn.
> - **"Interaction"** = **single-key, keyboard-only** (CONTEXT.md D-03) via Textual `BINDINGS` — no mouse-first or arrow-menu primary navigation.

## Design System

| Property | Value |
|----------|-------|
| Tool | none (Textual TUI — shadcn/registry not applicable) |
| Preset | not applicable (no web design system) |
| Component library | **Textual 8.2.7** widgets (`Static`, `Label`, `Input`, `Footer`, `Header`, `Switch`, custom widgets) |
| Icon library | **Unicode glyphs only** (box-drawing + emoji/symbols); no icon package, no bundled fonts |
| Font | **N/A — the user's terminal font** (TUI does not specify or bundle fonts; lean-deps constraint) |
| Styling | **Textual CSS** (`.tcss`) with `$variable` roles fed from the live omarchy theme (D-01/D-04) |
| Theme source | `~/.config/omarchy/current/theme/colors.toml` → `tomllib` → Textual `Theme`, **live-watched + repaint** (D-04/D-05; RESEARCH Pattern 4) |

**Locked stack (from RESEARCH Standard Stack):** Textual `8.2.7`, Python `3.14.6` (venv via `uv`, PEP-668), optional `watchfiles 1.2.0` (else stdlib mtime poll). No YAML emitter — per-field line-edits on loaded text (preserves the bytes the HMAC signs).

## Layout & Screen Composition

> Replaces the web "Spacing Scale" section. Spacing is in **terminal rows/columns** and Textual layout units.

### Screen model

**Two screens, single-key driven (D-03):**

| Screen | Purpose | Entry |
|--------|---------|-------|
| `StatusScreen` (default/home) | The read-only status surface (D-10): lock + countdown, token meter, grace, hmacs, ledger | App start; `Escape` from any screen returns here |
| `EditScreen` (modal/pushed) | The editable surface (D-09) + the anti-impulse preview (D-06) + inline-sudo commit (D-08) | `e` from Status |

A single status screen (not tabs). The ledger is the only optionally-collapsible region (see below). No tabbed navigation — it would violate the single-key minimal model.

### StatusScreen composition (top → bottom)

```
┌─ Header (Textual Header: app title "nightguard" + clock) ───────────────┐
│                                                                          │
│   ╭──────────────────── HERO (status band) ─────────────────────╮       │
│   │   ● LOCKED            04:13:27                              │       │  ← lock word + live countdown
│   │   curfew until 05:30                                         │       │     (countdown = the only 1s-refreshed cell)
│   ╰──────────────────────────────────────────────────────────────╯       │
│                                                                          │
│   TOKENS   ● ● ○   2 of 3 left · resets Mon 2026-06-30                   │  ← 3-glyph meter (D-10)
│   GRACE    unavailable today        (display-only this phase, D-11)      │
│                                                                          │
│   ╭─ integrity ─────────────────────────────────────────────────╮       │
│   │ config_hmac  7618c4a2…f01b      state_hmac  94d8ee01…77ac    │       │  ← hmacs, dim, truncated (D-10)
```

### Layout units (Textual)

| Region | Container | Sizing |
|--------|-----------|--------|
| Root | `Vertical` | full screen |
| Header / Footer | Textual `Header` / `Footer` | docked top/bottom, height `1` row each |
| Hero band | `Container` (`#hero`) | height `auto` (≈4–5 rows), centered content, `border: round $primary` |
| Tokens / Grace lines | `Horizontal` rows | height `1` each, `label` column fixed `width: 10`, value column `1fr` |
| Integrity panel | `Container` | height `auto`, `border: round $surface-lighten-1`, `dim` text |
| Ledger panel | `VerticalScroll` | `height: 1fr` (takes remaining space), `border: round $surface-lighten-1` |

### Spacing rules (rows/cells, not px)

| Token | Value | Usage |
|-------|-------|-------|
| gutter | `1` cell | Horizontal padding inside every bordered panel (`padding: 0 1`) |
| stack-gap | `1` row | Blank row between hero / tokens-grace block / integrity / ledger |
| label-col | `10` cells | Fixed left-column width for `TOKENS` / `GRACE` aligned labels |
| meter-gap | `1` cell | Space between the 3 token glyphs |

**Exceptions:** Countdown is the only cell that updates on the 1s tick; the status word never re-renders on tick (mirrors Windows T-04-14 — avoid flicker / false-reflow).

## Typography (terminal text styles)

> Replaces web font sizes/weights. There are no px or font weights — only Rich/Textual **text styles** and **glyph choices**. Declared roles (exactly the set the executor may use):

| Role | Style | Where used |
|------|-------|------------|
| Hero countdown | `bold`, primary-tinted, large via spacing (no font scaling exists) | The `HH:MM:SS` countdown in the hero band |
| Status word | `bold` + a leading state **glyph** (see below) | `LOCKED` / `GRACE` / `OPEN` |
| Section label | `bold` `$text` | `TOKENS`, `GRACE`, panel titles (`integrity`, `audit ledger`) |
| Body / value | default weight `$text` | values, ledger rows, copy |
| Dim / secondary | `dim` (`$text-muted`) | hmacs, hints, captions, "resets Mon …" |
| Reverse / focus | `reverse` | the currently-focused edit field highlight |

**Line height / leading:** N/A in a terminal (one cell = one row). Vertical rhythm is the `stack-gap` row above.

**Glyph vocabulary (Unicode, theme-independent so it survives no-color):**

| Meaning | Glyph | Notes |
|---------|-------|-------|
| Locked | `●` (filled) | paired with the `error`/`warning` color role AND the word `LOCKED` |
| Grace active | `◐` (half) | paired with `accent` AND the word `GRACE` |
| Open / unlocked | `○` (hollow) | paired with `success` AND the word `OPEN` |
| Token available | `●` | filled dot |
| Token spent | `○` | hollow dot |
| Loosen direction (preview) | `▲` up-arrow + word `LOOSENS` | cost-bearing — see preview |
| Tighten direction (preview) | `▼` down-arrow + word `TIGHTENS` | free |
| No change | `·` + word `no change` | dim |

**Rule:** every state is conveyed by **glyph + word + color** together — never color alone (see Accessibility).

## Color (semantic roles → omarchy theme variables)

> **The contract is the role→variable binding, NOT the hex.** Colors are owned by the live omarchy desktop theme and **repaint at runtime** when the desktop theme changes (D-04/D-05). The "live (everforest)" column is **today's value for illustration only** and MUST NOT be hardcoded.

### Role → omarchy `colors.toml` key → Textual `Theme` field

| Semantic role | omarchy `colors.toml` key | Textual `Theme` field / `$var` | Live (everforest, illustrative) | Usage |
|---------------|---------------------------|--------------------------------|---------------------------------|-------|
| **Background (dominant ~60%)** | `background` | `Theme.background` / `$background` | `#2d353b` | App canvas, default screen background |
| **Surface (secondary ~30%)** | `color0` (fallback `background`) | `Theme.surface` / `$surface` | `#475258` | Panel fills (integrity, ledger, edit fields), borders |
| **Foreground (text)** | `foreground` | `Theme.foreground` / `$text` | `#d3c6aa` | All primary text |
| **Dim / muted** | `color8` / derived (`$text-muted`) | `$text-muted` | `#475258`-ish | hmacs, hints, captions, "resets …" |
| **Accent (~10%, reserved)** | `accent` (== `color4`) | `Theme.primary` + `Theme.accent` / `$primary` `$accent` | `#7fbbb3` | **Reserved list below** |
| **Success** | `color2` (green) | `Theme.success` / `$success` | `#a7c080` | `OPEN`/unlocked glyph+word; "committed …" result line |
| **Warning / refusal** | `color3` (yellow) | `Theme.warning` / `$warning` | `#dbbc7f` | Loosen-cost preview ("costs 1 token"); non-punitive offline/blocked notices |
| **Error / locked / hard-refusal** | `color1` (red) | `Theme.error` / `$error` | `#e67e80` | `LOCKED` glyph+word; `REFUSED (…)` result line; tamper |

> Textual auto-derives shade variants (`$surface-lighten-1`, `$primary-darken-2`, etc.) from these base roles — use those for subtle panel borders rather than introducing new colors.

### Accent (~10%) reserved for — explicit list (never "all interactive elements")

The `accent`/`$primary` color is reserved ONLY for:
1. The **hero band border** (`border: round $primary`) and the hero countdown tint.
2. The **grace** glyph/word `◐ GRACE` when grace is active.
3. The **`TIGHTENS · free`** preview line (a free, sanctioned tightening — the "good" path).
4. The **currently-focused edit field** label accent (focus ring is `reverse`, the field label gets `$accent`).

Accent is **NOT** used for: ordinary text, panel fills, the footer legend, plain values, or the locked/open status (those use error/success).

### Theme-change behavior (D-05, live repaint)

- On mount: parse `colors.toml` → build `Theme(name="omarchy", …)` → `register_theme()` → set `App.theme = "omarchy"`.
- On theme change (detected by mtime poll on the 1s tick, or `watchfiles`): re-parse, **re-register the same name** (overwrites), reassign `App.theme` → Textual refreshes all `$variables` and repaints (RESEARCH Pattern 4, A3).
- **Fallback if `colors.toml` absent** (Pitfall 6): parse `alacritty.toml` (`[colors.primary]` / `[colors.normal]`) into the same roles.
- **No-color / low-color terminal fallback:** see Accessibility — the app must remain legible if the theme yields a monochrome or low-contrast palette.

## Interaction — Single-Key Keybinding Map (D-03)

> The full command surface. Single keystroke per action, surfaced live in the Textual `Footer` legend (PORT-01 "command-driven, minimal"). Lowercase, no modifiers, no arrow-menu as the primary model.

### StatusScreen bindings

| Key | Action | Effect |
|-----|--------|--------|
| `e` | `edit` | Push `EditScreen` |
| `r` | `refresh` | Re-read state (re-run `load_state` + `curfew_verdict`); repaint meter/status (no optimism) |
| `l` | `ledger` | Toggle ledger panel expanded ↔ last-5 collapsed |
| `q` | `quit` | Quit the app |

### EditScreen bindings

| Key | Action | Effect |
|-----|--------|--------|
| `j` / `k` | `field_next` / `field_prev` | Move focus between editable fields (vertical list; the ONE place arrow-like nav is allowed, kept to home-row j/k) |
| `Enter` | `edit_field` | Begin inline edit of the focused field (text `Input` for windows/lists, `Switch` toggle for `*.enabled`) |
| `Space` | `toggle` | Toggle the focused boolean field (`curfew.enabled`, `clock_protection.enabled`, `watchdog.enabled`, `blocking.*.enabled`) |
| `c` | `commit` | Open the **confirm + preview** for the staged change, then inline-sudo commit (D-06/D-08) |
| `u` | `undo` | Discard all staged edits; revert fields to sanctioned values |
| `Escape` | `back` | Return to StatusScreen (discards unstaged in-field edit; warns if staged edits pending) |

**Discoverability:** the `Footer` auto-renders every binding's label as the persistent single-key legend. No hidden commands.

### Per-field edit mechanism (Claude's discretion, resolved)

| Field type | Fields | Mechanism |
|------------|--------|-----------|
| Time window | `curfew.start`, `curfew.end` | Inline `Input` masked `HH:MM`; validated on blur (reject non-`HH:MM`) |
| Boolean toggle | `curfew.enabled`, `clock_protection.enabled`, `watchdog.enabled`, `blocking.browser_extension.enabled`, `blocking.native_apps.enabled` | `Switch` widget; `Space` toggles |
| String list | `curfew.allow_commands`, `blocking.native_apps.blacklist` | Inline list editor: `Enter` to add a row (`Input`), `d` on a focused row to delete; one entry per row |
| String value | `blocking.browser_extension.extension_id` | Inline `Input` (free text) |

Diff base for current values AND preview is **`config.sanctioned.yaml`**, not live `config.yaml` (RESEARCH Pitfall 5).

## The Anti-Impulse Edit Preview (D-06 / D-07) — load-bearing

> The core anti-impulse moment: **tighten/loosen direction + token cost must be unmistakable BEFORE the sudo prompt.** Computed in-process by importing `nightguard_ctl.classify_change` + `quota_decide` (D-07; RESEARCH Pattern 3) — never recomputed.

### Live per-field feedback (shown on each staged edit, before `c`)

| Classifier result | Glyph + word | Color role | Copy |
|-------------------|--------------|-----------|------|
| `tighten` (cost-free) | `▼ TIGHTENS` | `$accent` (the "good"/free path) | `▼ Tightens curfew · free` |
| `loosen` (costs a token) | `▲ LOOSENS` | `$warning` | `▲ Loosens curfew · costs 1 token` |
| `noop` | `· no change` | `$text-muted` (dim) | `· no change` |
| `loosen` but `quota_decide.allowed == False` | `▲ LOOSENS` + `✕ BLOCKED` | `$error` | `▲ Loosens · BLOCKED — weekly tokens exhausted (3/3); available again Monday` |

### Confirm gate (on `c`, BEFORE sudo)

A modal `ConfirmScreen` that states the consequence in one unmistakable line, then requires an explicit second keystroke:

- **Free tighten / multi-field tighten:** `▼ This change TIGHTENS your curfew · free.  Commit?  [y] yes  [n] no` — no token language.
- **Loosen (token available):** `▲ This change LOOSENS your curfew · costs 1 of 3 weekly tokens.  After commit: 1 left.  Commit?  [y] yes  [n] no` — warning color, token count explicit.
- **Loosen (no tokens):** commit is **disabled** — show `✕ Cannot commit: weekly loosen quota exhausted (3/3). Available again Monday.` in `$error`; only `[n]` / `Escape` available. (Mirrors Windows UI-04 disabled-commit with the locked "available again Monday" substring.)

**Hard rule (anti-impulse):** the **token cost and direction are rendered before any sudo/password/fingerprint prompt is reached** (D-06). The `y` keystroke is what triggers `suspend()` + `sudo … commit`. There is no path where the user authenticates first and learns the cost after.

## State & Feedback Rendering

> The result/transition surface. All result text comes from the **CLI's actual stdout/exit** (RESEARCH Pattern 5) — never fabricated by the TUI.

| State | Rendering | Color role |
|-------|-----------|-----------|
| **Inline auth transition (D-08)** | `with self.suspend():` releases the TTY; `sudo` password / **fingerprint** prompt appears inline on the real terminal (Pitfall 3). App shows nothing during suspend — the terminal belongs to sudo. On resume, render the result line. | terminal-native |
| **Commit success** | One line from CLI stdout: `✓ committed (<dir>, <free \| -1 token>): config_hmac=… · tokens N/3 used`, then auto-`refresh` of meter/status (no optimism). | `$success` |
| **Commit refused (quota/direction)** | One line from CLI stderr verbatim: `✕ REFUSED (<direction>): <reason>` (e.g. `REFUSED (loosen): weekly loosen quota exhausted (3/3 used); available again Monday`). | `$error` |
| **No-op commit** | `· no-op: proposed config is identical to sanctioned; nothing written.` | `$text-muted` |
| **Offline / time-unverified** | When the verdict is `offline_blocked` or NTP is unreachable: status hero shows `● LOCKED` + caption `time unverified — guard keeps the house closed`; never widen/optimistically unlock. Non-punitive tone. | `$warning` for the caption, `$error` for the lock |
| **Clock tamper** | Verdict `clock_tamper` → `● LOCKED` + caption `clock tamper detected — locked`. | `$error` |
| **State unverifiable (no key, advisory)** | The TUI cannot verify hmacs (PORT-03). Display verdict as **advisory** — footer/hero caption: `status reflects what the guard will enforce`. Never claim authority; never show OPEN optimistically when state is dubious. | `$text-muted` caption |
| **Empty ledger** | `no audit entries yet` (dim, centered in the ledger panel). | `$text-muted` |
| **Not initialized** | If `guard.json` / config absent: full-screen `nightguard is not initialized on this machine` + dim hint `run nightguard_ctl.py init`. | `$text-muted` |

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA (commit, free tighten) | `Commit` → confirm `Commit?  [y] yes  [n] no` |
| Primary CTA (commit, loosen) | `Commit (spends 1 token)` → confirm `costs 1 of 3 weekly tokens. After commit: N left.` |
| Edit entry hint (footer) | `e edit · r refresh · l ledger · q quit` |
| Empty state — ledger | `no audit entries yet` |
| Empty state — not initialized | `nightguard is not initialized on this machine` / hint: `run nightguard_ctl.py init` |
| Error — refused | `REFUSED (<direction>): <reason>` (verbatim from CLI stderr) |
| Error — quota blocked (preview/confirm) | `Cannot commit: weekly loosen quota exhausted (3/3). Available again Monday.` |
| Error — offline | `time unverified — guard keeps the house closed` |
| Error — tamper | `clock tamper detected — locked` |
| Success — commit | `committed (<dir>, <free \| -1 token>): … · tokens N/3 used` (verbatim from CLI stdout) |
| Token meter caption | `N of 3 left · resets Mon YYYY-MM-DD` |
| Grace (display-only) | active: `◐ grace active · MM:SS remaining` · else: `grace unavailable today` |
| Advisory caption | `status reflects what the guard will enforce` |
| Destructive action — discard staged edits (`u`) | `Discard all staged edits?  [y] yes  [n] no` |
| Destructive action — loosen commit | (see confirm gate) — explicit token spend, second keystroke required |

**Destructive actions in this phase:**
1. **Loosen commit** — spends a finite weekly token. Confirmation: explicit single-line cost preview + `y` keystroke (the anti-impulse gate) + the real sudo password/fingerprint prompt. Never one-tap.
2. **Discard staged edits (`u`)** — loses unsaved field edits. Confirmation: `[y/n]` prompt (lighter — no token at stake, but not silent).

> Tone: minimal, factual, non-punitive on refusals/offline (the wall is firm but not scolding). Direction + cost language is **always explicit and front-loaded** (the product's whole reason to exist).

## Accessibility & Clarity in a Terminal

> Replaces web a11y. Because colors are **theme-driven and variable**, the UI must never rely on color alone.

| Concern | Contract |
|---------|----------|
| **No color alone** | Every status carries **glyph + word + color** (e.g. `● LOCKED` red, `○ OPEN` green, `▲ LOOSENS · costs 1 token`). Stripping color must leave the meaning intact. |
| **No-color / monochrome terminal** | If the theme yields low/no contrast (or `NO_COLOR` is honored by the terminal), the glyph + word still distinguish every state. Token meter (`● ● ○`) reads as filled vs hollow without color. |
| **Direction redundancy** | Tighten/loosen is `▼`/`▲` glyph **and** the words `TIGHTENS`/`LOOSENS` **and** the warning/accent color — three redundant channels for the load-bearing anti-impulse signal. |
| **Focus visibility** | The focused edit field uses `reverse` (inverse video) + an `$accent` label — visible regardless of palette. |
| **Keyboard-only** | The entire app is operable without a mouse (D-03); Textual `Footer` keeps the key legend always visible (discoverability). |
| **Screen-reader / narrow terminals** | hmacs are truncated (`…`) to avoid horizontal overflow on narrow terminals; panels use `auto`/`1fr` so the layout reflows down, never clips the hero or footer. |
| **Glyph fallback** | Glyphs chosen from common Unicode (`● ○ ◐ ▲ ▼ · ✓ ✕`) widely present in monospace terminal fonts; no private-use or rare emoji that may render as tofu. |
