<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| OS env -> all consumers | NIGHTGUARD_DIR (user scope) is the single resolution input; a wrong/unset value is the cutover landmine |
| Rust signer -> on-disk guard.json/.guardkey | The Rust host is the SOLE signer; key + signed state cross the process boundary to disk where the guard reads them |
| config.yaml bytes -> HMAC | Byte form (BOM/CRLF/trailing newline) must be canonical or PS and Rust disagree on the tag |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-01 | Tampering | .guardkey scope | mitigate | load_or_create_key uses DPAPI Scope::User + None entropy (locked Phase 1) — identical on both sides; reuse the proven primitive, never a custom CryptProtectData call |
| T-05-02 | Spoofing | guard.json state_hmac | mitigate | state_hmac via the single locked compute_state_hmac A3 recipe; Task 2 cross-verifies Rust<->PS re-derive equality before this plan is accepted |
| T-05-03 | Tampering | config canonical bytes | mitigate | canonicalize_bytes (UTF-8/no-BOM/LF/one-trailing-LF) before HMAC; config.sanctioned.yaml is a byte-exact copy so Test-SanctionedValid identity holds |
| T-05-04 | Elevation | week_anchor forgery via naive math | mitigate | week_anchor from most_recent_monday_midnight (DST-aware); acceptance grep forbids +7*24h / weekday-subtraction |
| T-05-05 | Denial of Service | NIGHTGUARD_DIR set but live gate still active | accept | Plan 01 sets the var and inits state WITHOUT touching settings.json or the watchdog task; the legacy gate keeps protecting until Plan 03's gated cutover (no window unprotected) |
</threat_model>
