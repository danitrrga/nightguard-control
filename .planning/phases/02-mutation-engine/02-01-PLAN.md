<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| disk → engine | guard.json / config.yaml bytes read from disk are untrusted until HMAC-verified |
| engine → disk | the engine is the sole sanctioned writer/signer; bytes it writes must equal bytes it signs |
| Rust ↔ PowerShell guard | guard.json schema + state_hmac recipe is a cross-language interop contract (Phase 3 parses it) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Tampering | state_hmac over guard.json | mitigate | Lock the A3 recipe (serialize with state_hmac="", canonicalize, sign) and prove reproducibility in tests/state.rs; Phase 3 must re-derive identically |
| T-02-02 | Spoofing | config_hmac vs on-disk bytes | mitigate | sign.rs computes the tag over `canonicalize_bytes` output and returns the SAME bytes for writing (Pitfall 3) — test asserts tag == HMAC(on-disk bytes) |
| T-02-03 | Tampering | schema drift between Rust and PS guard | accept (this plan) → mitigate (plan 05) | Schema field names/types locked here as the interop contract; the cross-language state_hmac parity gate is plan 02-05 |
| T-02-SC | Tampering | cargo dependency installs (chrono-tz, sntpc, fd-lock, yamlpath, yamlpatch, serde) | mitigate | All packages [OK] in 02-RESEARCH.md Package Legitimacy Audit (slopcheck this session); no [ASSUMED]/[SUS]/[SLOP] — no human checkpoint required |
