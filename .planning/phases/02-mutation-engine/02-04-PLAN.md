<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| concurrent writers → commit critical section | another process/thread (or a racing app instance) could interleave writes and produce a forged/partial state |
| crash/interruption → on-disk state | an interrupted commit must never leave a forged-but-unsigned or inconsistent state |
| app clock → grace day boundary | grace eligibility must be NTP-true-time-boxed, not app-clock-boxed |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-10 | Tampering | partial/interrupted commit leaving a forged or inconsistent middle state | mitigate | Ordered atomic writes (sanctioned -> guard.json -> live) so every crash point converges to OLD or NEW; commit_order.rs proves convergence for stop-after-N in {0,1,2} |
| T-02-11 | Elevation of Privilege / TOCTOU | concurrent writers racing the commit critical section | mitigate | fd-lock exclusive (LockFileEx + LOCKFILE_EXCLUSIVE_LOCK) held across the entire ordered sequence AND across use_grace; RAII release on drop/crash (handle close) — no stale lock |
| T-02-12 | Spoofing | clock manipulation to forge a second grace in one true day | mitigate | true-day derived from the NTP true-now instant in the configured tz (Pitfall 4), not Local::now(); same-day reuse refused; NTP-unreachable refused (fail-closed) |
| T-02-13 | Repudiation | sign-vs-write race causing the guard to revert a legitimate write (GARD-05 foreshadow) | mitigate | live config.yaml is written LAST, after re-signing; never write live before guard.json — commit_order.rs enforces the ordering |
| T-02-14 | Tampering | forged/replayed signed state granting extra grace/tokens | mitigate | state_hmac re-derived over canonical bytes via the locked recipe on every write; key never leaves DPAPI (trust-kernel) |
</threat_model>
