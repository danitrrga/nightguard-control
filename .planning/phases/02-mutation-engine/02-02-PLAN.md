<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| proposed config → classifier | the proposed YAML is attacker-influenced edit intent; classification must be conservative (field-missing = noop, never a silent loosen) |
| system clock → week reset | a manipulated clock could try to fake a new week to reset the token budget |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-04 | Elevation of Privilege | quota.rs week reset via clock manipulation | mitigate (partial) | Reset is computed deterministically from the passed instant + configured tz; the AUTHORITATIVE clock for grace is NTP (plan 02-04). Quota reset is conservative — a forward-clock fake only resets a budget the user already controls via the app; the binding value (grace) is NTP-gated. Documented as accepted residual: quota reset trusts the supplied instant, which callers must source responsibly. |
| T-02-05 | Tampering | classifier misses a loosen, granting a free loosen | mitigate | Every spec-table row has a covering test; field-missing defaults to Noop (never a hidden loosen); `is_loosening_commit` is true iff ANY field loosens (fail-safe toward charging a token) |
| T-02-06 | Spoofing | naive +7*24h week math drifts the reset across DST, mis-timing the budget | mitigate | week.rs uses chrono-tz from_local_datetime with explicit MappedLocalTime handling; a grep gate asserts no `weeks(1)` literal; a synthetic DST-week test proves correctness |
</threat_model>
