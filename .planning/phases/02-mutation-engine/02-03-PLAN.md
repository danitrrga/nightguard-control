<objective>
Implement the NTP true-time module (RULE-05's time half): a synchronous SNTP query via `sntpc 0.10.1` + `sntpc-net-std`, mapping every SNTP error to a typed `NtpUnreachable` so grace is refused whenever true time cannot be established. Hide the live UDP behind a `TrueTime` trait so the quota/grace logic stays offline-testable.

Purpose: This is the one no-analog module (no networking existed in Phase 1). Isolating UDP behind a trait is what lets plan 02-04's grace logic be tested deterministically without a network; only a single live integration test touches real UDP.
Output: ntp.rs (the `NtpTrueTime` type, the `TrueTime` trait, a real `SntpTrueTime` impl, and a typed `NtpUnreachable`) + tests.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| network → engine | the SNTP response is from an untrusted network path; only used for a coarse true-time gate, never as a security oracle beyond "is the app clock plausibly correct" |
| app system clock → grace eligibility | the app's local clock is explicitly NOT trusted for grace/day boundaries — true time must come from NTP |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-07 | Spoofing | clock manipulation to forge grace eligibility / reset a day boundary | mitigate | Grace day-boundary derives from the NTP true-now instant (plan 02-04), not Local::now(); ntp.rs is the true-time source |
| T-02-08 | Denial of Service | NTP unreachable (offline) used to bypass refusal | mitigate (fail-closed) | Any SNTP error -> NtpUnreachable -> grace REFUSED (RULE-05). Unreachable is itself a tested refusal path; the PowerShell guard also block_when_offline independently |
| T-02-09 | Tampering | SNTP response spoofing to widen a grace window | accept (residual) → mitigate downstream | App-side NTP is advisory; the Phase 3 guard re-checks the window with its OWN NTP before honoring it (defense in depth per design-spec grace), so an app-side spoof cannot unilaterally widen the enforced window |
</threat_model>
