<objective>
Turn the structural half of the live desktop theme into something the TUI can actually
consume.

`omarchy_style()` already parses `shell.toml`, but its only consumer is the headless bar
panel feed (`ngtui/ngtui/__main__.py:136` → `panel.style_view`) — which is precisely why the
terminal UI still looks like a terminal form while faithfully following the desktop's
colour. This plan widens what it reads, adds the live compositor's corner radius, and adds
the pure mapper that turns the result into CSS variables.

Purpose: this is the half of the token pipeline that has no Textual in it, so it is the
half that can be unit-tested headlessly. Everything the next plan wires into the running app
is proved here first, without an App.
Output: `theme.py` grows four capabilities; three controls go green.
</objective>

  <action>
    **`hypr_rounding(timeout: float = 0.4) -> int`.** Ask
    `hyprctl getoption -j decoration:rounding` and return `["int"]`. Check `returncode`
    **before** parsing: hyprctl writes its errors to *stdout* with a non-zero return code —
    `HYPRLAND_INSTANCE_SIGNATURE not set! (is hyprland running?)` arrives on stdout with
    rc 1, and a stale socket gives rc 4 on stdout — so `json.loads(out.stdout)` on a failure
    raises `JSONDecodeError` rather than returning. Catch `(OSError,
    subprocess.SubprocessError)` on the call and `(ValueError, TypeError, AttributeError)`
    on the parse, and return `0` from every failure path. Use the narrow tuples the rest of
    `theme.py` uses, not the analog's `except Exception` — that breadth is acceptable for a
    fire-and-forget side effect, not for a value-returning function.

    `0` is the safe default, not a guess: square is what the reference aesthetic wants and
    what this box reports. Clamp with `max(0, int(...))`. Every measured failure path returns
    in about 10 ms, so the 0.4 s timeout is a ceiling rather than a cost. Call it from
    `omarchy_style()` only, which is called once at app construction and once per detected
    theme change — never per tick.

    **`style_variables(style: dict) -> dict[str, str]`.** Pure: no Textual import, no file
    read, no subprocess. One dict in, one flat dict of strings out — the same shape as
    `panel.style_view()`, which is the function to copy, including its module-level
    fallback table and its type-dispatch loop.

    Emission shape, hex-free by default:
      - `$ng-fill-normal` … `$ng-fill-pressed` and `$ng-fill-selection` — a **bare percent**
        string, `"4%"`. Textual substitutes variables at the token level, so `app.tcss` can
        write `background: $ng-color-normal $ng-fill-normal;` and it resolves.
      - `$ng-border-normal-a` … — a bare percent string, `"40%"`.
      - `$ng-color-normal` … `$ng-color-pressed` — a **resolved hex**, because two installed
        themes pin per-state colours that are not the palette foreground. This is the one
        place the pipeline legitimately handles a hex: it *produces* one from the live theme
        at runtime, which is not the same thing as a hex written into `app.tcss`.
      - `$ng-border-style` — `vkey` / `hkey` / `solid`, selected by the `$ng-radius` family.
      - `$ng-radius` — the integer as a string.
      - **`$ng-popup-bg`, `$ng-popup-text`, `$ng-popup-border`** and **`$ng-tip-bg`,
        `$ng-tip-text`, `$ng-tip-border`** — resolved hex, straight from the `[popups]` and
        `[tooltip]` entries that Task 1 puts in the style dict. Emitting them into the raw
        dict is **not** enough: the stylesheet reads the `$ng-*` map, not the dict, so a
        variable missing here surfaces as `UnresolvedVariableError: reference to undefined
        variable '$ng-popup-border'` when the next plan's stylesheet is parsed — and that
        error kills the app at compose rather than degrading. The confirm card and the
        masked password field both consume `$ng-popup-border` in the stylesheet plan, which
        is how the accent comes off them.
        The mapping for all six is the design contract's §2.3 table, including its fallbacks
        (popup background falls back to the palette background, popup text to foreground,
        popup border to accent; tooltip the same).

    **Never emit a variable whose value is itself a `$`-reference.** `v["ng-fill"] =
    "$foreground 4%"` fails with `StylesheetParseError — Invalid value ('$foreground') for
    the background property`: substitution is not recursive at that point. Write that in the
    docstring — it is the pitfall that costs an afternoon.

    The fixed-alpha roles (`$ng-text-caption` 70 %, `$ng-text-quiet` 50 %, `$ng-rule` 12 %)
    need **no variable at all** — `$foreground 70%` written directly in `app.tcss` resolves.
    Do not emit them here. Textual's own `HelpPanel` stylesheet does exactly this.

    The docstring states why alphas and border styles are bare tokens while colours are
    resolved, and names the token-pipeline requirement (UIX-01).
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `hyprctl` stdout → `theme.py` | a subprocess's output crossing into the app, from a compositor that may be absent, wedged, or answering through a stale socket |
| `shell.toml` → the CSS variable map | file content that becomes the stylesheet's values on a running long-lived process |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-12.1-07 | Denial of Service | `hypr_rounding()` blocking the 1 s tick | mitigate | `timeout=0.4` plus `except subprocess.SubprocessError`; called from `omarchy_style()` only, which runs once at construction and once per *detected* theme change. Measured: every failure mode returns in about 10 ms, so the timeout is a ceiling and not a cost. |
| T-12.1-08 | Tampering | unvalidated `hyprctl` stdout | mitigate | `returncode` is checked before `json.loads`, and the parsed value is clamped with `max(0, int(...))`. Without the return-code check the documented outside-Hyprland path raises `JSONDecodeError` — which is the negative control this plan demonstrates. |
| T-12.1-09 | Denial of Service | a malformed or half-written `shell.toml` during a theme swap | accept, with the existing guard | `raw_shell()` already returns `{}` on `OSError` / `TOMLDecodeError`, and the per-token fallbacks mean a partial file loses one token rather than the whole style. The swap is an atomic directory rename, so a half-written file is never visible; the guard stays because the rename is not this app's guarantee to make. |
| T-12.1-10 | Tampering | a theme value reaching a shell or an `eval` | mitigate | Theme values reach CSS variables and colour parsing only. A bad value produces a parse error at stylesheet reparse, never execution. Asserted structurally: no value from `style_variables` is passed to `subprocess`, and `style_variables` itself performs no I/O. |
| T-12.1-SC | Tampering | package installs | n/a | No package added, removed or upgraded. |
</threat_model>
