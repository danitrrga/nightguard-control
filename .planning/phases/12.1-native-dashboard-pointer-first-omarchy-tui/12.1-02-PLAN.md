<objective>
Fix the colour-role collapse that makes half of this product's colour contract meaningless,
and add the missing sweep that let it ship.

Measured on the live box with the shipped loader: **26 of the 28 installed themes collapse
`accent`, `success`, `warning` and `error` to one colour.** `_theme_from_colors()` reads
only the ANSI key vocabulary (`color1`/`color2`/`color3`) and falls back to `accent`; 26
themes declare `red`/`green`/`yellow` and no `color1/2/3`. So today LOCKED, OPEN and GRACE
all paint the same hue, and the accent reserve is unsatisfiable by construction.

Purpose: this is not cosmetic. The accessibility rule — glyph, word and colour travel
together so a monochrome terminal loses nothing — is inverted while the colour channel
itself is the monochrome one. The root cause is a **test gap**: there is a 28-theme sweep
for the bar panel's mapping and none for the Textual role mapping. The durable fix is the
sweep, not two patched chains.
Output: pick chains in `theme.py`, and a parametrised sweep that names the theme when it fails.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `colors.toml` → `theme.py` | untrusted-ish file content, rewritten wholesale by `omarchy-theme-set` and not in this repo |
| the resolved palette → the verdict rendering | the point at which a colour becomes a claim about whether the curfew is holding |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-12.1-04 | Spoofing | the verdict colour channel | mitigate | **This plan's whole reason.** With all three verdict roles collapsed to one hue, a LOCKED screen and an OPEN screen are the same colour — the rendering misreports the curfew's state to a user reading colour before word. The pick chains make them three distinct colours and the 28-theme sweep is what keeps them that way. Glyph and word already carry the meaning independently (`widgets/status.py:31`), so no single channel is load-bearing. |
| T-12.1-05 | Tampering | a malformed or partial `colors.toml` | mitigate | `pick()` validates each candidate is a `#`-prefixed parseable colour before accepting it, and every role has a terminal fallback, so a theme missing a key loses one colour and never the whole palette. `load_omarchy_theme`'s existing narrow exception tuple (`theme.py:291`) is unchanged. |
| T-12.1-06 | Repudiation | the sweep itself | mitigate | A `skipif`-guarded sweep that finds no themes passes silently. The vacuity guard asserts the discovery actually found the 28 themes, and the copied-verbatim `_installed_themes()` means the two sweeps cannot drift into disagreeing about what "installed" means. |
| T-12.1-SC | Tampering | package installs | n/a | No package is added, removed or upgraded. No slopcheck required. |
</threat_model>
