## Sampling Rate

- **After every task commit:** the **full** suite, not the quick subset. A subset is exactly
  how a regression in the trust-path tests slips through during a phase whose stated work is
  visual. **Held: every one of the eight executing plans records a full-suite line per task.**
- **After every plan wave:** the full suite **plus** the negative-control demonstration for
  every control added in that wave — each must be *seen* to fail, with its failure message
  recorded in the plan. A control never seen to fail is not evidence. **Held, and it is the
  single most productive rule in this phase — see *What the arming actually found*.**
- **Before `/gsd:verify-work`:** the full suite green except the one named baseline red
  (`ngtui/tests/test_theme_sync.py::…[dos-moos]`, the bar panel's `surface` fallback,
  deliberately left).
- **Phase gate:** the above, then a live walkthrough after `uv tool install --python 3.14 .
  --force` on **`city-783`** (one of the only two themes shipping a hand-written
  `shell.toml`, and the one that also pins a gradient border and `focus-border-width = 2`)
  **and** one theme whose `shell.toml` is generated from Omarchy's template, because the two
  exercise different branches of the variable map.
- **Max feedback latency:** contract said 4 s. **Superseded — see below.**

### The latency budget — revised, with the measurement

The 4 s budget was set against a suite that held no Pilot test at all (plan 01's first
finding was that nothing in the suite used `run_test`, `Pilot` or `asyncio`). The phase added
twenty-two Pilot-driven integration tests, and each one boots a real `App`, mounts a real
screen and drives a real event loop.

Measured, `--durations`:

```
10.30s  test_dashboard_cursor.py::test_every_control_is_keyboard_reachable
 4.15s  test_dashboard_cursor.py::test_the_walk_visits_every_registered_stop_including_the_ramp
 3.89s  test_dashboard_home.py::test_the_real_home_surface_walks_all_sixteen_stops
 3.27s  test_dashboard_budget.py::test_the_degradation_ladder_keeps_the_hero_and_the_ledger
 2.45s  test_dashboard_cursor.py::test_the_paint_ladder_keeps_its_priority
```

The top five cost 24 s of the 42.75 s total, and all five are registry walks or ladder
sweeps — they press a key and settle, sixteen or nine times over. That is the cost of
asserting against the composed surface rather than against a model of it, which is the
decision the phase made deliberately and repeatedly (control 11c asserts on
`render_line(0).text`, not on an attribute; control 6b asserts on activation, not on
`pilot.click()`'s return).

**The budget is revised to 45 s for the full suite**, and the reason is recorded rather than
the number quietly edited. The sampling property the 4 s figure was protecting — feedback
inside a single task, so a regression is attributable to the change that caused it — still
holds at 43 s and held for every task in this phase. The trust-path subset, which is the part
that must never be deferred, runs in **1.60 s** for 90 tests and is unaffected.

## What the arming actually found

The rule "arm every control and record the message" was expected to be ceremony. It was not.
**A prescribed negative control was structurally blind in every single wave — seven for
seven.** Every one of these was found by arming, and none of them would have been found by
reading the test.

| # | Shape | Where |
|---|---|---|
| 1 | The control passes with the bug fully present — the fallback tail is `or accent`, a colour the theme itself *declares*, so provenance cannot see an in-theme fallback. 27/27 green with the bug in. | 02 |
| 2 | The guard is already subsumed — `json.JSONDecodeError` **is** a `ValueError`, so the handler swallowed the raise the return-code check exists to prevent. Only a failure whose stdout *parses* discriminates. | 03 |
| 3 | A value enforced at two layers, so removing either alone leaves the end-to-end assertion green. | 03 |
| 4 | The control's own failure message raising instead of printing — `"%r" % color` on a `NamedTuple` → `TypeError: not all arguments converted during string formatting`. | 04 |
| 5 | The control measured the wrong rung — Textual focuses the first focusable widget on mount, so `rows[0]` is on the cursor rung, not idle. | 04 |
| 6 | "Drop one row from the registry" leaves the control green, because `expected` is read from the same registry and shrinks with it. | 05 |
| 7 | An assertion blind by construction to what it appears to cover — `pilot.click()`'s return value is `widget_at is target_widget`, false on four of five live positions on fully working code. | 05 |
| 8 | Expectations derived from the function under test, so a uniformly-wrong implementation stays self-consistent — the edge just moves from 117 to 118 and every assertion follows it there. | 06 |
| 9 | A budget check that is not one — `max_scroll_y` stayed 0 with an extra row because the flexible region absorbs it. Ten rows were needed. Plan 08 bounded the region and the threshold moved to four. | 07, 08 |
| 10 | A comparison against the wrong operand — `virtual_size.height` is the frame's **inner** height (44), compared against the window's 46. | 08 |
| 11 | **A control scanning zero files.** `NGTUI_SRC` had one `parent.parent` too many and resolved to a directory that does not exist; `rglob` over it yields nothing and all three PORT-03 tests passed vacuously for their whole life. | **09** |

Finding 11 is the one that justifies the rule outright. The no-crypto scan (PORT-03) is the
guard behind the project's core claim that *the TUI never holds the HMAC key and never

### UIX-01 does not close, and the table is not tidied to say it does

UIX-01's text names four structural sources: `shell.toml`'s `[controls]` state
fills/borders, **`[spacing]`**, **`[font]`**, and Hyprland's `decoration:rounding`. Three of
the four are delivered and proved. `[spacing]` and `[font]` are not, and the gap is not
cosmetic — measured at close:

```
$ style_variables(omarchy_style())
emitted 34 variables, 24 consumed by app.tcss, 10 with no consumer:
   $ng-border-{cursor,focus,normal}-w      (a grid reserves a column, not a width)
   $ng-border-{pressed,selected}{,-a,-w}
   $ng-radius                              (Textual has no border-radius)

$ omarchy_style() parses 31 spacing_* keys and font_base — and style_variables()
  emits NO spacing or font variable at all. Not an unconsumed variable: no variable.

$ grep -rn 'spacing_\|font_base' --include='*.py' ngtui | grep -v ngtui/theme.py
ngtui/panel.py:259:    "font_base": 12,
ngtui/panel.py:260:    "spacing_scale": 1.0,
ngtui/panel.py:261:    "spacing_scale_with_font": True,
```

The only reader of `[spacing]` and `[font]` in the tree is `panel.py`, which is the bar
panel — out of bounds for this phase by the scope fence and untouched. So the two tokens are
parsed and then dropped on the floor before they reach the TUI.

Five of the ten unconsumed variables **structurally cannot** be consumed: Textual's box model
has no border-radius, and a reserved-border grid pins a column rather than setting a width.
Those are honest no-ops. `[spacing]` and `[font]` are different — they are named in the
requirement and there is no path at all.

**Verdict: UIX-01 is the phase's one incomplete requirement**, reported as a phase-level gap
rather than ticked. What *is* proved: the `[controls]` half reaches a rendered row's resolved
background (control 2), a live theme change moves a border **style** and not only a colour
(control 3), the rounding query fails closed on all four hostile `hyprctl` answers (4b), and
the watcher sees `shell.toml` and not only `colors.toml` (4c). The live-desktop half of
UIX-01 — that the watcher, the file paths and the deployed entry point line up — is the
subject of the manual gate below and is **not yet verified**.
