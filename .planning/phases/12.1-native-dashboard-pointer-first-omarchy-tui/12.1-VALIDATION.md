## Test Infrastructure

| Property | Value |
|----------|-------|

| **Measured runtime** | **3.01 s** for the full suite (453 passed, 1 failed, 3 skipped, re-measured 2026-09-13 — it was 458 passed earlier that day, before a theme was removed from the system and took 5 parametrised cases with it) |

---

## Sampling Rate

- **After every task commit:** the **full** suite, not the quick subset. It costs 3.18 s
  measured, and a subset is exactly how a regression in the trust-path tests slips through
  during a phase whose stated work is visual.
- **After every plan wave:** the full suite **plus** the negative-control demonstration for
  every control added in that wave — each must be *seen* to fail, with its failure message
  recorded in the plan. A control never seen fail is not evidence.
- **Before `/gsd:verify-work`:** the full suite green except the one named baseline red
  (`ngtui/tests/test_theme_sync.py::…[dos-moos]`, the bar panel's `surface` fallback,
  deliberately left).
- **Phase gate:** the above, then a live walkthrough after `uv tool install --python 3.14 .
  --force` on **`city-783`** (one of the only two themes shipping a hand-written
  `shell.toml`, and the one that also pins a gradient border and `focus-border-width = 2`)
  **and** one theme whose `shell.toml` is generated from Omarchy's template, because the two
  exercise different branches of the variable map.
- **Max feedback latency:** 4 s.

## Negative controls — what makes each one fail

Three of these were **measured failing** during research and are recorded with their real
output rather than a prediction. The rest are recipes the executor must demonstrate.

| Control | How it is made to fail | Evidence today |
|---|---|---|
| 1 | inject a hex into a temp copy of `app.tcss` | recipe |
| 2 | build ignoring `[controls]` yields `a = 0.04` instead of `0.42` | recipe |
| 3 | reassign `App.theme` alone | **measured**: border stayed `('hkey', Color(169,192,191, a=0.4))`, fill stayed `a=0.04`, accent stayed `#7FC9C4` — all three unchanged, which is what the shipped code does today |
| 4 | run the sweep against the current pick chain | **measured**: 26 of 28 themes collapse the verdict roles to one colour |
| 5 | make the cursor keyboard-only | **measured**: it jumps to row 0 instead of continuing to row 3 |
| 7 | add `border-right` under `:focus` | **measured**: `content_size` `(130,1)` → `(129,1)`. Adding `border-top` gives `(130,1)` → `(130,0)`. **`region` does not move under either bug** — it is not a valid target |
| 9 | compose 60 rows of content | **measured**: `content_height = 60`, overflows; passes at 40 and 46. A scrollbar is not a valid signal |
| 10 | paint the frame in the accent | recipe |
| 11b | off-by-one in the column→minute mapping | recipe — and the expected column must be **derived from the measured width**: column 107 reads 21:30 at width 120 but 20:00 at the real width 129 |

## Wave 0 Requirements

- [ ] **Decide the async test idiom, and prove one Pilot test runs.** No test in the suite
      uses `run_test`, `Pilot` or `asyncio` today. Either an `asyncio.run()` wrapper (no
      plugin) or `@pytest.mark.asyncio` with `asyncio_mode = "auto"`. A bare `async def`
      fails with *"async def functions are not natively supported."* — this blocks nine of
      the test files below, so it is the first thing in the phase.
- [ ] `ngtui/tests/conftest.py` — add a UI fixture group: a paired fixture `shell.toml` +
      `colors.toml` under `tmp_path`, and a helper that builds the app against them without
      touching the live desktop theme.
- [ ] `ngtui/tests/test_token_pipeline.py` — controls 2, 3 and 3b
- [ ] `ngtui/tests/test_theme_roles.py` — the 28-theme role sweep, control 4. Mirror the
      existing `_installed_themes()` helper and its skip condition in
      `ngtui/tests/test_theme_sync.py`.

- [ ] `ngtui/tests/test_dashboard_cursor.py` — controls 5, 6 and 6b
