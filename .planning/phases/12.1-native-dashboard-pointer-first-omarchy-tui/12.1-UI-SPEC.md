# Phase 12.1 — UI Design Contract

> The visual and interaction contract for the native dashboard. Every value here is
> either lifted from a locked sketch decision, read off the live desktop theme, or
> verified against the installed `textual 8.2.7`. Nothing is aspirational.

## How this document diverges from the template

This is **not a web UI**. The template's shadcn/px/registry frame does not apply, and
filling it in as written would produce a contract an executor cannot implement:

| Template asks for | This target has instead |
|---|---|
| shadcn preset + component registry | Textual's own built-in widget set (§9). No registry, no third-party blocks, so the registry-safety gate is **not applicable** — there is nothing to vet. |
| spacing in px, multiples of 4 | spacing in **cells**, derived from `shell.toml [spacing]` (§4). A 4-px grid is meaningless at a 6.25 × 12.40 px cell. |
| 3–4 font sizes | **one** cell size, always. The type scale becomes weight + case + dim level + glyph mass (§5). |
| hex per colour role | **role names only.** No fixed hex anywhere in `app.tcss` or a widget — UIX-06, non-negotiable (§6). Moonlit Indigo is retired. |
| — | an **interaction contract** (§8). For this phase it is the most important section in the document. |

## 2. Token pipeline (UIX-01)

Today `load_omarchy_theme()` (`ngtui/ngtui/theme.py:280`) maps **only** `colors.toml`
into a Textual `Theme`. `omarchy_style()` (`theme.py:160`) already parses `shell.toml`'s
structural tokens, but its only consumer is the head-less bar-panel path
(`ngtui/ngtui/__main__.py:136` → `panel.style_view`). Closing that gap is this
requirement.

### 2.1 The verified mechanism

Probed headless against the installed package (scratchpad `probe2.py`), because the
obvious approach does **not** work:

- `Theme(variables={...})` values do reach the stylesheet as `$name`
  (`textual/app.py:1432` merges `theme.variables` into `get_css_variables()`), **but**
  `App.CSS` / `CSS_PATH` is parsed *before* `on_mount` runs. Registering the theme in
  `on_mount` and referencing `$ng-*` in `app.tcss` raises
  `UnresolvedVariableError: reference to undefined variable '$ng-border-normal'` and the
  app dies at compose. **Do not wire it that way.**
- **Do** override `App.get_css_variables()` — Textual's own documented extension point
  ("May be implemented in a subclass to add new CSS variables", `app.py:1419`). It is
  called during stylesheet parse, so the tokens exist on the first parse.
- A **multi-token** variable works: `$ng-border-normal: hkey #a9c0bf 40%` used as
  `border: $ng-border-normal` resolved to
  `Edges(top=('hkey', Color(169,192,191, a=0.4)), …)`. So a variable can carry the
  **border style** as well as its colour — which is what makes "switching the theme
  changes the borders, not only the colours" reachable at all.
- `App.refresh_css()` re-runs `get_css_variables()` and re-applies. Proved with a
  structural change, not a colour change: `hkey #a9c0bf 40%` → `vkey #ff0000 90%` landed
  on the live widget as `Edges(top=('vkey', Color(255,0,0, a=0.9)), …)`.

**Two constraints found by hitting them, both of which break the app at start-up:**

- `get_css_variables()` is called from **`App.__init__`** (`app.py:729`,
  `Stylesheet(variables=self.get_css_variables())`), not from `on_mount`. So any state it
  reads **must be assigned before `super().__init__()`**. Assigning it after — the natural
  order — raises `AttributeError: 'App' object has no attribute …` during construction.
- A variable's **value may not itself be a `$`-reference**: substitution is not recursive
  at that point. `v["ng-fill"] = "$foreground 4%"` fails with
  `Invalid value ('$foreground') for the background property`. The variable must carry an
  already-resolved colour plus its alpha — `"#a9c0bf 4%"`. This is why `style_variables()`
  in §2.2 must resolve colours itself rather than emit role references, and it is the one
  place the pipeline legitimately handles a hex: it *produces* one from the live theme at
  runtime, which is not the same thing as a hex written into `app.tcss`.

| `hyprctl decoration:rounding` | `0` | `$ng-radius` → selects the border **style** family, §9.2 | `0` |

**Border-token indirection.** A `*-border` value may be the string
`"hyprland.active-border"` rather than a hex. `_resolve_border()` (`theme.py:114`) already
dereferences `[hyprland]` and **rejects a gradient** (`"rgba(7fc9c4ee) rgba(68a5a2ee) 45deg"`
is what this theme actually ships) by returning `None` so the caller falls back. Keep that:
half a gradient on a character grid is worse than the accent.

**Colour-word indirection.** `[controls] *-color` may be the literal word `foreground`,
`accent` or `urgent` instead of a hex (`Style.qml:70-75`, `resolveStateColor` at `:115`).
The parser must accept both and resolve the words against `colors.toml`.

**Sections deliberately NOT consumed** — so an executor does not wire them "for
completeness": `[bar]`, `[menu]`, `[launcher]`, `[lock]`, `[polkit]`, `[notifications]`,
`[image-picker]`. The TUI is not a bar, a menu or a lock screen.

### 2.4 The colour-role bug this phase must fix

`_theme_from_colors()` (`theme.py:237`) picks `error`/`success`/`warning` from
`color1`/`color2`/`color3` and falls back to **`accent`**. The theme running right now
(`periphery`) declares no `color0..color8` at all — it uses named keys. Measured on the
live box with the shipped loader:

```
primary #7fc9c4   accent #7fc9c4   surface #060f12
success #7fc9c4   warning #7fc9c4  error   #7fc9c4
```

So today **LOCKED, OPEN and GRACE all paint the same cyan**, and the accent-reserve rule
in §6.2 is unsatisfiable by construction. Required pick chains (first present wins):

| Role | Chain |
|---|---|
| `error` | `color1` → `red` → `urgent` → `accent` |
| `success` | `color2` → `green` → `accent` |
| `warning` | `color3` → `yellow` → `orange` → `accent` |
| `surface` | `color0` → `lighter_background` → `selection` → `dark_background` → `background` |
| `panel` | `lighter_background` → `selection` → `surface` |

**The bug is not one theme — it is 26 of 28.** Measured by loading every installed
`colors.toml` through the shipped `load_omarchy_theme()` and counting distinct values
across `accent`/`success`/`warning`/`error`:

```
themes inspected: 28
all four colours IDENTICAL (locked == open == grace == accent):  26
all four distinct:                                                1   city-783
partially distinct:                                               1   dos-moos (3 of 4)
```

Key vocabularies, counted directly: **26 themes declare `red`/`green`/`yellow` and no
`color1/2/3`**, one declares ANSI keys only (`dos-moos`), one declares both (`city-783`).
The loader knows only the ANSI vocabulary, so the colour channel has been dead on ~93 % of
installed themes since it shipped — and `dos-moos` happening to be active during the first
sketching rounds is why it was not caught there.

That inverts the accessibility contract in §11: the reason for "glyph + word + colour
together" is that meaning must survive a monochrome terminal, and right now the colour
channel *is* the monochrome one. Fixing the pick chains is therefore not cosmetic — it is
what makes the rest of the colour contract mean anything.

There is a theme-sweep test for the **panel's** mapping (`tests/test_theme_sync.py`,
parametrised over every installed theme — it is what caught the `dos-moos` surface red).
There is **no equivalent sweep for the Textual `Theme` roles**. That missing sweep is the
reason this shipped, and adding it is the durable fix rather than patching two chains.

This is the same class of gap the de-risking notes recorded at `panel.py:232`
(`12.1-NOTES-interaction-probes.md` §3), where `dos-moos` is the one installed theme that
declares neither `lighter_background` nor `selection`. **Fix it in `theme.py` only.**
`panel.py` feeds the bar panel, which is out of bounds (§14) — see OD-1.

## 3. What the pipeline must be *proved* to do

UIX-01's success criterion is a **running** TUI that restyles, borders and fills included.
Two assertions, with their negative controls, because a colour-only pipeline passes a
colour-only test:

1. **Consumption.** A fixture `shell.toml` with a distinctive `normal-fill-alpha = 0.42`
   must produce a control row whose resolved `styles.background` has `a == 0.42`.
   *Control:* a build that ignores `[controls]` yields `0.04` — the test fails, and its
   message is recorded in the plan.
2. **Live restyle.** Mutate the fixture from `normal-border = hkey …` shape to a different
   **border style**, run the repaint path, assert `styles.border.top[0]` changed
   (`'hkey'` → `'vkey'`). *Control:* a pipeline that only reassigns `App.theme` leaves the
   style at `'hkey'` and fails.

## 4. Spacing scale — in cells

Quattro's `[spacing]` is in px (`Style.qml:231-260`). The measured cell is
**6.25 × 12.40 px** (the sanctioned window `size 875 600`,
`packaging/omarchy/hypr/nightguard.windowrule.conf:8`, at CaskaydiaCove Nerd Font 8pt).
Conversion is `round(px / cell)`, floored at `1` for a gap whose job is to *separate*, and
allowed to reach `0` otherwise.

| Quattro token | px | Cells (x) | Rows (y) | Where |
|---|---|---|---|---|
| `xxs` / `xs` | 2 / 3 | **0** | **0** | collapses — a grid has no sub-cell space |
| `sm` / `md` / `lg` | 4 / 6 / 8 | **1** | 1 | the default gap between a label and its value |
| `control-gap` | 8 | **1** | — | glyph → word inside a control |
| `label-gap` | 4 | **1** | — | value → its right-hand detail |
| `xl` / `xxl` / `xxxl` | 10 / 12 / 14 | **2** | 1 | the region gutter |
| `control-padding-x` / `row-padding-x` | 10 / 12 | **2** | — | a control row's left inset |
| `control-padding-y` | 6 | — | **0** | a control row is exactly **1 row** tall |
| `row-gap` | 8 | — | **1** | one blank row between regions |
| `huge` / `panel-padding` | 18 | **3** | 1 | the device frame's inner gutter |

**The whole scale is therefore `{0, 1, 2, 3}` cells horizontally and `{0, 1}` rows
vertically.** That is not a simplification of Quattro — it is what Quattro's scale *is*
once the cell is the quantum. Any value not in that set is a bug.

Exceptions, each with a reason:

- **Fixed label columns.** `18` cells for a blocking-row label, `12` for a week-row key,
  `22` for a staged-row label. A grid aligns by column count, not by a spacing token; these
  are layout constants and belong in `app.tcss` as plain integers.
- **`Digits` is 3 cells per character** (`textual/renderables/digits.py`), so `07:38:00`
  occupies 24 × 3 cells. Not negotiable, not a spacing choice.
- The cell geometry itself (6.25 × 12.40) is a **measured constant** recorded in code with
  its provenance. It is not a colour and the hex ban does not reach it; a terminal cannot
  be asked its cell size. If the terminal font changes, the derived scale is off by at most
  one cell, and the overflow test (§10) is what catches the consequence.

## 5. Typography — the grid mapping

A character grid has exactly one cell size, so **there are no font sizes in this contract.**
Quattro's scale translates to weight + case + dim level + glyph mass. This mapping is a
decision, recorded so it is not re-made per widget.

| Quattro token | px @ base 12 | On the grid |
|---|---|---|
| `caption` | 10 | `$ng-text-caption` + **UPPERCASE** + one space of tracking. Verbatim from `PanelHero.meta` / `PanelSectionHeader` (`toUpperCase`, `letterSpacing 1.2`, `Qt.darker(fg, 1.4)`). |
| `body-small` | 11 | `$ng-text-caption`, sentence case — tooltips, right-hand detail |
| `body` | 12 | default: `$foreground`, `text-style: none` |
| `subtitle` | 13 | `text-style: bold` — a control row's label (`Toggle.qml` sets `titleSize: subtitle`, `font.bold: true`) |
| `title` / `heading` | 14 / 16 | `text-style: bold` + UPPERCASE, no tracking — the verdict word |
| `display` / `display-large` | 24 / 28 | **`Digits`**, thin set (`DIGITS3X3`) |
| `icon` / `icon-large` | 14 / 18 | a Nerd Font glyph at the same cell size; mass comes from the glyph, not a size |

**Exactly two weights: regular and bold.** `dim` is not a weight — it is the caption
channel, and it is expressed as **colour alpha**, not `text-style: dim`. (`dim` is in
`VALID_STYLE_FLAGS` but renders at the terminal's discretion; alpha is computed by Textual
and is therefore deterministic.)

**Exactly two dim levels**, translating Qt's two darkenings:

| Name | Value | Translates | Used for |
|---|---|---|---|
| `$ng-text-caption` | `$foreground 70%` | `Qt.darker(fg, 1.4)` — `PanelSectionHeader:22` | section labels, secondary values, captions |
| `$ng-text-quiet` | `$foreground 50%` | `Qt.darker(fg, 1.5)` — `Toggle.qml` description | right-hand detail, the hour axis, provenance lines |

**Letter-spacing does not exist in Textual.** `StylesBase` has no `letter_spacing`
property (enumerated on the installed package). Tracking is emulated by interleaving spaces
in the string — `"T H E   D A Y"` — which costs `2n − 1` cells. Permitted **only** for the
six section labels in §7.2. Nowhere else.

**`Digits` is allowed exactly once per screen: the countdown.** It is the only `display`-mass
element, and a second one would break the family's "never stack two hero materials" rule.
Its character set is `" 0123456789+-^x:ABCDEF$£€()"` (`renderables/digits.py:8`), so `:`
renders and `HH:MM:SS` is safe; `.` is silently translated to `•`. The **thin** set is the
choice — `text-style: bold` switches Textual to `DIGITS3X3_BOLD`, which is heavier and reads
more like terminal art than the desktop it is imitating. The countdown's **colour** follows
the verdict role (§6.2); the glyphs themselves carry no accent.

## 6. Colour contract

### 6.1 Roles only — the hex ban

`app.tcss` and every widget reference `$`-names exclusively. That already holds in the
shipped `app.tcss` (its header states it) and must survive the refresh. The only places a
hex string exists are the live theme files, which the app reads at runtime.

| Role | `$`-name | Source | Usage |
|---|---|---|---|
| Ground (≈ 80 % of the surface) | `$background` | `colors.background` | the screen, every region |
| Ink | `$foreground` | `colors.foreground` | all body text |
| Caption / quiet ink | `$ng-text-caption`, `$ng-text-quiet` | derived alpha, §5 | labels, detail |
| Control surfaces | `$ng-fill-*`, `$ng-border-*` | `shell.toml [controls]`, §2.3 | the state ladder, §8.3 |
| Rule | `$ng-rule` = `$foreground 12%` | `PanelSeparator.qml` `strength: 0.12` | keylines between regions |
| Verdict — closed | `$error` | pick chain §2.4 | the word `LOCKED`, its countdown |
| Verdict — open | `$success` | pick chain §2.4 | the word `OPEN`, its countdown |
| Verdict — grace | `$accent` | `colors.accent` | the word `GRACE`, its countdown |
| Alarm | `$error` | pick chain §2.4 | `WEAK MODE`, "matches nothing", "covered by nothing", a refusal line |

### 6.2 Accent reserve — the explicit list

The accent may appear in **exactly two places**, and nowhere else:

1. **One dot** beside the wordmark (`●`, one cell). The reference's announcement dot.
2. **The verdict word and its countdown, when and only when the verdict is `GRACE`.**

Not the frame. Not a keyline. Not a chip — including the filled primary chip, which inverts
to `$foreground`-on-`$background`, not to the accent. Not the hero (§12: greyscale on
purpose). Not the token meter. Not a focus ring — the cursor rung is fed by
`hover-cursor-color`, which this theme resolves to `foreground`; if another theme points
that token at its accent, that is the **theme's** decision expressed through the kit's own
token, and it does not breach this reserve.

The current `app.tcss` breaches it in three places that must go: `#hero { border: round $primary }`
(`app.tcss:31`), `#countdown { color: $primary }` (`:50`), and `#confirm-box { border: round $primary }`
(`:189`). The hero loses its box entirely (§7.1); the countdown follows the verdict role; the
confirm card uses `$ng-popup-border`.

### 6.3 The 5 % guardrail is checked, not asserted

Verified measurable: `app.screen._compositor.render_strips()` yields every rendered segment
with its resolved `Style`, and at `run_test(size=(135, 46))` the cell total is exactly
**6210** (measured, matches 135 × 46). The test counts non-space cells whose `style.color`
**or** `style.bgcolor` equals the resolved accent.

- **Ceiling: 310 cells (5 %).** Failing this fails the phase.
- **Design target: ≤ 62 cells (1 %).** The composition in §7.2 spends 1 cell on the dot plus
  ≤ 6 on the verdict word and ≤ 24 on the countdown — and those 30 only in the `GRACE` state.
- `render_strips()` is a private API. Acceptable inside a test against a pinned dependency;
  it must not be reached from application code.

### 6.4 Second semantic colour

`$error` only, for the four alarm cases named in §6.1. There is no destructive action on
this surface (§14), so there is no destructive colour.

## 7. Layout contract

### 7.1 The device frame

One root container, `#frame`, carrying **per-edge** borders — verified glyphs from
`textual/_border.py`:

```
border-top: hkey $ng-border-normal;      /* ▔  one eighth of a cell */
border-bottom: hkey $ng-border-normal;   /* ▁ */
border-left: vkey $ng-border-normal;     /* ▏ */
border-right: vkey $ng-border-normal;    /* ▕ */
padding: 0 2;
```

That is the whole frame: 1 row top, 1 row bottom, 1 column each side, plus a 2-column inner
gutter. It replaces six drawn rectangles and it is why nothing else on the screen needs a
box. **No region draws its own outline.** Regions are separated by keylines
(`$ng-rule`) and by one blank row.

### 7.3 Column budget — 135 columns

`1 frame │ 2 gutter │ 129 content │ 2 gutter │ 1 frame`. Content is **129 cells**.

- The hero, the keylines and the chip strip are `width: 1fr` and must be **generated from

- `overflow-x: hidden` everywhere. Horizontal scrolling never appears.

### 7.4 Degradation below 135 × 46

|---|---|---|

## 8. Interaction contract (UIX-02, UIX-03, UIX-05)

This is the section the phase exists for. Every behaviour here is read out of Omarchy 4's
own kit, with the file it came from, and verified against `textual 8.2.7`.

### 8.1 One cursor, shared

Omarchy's contract: `hot = mouseArea.containsMouse || hasCursor` (`Ui/Button.qml`), and each
control emits `hovered(bool)` so the panel **moves its keyboard cursor on mouse-enter**
(`plugins/panels/monitor/Panel.qml:42` — "Mouse hover on a target updates root state via the
components' `hovered` signal so keyboard cursor and pointer share one highlight").

**In this TUI the cursor *is* Textual focus.** One model, no shadow state:

- Every control row is `can_focus=True`.
- `on_enter` → `self.focus()`. The pointer moves the keyboard cursor. They cannot disagree
  because there is only one of them.
- `j` / `k` / `↓` / `↑` walk the cursor over the registered order (§8.5).
- `Enter` / `Space` activate the focused control — which comes free with focus, and matches
  `Keys.onReturnPressed` / `onEnterPressed` / `onSpacePressed` on every control in the kit.
- `Escape` leaves the current surface.

Verified: `Enter`, `Leave`, `Click` (with `button` = 1/3 and `chain` = 1/2), `MouseMove`
(widget-relative `x`) all deliver to a row widget; the hover-then-`j` continuation is
assertable via `pilot.hover()` + `pilot.press("j")` + `app.focused.id`
(`12.1-NOTES-interaction-probes.md` §1). Note the attribute in 8.2.7 is `Widget.mouse_hover`,
not `mouse_over`.

### 8.2 The one Omarchy pattern that does not translate cleanly

`cursorShape: Qt.PointingHandCursor` is set on every `MouseArea` in the kit. **The hover
fill has to carry the whole affordance**, which is why the cursor rung uses the theme's
`hover-cursor` alpha rather than something subtler.

A correction to the sketch's flat claim, because it is now checkable: Textual 8.2.7 *does*
have a `pointer` CSS property (`css/styles.py:510`, `VALID_POINTER` at
`css/constants.py:94`), which emits the **Kitty pointer-shape protocol** (`OSC 22`,
`app.py:3916`). `foot 1.28.0` documents `OSC 22` support
(`/usr/share/doc/foot/README.md:543`). But the terminal that actually runs `ngtui` is
resolved by `xdg-terminal-exec` at launch and is **not pinned** — there is no
`xdg-terminals.list` on this box, and both `foot 1.28.0` and `Alacritty 0.17.0` ship desktop
entries.

Therefore: `pointer: pointer` on control rows is **progressive enhancement only** (OD-4).
Nothing may depend on it, and no test may assert it. The affordance rule stands unchanged.

### 8.3 Paint-priority ladder

Priority, from `Ui/Button.qml`'s `color:` / `borderSpec:` ladders:
**pressed > focus > hover/cursor > selected > active > idle.**

Because the cursor is focus, two of those rungs collapse into one — which is exactly what
this theme intends: `shell.toml`'s own comment on `focus-*` says *"Mirror the hover-cursor
values by default so mouse hover, keyboard cursor, and tab focus all read as the same
state."* So:

| Rung | Selector | Fill | Border | Live alpha |
|---|---|---|---|---|
| idle | `.ctl` | `$ng-fill-normal` | `$ng-border-normal` | 0.04 / 0.40 |
| selected | `.ctl.-selected` | `$ng-fill-selected` | none — `selected-border-width` is `0` | 0.18 |
| **cursor** (pointer **or** keyboard) | `.ctl:focus` | `$ng-fill-cursor` | `$ng-border-cursor` | 0.08 / 0.25 |
| pressed | `.ctl.-pressed` | `$ng-fill-pressed` | `$ng-border-cursor` | 0.22 / 0.25 |
| staged (this product's own rung) | `.ctl.-staged` | inherits its rung's fill | `$warning` | — |
| refused | `.ctl.-refused` | inherits | inherits | value text drops to `$ng-text-quiet` |

`$ng-fill-focus` / `$ng-border-focus` are **not** unused: they are reserved for the one place
where Textual focus means something other than the cursor — a text `Input` in edit mode,
where the theme's dedicated focus ring is the correct signal. `$ng-fill-selection` styles
that `Input`'s text selection.

**Rule order is the mechanism, and it is load-bearing.** `:focus` counts as a class for
specificity, so `.ctl:focus` and `.ctl.-pressed` tie, and the **later** rule wins — verified:
with `-pressed` declared after `:focus`, a focused+pressed row painted the pressed colour.
`app.tcss` must declare the ladder in exactly this order: idle → selected → `:focus` →
pressed → staged → refused.

### 8.4 No reflow (UIX-05)

`Ui/Button.qml` reserves the largest border any state can paint (`_reservedBorderTop` …),
"otherwise a borderless idle button grows by a pixel per side on hover/focus and relayouts
neighboring controls."

On a grid the reservation is simpler and stricter: **a control row's border is always
`border-left: vkey`, 1 column, in every state. Only its colour changes** — including at
idle, where it is `$ng-border-normal`, never `none`. The row is always `height: 1`, and its
left inset is always 2 cells (§4). Nothing on this screen changes size in response to input.

Assertion: capture every row's `region` across idle / cursor / pressed / selected and
require them identical (§10.5).

### 8.5 Timings

| What | Value | Source | Textual |
|---|---|---|---|
| Fill transition | **120 ms** | `Behavior on color { ColorAnimation { duration: 120 } }`, `Button.qml` | `transition: background 120ms linear, color 120ms linear` — verified populated into `styles.transitions` |
| Tooltip delay | **400 ms** | `ToolTip { delay: 400 }`, `Button.qml` | `NightguardApp.TOOLTIP_DELAY = 0.4` — the default is **0.5**, close enough to look deliberate, so it must be set explicitly |
| Tick | 1 s, unchanged | existing `app.py:48` | only the countdown cell and the theme poll (`app.py:70`) |

**Border colour cannot be animated.** Textual's `ANIMATABLE` set contains `background` and
`color` but **not** `border` (enumerated on the installed package). So a state change
cross-fades its fill over 120 ms and snaps its border colour. State that in the CSS comment
so nobody spends a day trying to fix it.

## 12. The hero (UIX-04)

One instrument, full width, the only ASCII art on the screen.

### The ramp

- **Character set:** `" .:-=+*#%@"`, index 0–9.
- **Density = hours until the curfew starts**, exactly:

  | Condition | Index | Glyph |
  |---|---|---|
  | inside the curfew | 9 | `@` |
  | < 1 h to curfew | 8 | `%` |
  | < 2 h | 7 | `#` |
  | < 3 h | 6 | `*` |
  | < 4 h | 5 | `+` |
  | < 6 h | 4 | `=` |
  | < 8 h | 3 | `-` |
  | < 11 h | 2 | `:` |
  | otherwise | 1 | `.` |

  **Index 0 (the space) is never emitted.** A blank cell in the day reads as missing data,
  not as "far from the curfew". A test asserts the density function's range is 1–9.
- **Column → minute:** `m = ((i + 0.5) / width) × 1440`, where `width` is the **measured**
  ramp width at paint time (§7.3), never a constant.
- **Greyscale, on purpose.** Each run is `$foreground` at `0.30 + 0.055 × d` alpha; hours
  inside the curfew at `0.92`. Computed in Python from the **resolved** foreground colour
  (`Color.parse(app.theme_variables["foreground"]).with_alpha(...)`) into a `rich.text.Text`,
  because `$`-variables do not resolve inside a widget's content. No literal hex —
  the input is a theme variable and the arithmetic is on the parsed colour. Density already
  carries the meaning; the colour budget belongs to the verdict.
- **Now:** exactly one cell, `█`, bold, at `floor(now_min / 1440 × width)`, in
  `$foreground` at full strength. One bright cell, one marker.

### The permission channel

A separate row directly beneath: `▔` where the minute falls inside the edit window, space
elsewhere, at `$foreground 80%`. Read from the **signed** config's `edit_window` and its
timezone. It is a second channel, not a second hero — one row, one glyph, no colour.

### The hour axis

Row 9: two-digit hour labels every 2 hours, in `$ng-text-quiet`.

### The read-out (both inputs, one destination)

Row 10 is reserved for it, so nothing reflows when it fills.

- **Pointer:** `on_mouse_move` → the column from the widget-relative `x` → the read-out.
- **Keyboard:** with the cursor on the ramp, `h` / `l` move a column index and write the
  **same** string. Keyboard parity is mandatory, so the read-out cannot be tooltip-only —
  a tooltip is unreachable without a pointer.
- **Copy:** `09:14   open · a loosening is allowed here` /
  `21:52   curfew — locked · a loosening is refused here`.
- Verified: column → hour lands exactly — column 107 of 120 resolved to `21:30`, the curfew
  start (`12.1-NOTES-interaction-probes.md` §4).

The ramp's **tooltip** carries the explanation of what the instrument is (§10.5), not the
per-column value.
