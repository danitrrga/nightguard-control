## Decisions Made

- **Async idiom: the `asyncio.run()` wrapper.** Recommended by RESEARCH on the measured
  grounds that it needs no plugin; adopted. `grep -c 'pytest.mark.asyncio'` on the new
  module returns 0 and `pyproject.toml` gained no `asyncio_mode`.
- **The fixture theme's `[controls] *-color` keys carry the literal word `foreground`,
  not a hex.** Worth recording because the plan's justification is half right: the
  omarchy template (`/usr/share/omarchy/default/themed/shell.toml.tpl`) does write
  `"{{ foreground }}"`, but the **generated** file on this box carries the substituted
  hex (`normal-color = "#DADDFB"`), not the word. Both forms exist in the wild —
  `Style.qml` resolves the bare word — so the generated fixture variant uses the word
  (giving the word-resolution path coverage) and the pinned `city-783` variant uses
  per-rung hex. The mixture is deliberate and commented in place.
- **`probe_app` overrides `action_edit` and `action_refresh` to raise** rather than
  merely not pushing `EditScreen`. T-12.1-01 says the probe must never reach the
  editor; a stray `e` or `r` in a Pilot test would otherwise have routed a UI control
  into the commit path or into a live `guard.json` read. Same shape as the existing
  `read_key_explodes` fixture — make the forbidden path loud.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] `CSS_PATH` resolved against `tests/`, not the package**

- **Found during:** Task 2 (probe_app)
- **Issue:** `NightguardApp.CSS_PATH = "app.tcss"` is relative, and Textual resolves a
  relative `CSS_PATH` against the directory of the module where the App subclass is
  **defined**, not where it is inherited from. `_ProbeApp` is defined in
  `tests/conftest.py`, so it looked for `ngtui/tests/app.tcss`:
  `StylesheetError: unable to read CSS file '…/ngtui/tests/app.tcss'`. Every Pilot
  control in the phase would have died on this.
- **Fix:** `CSS_PATH` pinned to an absolute path derived from `ngtui.app.__file__`, so
  it cannot drift and the probe is guaranteed to exercise the real shipped stylesheet.
- **Files modified:** `ngtui/tests/conftest.py`
- **Verification:** the probe test loads the stylesheet and reaches its theme assertions.
- **Committed in:** `97ad64a`

**2. [Rule 1 - Bug] Overriding `on_mount` did not replace the base — both ran**

- **Found during:** Task 2 (probe_app)
- **Issue:** Textual dispatches a message to the handler of **every** class in the MRO
  (`message_pump.py:758`, `for cls in self.__class__.__mro__`). Defining `on_mount` on
  `_ProbeApp` therefore did not suppress `NightguardApp.on_mount`; both ran, and the
  base pushed the real `StatusScreen` **on top of** the probe screen. Measured stack:
  `[Screen(id='_default'), _ProbeScreen(), StatusScreen()]`, with every
  `query(".ctl")` returning 0. Left standing, the cursor / no-reflow / token-pipeline
  controls would have been silently asserting against `StatusScreen` — which reads
  live guard state, crossing the exact boundary T-12.1-01 exists to hold.
- **Fix:** the probe's `on_mount` takes the `events.Mount` argument and calls
  `event.prevent_default()`, which sets `_no_default_action`; the dispatch loop breaks
  on it before reaching the base class (`message.py:131-140`).
- **Files modified:** `ngtui/tests/conftest.py`
- **Verification:** stack is now `[Screen(id='_default'), _ProbeScreen()]` and
  `app.screen.query(".ctl")` returns 5.
- **Committed in:** `97ad64a`

**3. [Rule 2 - Missing critical functionality] The fixture group had no caller**

## Issues Encountered

Beyond the three fixed above, one measured behaviour that later plans must honour:

**`App.query` is scoped to the default screen.** Measured with the probe mounted:
`app.children == [_ProbeScreen()]`, yet `len(app.query(".ctl")) == 0` while
`len(app.screen.query(".ctl")) == 5`. RESEARCH's control recipes are written as
`app.query(ControlRow)` — control #9's `max(w.region.bottom for w in app.query(ControlRow))`
and control #6's row sweep both read that way, and both would operate on an **empty**
query: the `max()` would raise `ValueError` on an empty sequence, and an
"assert every row …" loop would pass over zero rows. **Read every `app.query(...)` in
RESEARCH and PATTERNS as `app.screen.query(...)`.** `test_ui_harness.py` asserts both
sides of this so the rule is recorded by a test, not only in prose; if a future Textual
version changes it, that assertion says so explicitly.

Also measured, and part of the harness contract: **the probe screen auto-focuses `r0`
on mount**, so `tab` moves to `r1` rather than arriving at `r0`. This is consistent with
RESEARCH control #5's negative-control note ("focus stays at `r0`, so `j` lands on
`r1`"). The cursor controls read the focus position, so where it starts is not an
accident to be discovered per-test.
