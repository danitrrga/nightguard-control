# Phase 12.1: Native dashboard — pointer-first Omarchy TUI — Research

**Researched:** 2026-09-13
**Domain:** Textual 8.2.7 (installed, pinned) · Omarchy 4 theme pipeline · headless Pilot verification
**Confidence:** HIGH — every API claim below was executed against
`ngtui/.venv/lib/python3.14/site-packages/textual` on this box, not read from docs.

## Summary

The design contract (`12.1-UI-SPEC.md`) is approved and normative, so this research closed
*implementation* unknowns rather than design ones. Seven areas were probed headlessly. Five
confirmed the contract. **Four findings contradict or materially extend it**, and each would
have produced a plan that looks correct and is not:

1. **The shipped live-restyle is a no-op.** `_apply_omarchy_theme()` (`app.py:52`) does
   `register_theme(...)` then `self.theme = "omarchy"`. `App.theme` is a plain
   `Reactive(...)` with `always_update` unset, so re-assigning the *same* string never fires
   `_watch_theme`, which is the only thing that calls `refresh_css()`. Measured: after a
   theme swap the border, the fill **and the accent colour** all stayed at their old values.
   D-05 "repaint on desktop theme change" does not work today — not just for borders.
   `register_theme(...)` + `refresh_css(animate=False)` is the whole fix, and it carries
   border style, border colour, alpha and palette in one call.
2. **§13 control #7 as written cannot fail.** A `height: 1` / `width: 1fr` row's `region`
   stays `(0, y, 135, 1)` under *both* reflow bugs it is meant to catch. `content_region` /
   `content_size` discriminate on both. The requirement (UIX-05) is unchanged; the
   assertion target must move.
3. **The pipeline can be hex-free in Python too.** Variable substitution is token-level:
   `background: $foreground $ng-fill-normal;` with `$ng-fill-normal = "4%"` resolves, and
   `border-left: $ng-style $foreground $ng-a-border;` resolves with the *border style* also
   arriving as a variable. This is exact for 26 of 28 themes (their `[controls]` colours are
   literally `{{ foreground }}` from Omarchy's template) and wrong for the 2 that ship their
   own `shell.toml` and pin distinct per-state colours — so a resolved colour variable is
   still needed as the override, not as the default.
4. **`rich` cannot parse an 8-digit hex.** §12's stated ramp route
   (`Color.parse(...).with_alpha(...)` into a `rich.text.Text`) raises
   `StyleSyntaxError: unable to parse '#a9c0bf5a' as color`. Either blend explicitly
   (`bg.blend(fg, a).hex`) or use Textual's own `Content` + `textual.style.Style`, which
   blends against the widget's real background. Both proved; `Content` is better.

The colour-role pick chains in §2.4 were re-measured against all 28 installed themes and
reproduce the spec's figures exactly (1/28 → 27/28, zero unresolvable). `hyprctl` fails fast
(~10 ms) and safely in every failure mode, but writes its error to **stdout** with a
non-zero return code, so a naive `json.loads(stdout)` is the trap.

**Primary recommendation:** Build `get_css_variables()` to emit alphas, border styles and
widths as bare tokens plus one resolved colour per rung; drive every live change through
`register_theme(...)` + `refresh_css(animate=False)` from the existing 1 s tick; and write
the §13 controls against `content_size`, the *measured* ramp width and the *resolved*
`app.theme_variables[...]` values rather than against `region`, column 107 and the raw
`colors.toml`.

### Pattern 1: the live-restyle sequence (UIX-01) — the shipped path is a no-op

**What:** `App.refresh_css()` is the single call that re-runs `get_css_variables()`,
re-parses the stylesheet and re-applies it. Re-assigning `App.theme` does **not** do this
when the name is unchanged.

**Why the current code fails.** `App.theme` is declared
`theme: Reactive[str] = Reactive(constants.DEFAULT_THEME)` (`textual/app.py:560`) with
`always_update` unset, so assigning the same value skips the watcher.
`_watch_theme` (`app.py:1503`) is the *only* thing that calls
`self.call_next(partial(self.refresh_css, animate=False))` — so with the watcher skipped,
nothing refreshes. [VERIFIED: source read + executed probe]

**Measured**, one app, one screen, mutating the source of `$ng-border-normal` /
`$ng-fill-normal` and the theme's accent between each step:

```
A initial                    : (('hkey', Color(169, 192, 191, a=0.4)),  'a=0.04', accent '#7FC9C4')
B after register+theme=same  : (('hkey', Color(169, 192, 191, a=0.4)),  'a=0.04', accent '#7FC9C4')   <-- NOTHING CHANGED
C after refresh_css()        : (('vkey', Color(255, 0,   0,   a=0.9)),  'a=0.42', accent '#123456')   <-- everything changed
D after theme flip-flop      : (('tall', Color(0,   255, 0,   a=0.7)),  'a=0.11', accent '#ABCDEF')
E after refresh_css(False)   : (('solid',Color(0,   0,   255, a=0.33)), 'a=0.07', accent '#ABCDEF')
F refresh_css, theme NOT re-registered -> accent: #ABCDEF   (stale — register_theme must come first)
G register_theme + refresh_css -> accent: #0F0F0F           (minimal correct sequence)
```

Line **B** is the current `_apply_omarchy_theme()` behaviour and it is also the spec's §3
negative control for control #3 — now with real output rather than a prediction.

**The sequence to implement, in this order:**

```python
def _apply_omarchy_theme(self) -> None:
    try:
        self._style = omarchy_style()                  # 1. structure: shell.toml + hyprctl
        self.register_theme(load_omarchy_theme())      # 2. palette: colors.toml (overwrites "omarchy")
        self.theme = "omarchy"                         # 3. no-op after the first call; keep it for the first
        self.refresh_css(animate=False)                # 4. re-runs get_css_variables + reparse + update
    except (FileNotFoundError, OSError, KeyError, ValueError):
        pass                                           # cosmetic: keep the current styling
```

`refresh_css` internally does exactly
`set_variables(self.get_css_variables())` → `stylesheet.reparse()` →
`stylesheet.update(self.app, animate=…)` → `screen._refresh_layout(self.size)` → the same
update for every other screen in the stack (`textual/app.py:3797-3819`). **No separate
`stylesheet.reparse()`, `screen.refresh()` or `Theme` re-register call is needed** — and
calling them by hand would skip the other-screens pass.

`animate=False` matches what Textual's own `_watch_theme` uses and avoids cross-fading the
entire surface on a desktop theme swap.

**Cost:** `refresh_css()` re-parses the whole stylesheet. Call it only when
`ThemeWatch.changed()` is true, never unconditionally on the tick.

### Pattern 2: hex-free variables — substitution is token-level

**What:** a `$`-variable does not have to carry a whole value. Textual substitutes at the
token level, so a variable can supply just the alpha, just the border style, or just the
width.

**Verified:**

```python
CSS = """
#a { background:  $foreground $ng-a-normal; }              /* $ng-a-normal = "4%"    */
#b { border-left: $ng-style  $foreground $ng-a-border; }   /* $ng-style = "vkey"     */
"""                                                        /* $ng-a-border = "40%"   */
```
```
a bg  : Color(169, 192, 191, a=0.04)
b bord: ('vkey', Color(169, 192, 191, a=0.4))
after mutating the variables to "42%" / "hkey" / "90%" and calling refresh_css(animate=False):
a bg  : Color(169, 192, 191, a=0.42)   b bord: ('hkey', Color(169, 192, 191, a=0.9))
```

**Why this matters beyond elegance.** Omarchy's generated `shell.toml` template
(`/usr/share/omarchy/default/themed/shell.toml.tpl`) writes **every** `[controls]` colour as
`"{{ foreground }}"`. Counted: **26 of 28 installed themes get that generated file** — only
`city-783` and `dos-moos` ship their own `shell.toml`. So on 26/28 themes the base colour
*is* `$foreground` and no hex needs to be produced at all.

**But the two that ship their own deviate, and the pipeline must carry them**
[VERIFIED: read from the two files on disk]:

| Theme | Deviation | Consequence |
|---|---|---|
| `city-783` | `focus-color = "#eceff2"` ≠ `foreground "#b9bec6"`; `focus-border-width = 2`; `focus-border` is a **10-stop Hyprland gradient** `"#ad2222 … #eceff2 … 35deg"` | Needs a per-rung colour override; width must clamp to 1 cell; `_resolve_border()` must reject the gradient (it already does — returns `None`) |
| `dos-moos` | `focus-color = "#F4E276"`, `selected-color = "#819890"`, plus `pressed-color` / `selection-color` which §2.3 does not list; **no `*-border` key at all**; `[spacing]` overrides `xs=2 md=4 control-padding-y=5 panel-padding=10` | Per-rung colour override; `*-border` must fall back to `*-color` then palette `foreground`; the spacing scale is genuinely theme-variable (`panel-padding 10` → 2 cells, not 3) |

**Recommended emission shape** — hex-free by default, resolved-hex only as an override:

| Variable | Value shape | Source |
|---|---|---|
| `$ng-color-normal` … `$ng-color-pressed` | resolved hex, e.g. `#b9bec6` | `[controls] <rung>-color`, falling back to palette `foreground`; the word `accent`/`urgent`/`foreground` resolved against `colors.toml` (`Style.qml:70-75`) |
| `$ng-fill-normal` … `$ng-fill-pressed`, `$ng-fill-selection` | bare percent, e.g. `"4%"` | `<rung>-fill-alpha` |
| `$ng-border-normal-a` … | bare percent, e.g. `"40%"` | `<rung>-border-alpha` |
| `$ng-border-style` | `vkey` / `hkey` / `solid` / `round` | selected by `$ng-radius` family (§9.2) |
| `$ng-radius` | integer as string | `hypr_rounding()` |

`app.tcss` then reads `background: $ng-color-normal $ng-fill-normal;` — no hex in the file,
and the hex the pipeline produces is read from the live theme at runtime, which §2.1 already
blesses.

**Do NOT** emit `$ng-fill: "$foreground 4%"`. Substitution is not recursive at that point:

```
StylesheetParseError — Invalid value ('$foreground') for the background property
```

`$foreground 12%` written **directly in `app.tcss`** is fine and resolves
(`Color(169,192,191, a=0.12)`) — only a *variable's value* may not be a `$`-reference. So
the fixed-alpha roles (`$ng-text-caption` 70 %, `$ng-text-quiet` 50 %, `$ng-rule` 12 %) need
no variable at all; write them inline as `$foreground 70%` etc. Textual's own `HelpPanel`
does exactly this (`border-left: vkey $foreground 30%`).

### Pattern 4: the paint ladder — rule order is the mechanism

### Anti-patterns to avoid

- **`Rule` with default CSS.** `Rule.-horizontal` ships `margin: 1 0` (so a keyline costs
  **3 rows**, not 1) and `color: $secondary`. On the omarchy `Theme`,
  `$secondary == $primary == $accent` [VERIFIED: `to_color_system().generate()` → all three
  `#AC2222`], so an unstyled `Rule` paints an **accent keyline** — a direct breach of the
  §6.2 reserve ("Not a keyline") *and* of the row budget. Override both:
  `Rule { margin: 0; color: $foreground 12%; }`.
- **Re-assigning `App.theme` and expecting a repaint.** Proved dead (line B above).
- **`show_vertical_scrollbar` as an overflow signal.** Already recorded in the notes; it was
  `False` while overflowing.
- **Asserting on `Widget.region` for the no-reflow control.** It cannot fail — see below.
- **Comparing painted colours against the raw `colors.toml` value.** Textual's colour system
  shifts some roles: `accent = "#ad2222"` in the file resolves to `#AC2222` in
  `app.theme_variables`. Always compare against the resolved value.
- **Calling `refresh_css()` on every tick.** It re-parses the whole stylesheet; gate it on
  `ThemeWatch.changed()`.

### 3. Hyprland's live rounding

**Command and shape on this box:**

```
$ hyprctl getoption -j decoration:rounding
{"option": "decoration:rounding", "int": 0, "set": true }
```

(Note the trailing space before `}` — `json.loads` handles it. Both argument orders work:
`getoption -j decoration:rounding` and `getoption decoration:rounding -j`.)

**Failure modes, all measured:**

| Mode | Result | Elapsed |
|---|---|---|
| normal | `{"int": 0, "set": true}`, rc 0 | **9.9 ms** |
| `hyprctl` not on PATH | `FileNotFoundError` (a subclass of `OSError`) | immediate |
| `HYPRLAND_INSTANCE_SIGNATURE` unset (not inside Hyprland) | **rc 1**, and `HYPRLAND_INSTANCE_SIGNATURE not set! (is hyprland running?)` on **stdout** | 10.2 ms |
| bogus `$HIS` (stale socket) | **rc 4**, `Couldn't connect to /run/user/1000/hypr/bogus_0_0/.socket.sock. (4)` on **stdout** | 9.3 ms |

**The trap:** hyprctl writes its error to **stdout**, not stderr, with a non-zero return
code. `json.loads(result.stdout)` on a failure raises `JSONDecodeError`. The return code
must be checked first.

**Verified-safe implementation:**

```python
def hypr_rounding(timeout: float = 0.4) -> int:
    """Hyprland's live decoration:rounding, or 0 when it cannot be asked.

    0 is the safe default, not a guess: square is what industrial-brutalist-ui wants
    and what this box reports. hyprctl writes its errors to STDOUT with a non-zero
    return code, so the return code is checked before the JSON is parsed.
    """
    try:
        out = subprocess.run(
            ["hyprctl", "getoption", "-j", "decoration:rounding"],
            capture_output=True, text=True, timeout=timeout, check=False,
        )
    except (OSError, subprocess.SubprocessError):   # FileNotFoundError, TimeoutExpired
        return 0
    if out.returncode != 0:
        return 0
    try:
        return max(0, int(json.loads(out.stdout).get("int", 0)))
    except (ValueError, TypeError, AttributeError):   # JSONDecodeError is a ValueError
        return 0
```

Every failure path returns within ~10 ms; the 0.4 s timeout is a ceiling, not a cost. It is
called from `omarchy_style()`, which is called from `get_css_variables()` — i.e. once at
`App.__init__` and once per detected theme change, never per tick.

**Testing the failure modes without leaving Hyprland:** monkeypatch `subprocess.run` to
raise `FileNotFoundError`, to return `CompletedProcess(returncode=1,
stdout="HYPRLAND_INSTANCE_SIGNATURE not set! (is hyprland running?)\n\n")`, and to return
`returncode=0, stdout="not json"`. All three must yield `0`.

### 6. No-reflow (control #7): the assertion that actually discriminates

### 7. Counting accent cells (§6.3) — working idiom

```python
from rich.cells import cell_len
from textual.color import Color

def count_accent_cells(app) -> tuple[int, int]:
    """(accent-painted cells, total cells) for the composed screen.

    render_strips() is private API. Acceptable inside a test against a pinned
    dependency; never reached from application code.
    """
    accent = Color.parse(app.theme_variables["accent"])   # the RESOLVED value, not colors.toml
    target = (accent.r, accent.g, accent.b)
    hits = total = 0
    for strip in app.screen._compositor.render_strips():
        for text, style, _ in strip:
            width = cell_len(text)
            total += width
            if style is None:
                continue
            fg = style.color.get_truecolor() if style.color else None
            bg = style.bgcolor.get_truecolor() if style.bgcolor else None
            if bg is not None and (bg.red, bg.green, bg.blue) == target:
                hits += width                                        # a background paints every cell
            elif fg is not None and (fg.red, fg.green, fg.blue) == target:
                hits += sum(1 for ch in text if not ch.isspace())     # a foreground paints only glyphs
    return hits, total
```

Measured at `run_test(size=(135, 46))`:

```
accent cells = 154   total cells = 6210   ratio = 2.48%     ceiling (5%) = 310
NEGATIVE CONTROL — frame border repainted in $accent + one accent-background row:
accent cells = 424   total cells = 6210   ratio = 6.83%     -> trips the 310 ceiling
```

`total == 6210` exactly, confirming §6.3's figure and that `cell_len` is the right width
function (not `len(text)`).

**Compare against `app.theme_variables["accent"]`, never against the raw `colors.toml`
value.** Textual's colour system shifts some roles: `city-783`'s `accent = "#ad2222"`
resolves to `#AC2222`. A test parsing the theme file would count zero accent cells and pass

## Common Pitfalls

### Pitfall 1: the theme reassignment that repaints nothing
**What goes wrong:** `register_theme(...) + self.theme = "omarchy"` looks like a repaint and
is a no-op.
**Why:** `App.theme` is a plain `Reactive` — same value, no watcher, no `refresh_css`.
**Avoid:** always end the restyle with `self.refresh_css(animate=False)`.
**Warning sign:** a theme swap changes the terminal's own colours (Omarchy retints the
terminal) while the TUI's surfaces stay put — which reads as "it worked" at a glance.

### Pitfall 2: a `$`-variable whose value is a `$`-reference
**What goes wrong:** `v["ng-fill"] = "$foreground 4%"` → `StylesheetParseError: Invalid
value ('$foreground') for the background property`.
**Avoid:** either emit a resolved colour + alpha, or emit only the alpha token and let
`app.tcss` write `background: $foreground $ng-fill-normal;`.
**Note:** `$foreground 4%` written **directly in `app.tcss`** is fine. The restriction is on
variable *values* only.

### Pitfall 3: state read by `get_css_variables()` assigned after `super().__init__()`
**What goes wrong:** `AttributeError: 'NightguardApp' object has no attribute '_style'`
during construction — before any screen exists, so it reads as an import-time crash.
**Why:** `Stylesheet(variables=self.get_css_variables())` runs at `textual/app.py:729`.
**Avoid:** assign `self._style` (and anything else it touches) **before** `super().__init__()`.

### Pitfall 4: `hyprctl` errors on stdout
**What goes wrong:** `json.loads(result.stdout)` raises `JSONDecodeError` outside Hyprland,
because hyprctl writes `HYPRLAND_INSTANCE_SIGNATURE not set!` to **stdout** with rc 1.
**Avoid:** check `returncode` first; catch `OSError` (covers `FileNotFoundError`) and
`subprocess.SubprocessError` (covers `TimeoutExpired`); return `0`.

### Pitfall 5: an unstyled `Rule` breaks two contracts at once
**What goes wrong:** it costs 3 rows (`margin: 1 0`) and paints in `$secondary`, which
equals `$accent` on the omarchy `Theme`.
**Avoid:** `Rule { margin: 0; color: $foreground 12%; }` — or draw keylines with a `Static`.
**Warning sign:** the row budget (§7.2) overruns by exactly 4 rows (two margin rows on each
of the two keylines above the fold) and the accent count jumps by ~258 cells (2 × 129).

### Pitfall 6: a no-reflow test that cannot fail
**What goes wrong:** `assert row.region == row.region` across states passes under both reflow
bugs.
**Avoid:** assert on `content_size` / `content_region`.
**Warning sign:** the negative control "give one state a wider border" does not turn the test
red. If that happens, the test is not evidence.

### Pitfall 7: hardcoding the ramp probe column
**What goes wrong:** `offset=(107, 0)` expecting `21:30` is a width-120 result; the real ramp
is 129 wide, where 107 → `20:00` and the curfew edge is column 116.
**Avoid:** compute the expected column from the widget's measured width inside the test —
which is also §7.3's rule for the ramp itself ("No literal ramp width in code").

### Pitfall 8: comparing against the theme file's hex instead of the resolved one
**What goes wrong:** the accent-count test finds zero accent cells and passes.
**Why:** Textual's colour system shifts some values (`#ad2222` → `#AC2222`).
**Avoid:** read `app.theme_variables["accent"]`.

### Pitfall 9: a bare `async def` test
**What goes wrong:** `async def functions are not natively supported.` — reported as a
failure, not an error, so it can look like a real assertion failure.
**Avoid:** wrap in `asyncio.run()` inside a sync test, or mark with `@pytest.mark.asyncio`.

### Pitfall 10: stale `theme.name` immediately after a swap
**What goes wrong:** the header shows the previous theme's name for up to ~440 ms after a
change, and keeps showing it because the watcher already consumed the event.
**Avoid:** watch `theme.name` as the signal, or re-read `theme_name()` at paint time rather
than caching it at restyle time.

## Security Domain

`security_enforcement` is not set in `.planning/config.json`, so it is treated as enabled.
This phase is a terminal-UI restyle with **no network surface, no persistence, no
authentication and no cryptography**. The honest answer for most ASVS categories is "does
not apply", and inventing controls here would be theatre.

### Applicable ASVS categories

| ASVS category | Applies | Standard control |
|---|---|---|
| V2 Authentication | no | The only authentication on the product is `sudo` under `App.suspend()` with a real PTY — **out of scope and unchanged** (CONTEXT scope fence). |
| V3 Session Management | no | No sessions. |
| V4 Access Control | **indirectly — the phase's own premise** | The refusal to accept a weakening keystroke outside the edit window is enforced by `backend.py` and the signer's direction classifier, not by the UI. The rendering of the four frozen keys as *refused* must not become the enforcement — the row's `refusal` string is presentation; the signer still refuses. Covered by the untouched `test_edit_window*.py`. |
| V5 Input Validation | **yes, narrowly** | Every value read this phase comes from a **TOML file** parsed by stdlib `tomllib`, plus one subprocess's JSON. Both are already fail-closed. The new surface is `hyprctl` stdout — validated by checking `returncode` before `json.loads`, and clamping the result with `max(0, int(...))`. |
| V6 Cryptography | no | The TUI holds no key and computes no HMAC — pinned by `test_port03_no_crypto.py`, which stays green. |

### Known threat patterns for this stack

| Pattern | STRIDE | Standard mitigation |
|---|---|---|
| A malformed or half-written `shell.toml` / `colors.toml` crashes the running TUI mid-theme-swap | Denial of Service | Already handled: `raw_shell()` / `raw_tokens()` return `{}` on `OSError`/`TOMLDecodeError`; `_apply_omarchy_theme` catches and keeps the current styling. The atomic directory rename means a half-written file is never visible, but the guard stays. |
| `hyprctl` hangs (stale socket, compositor wedged) and freezes the 1 s tick | Denial of Service | `timeout=0.4` plus `except subprocess.SubprocessError` → `0`. Measured: every failure mode returns in ~10 ms. Called only on a detected theme change, never per tick. |
| A malicious theme injects a value that ends up in a shell or a widget's content | Injection / Tampering | Theme values reach **CSS variables and colour parsing only** — never a shell, never `eval`, never `subprocess`. A bad value produces a `StylesheetParseError` at reparse, not execution. `refresh_css` reparses into a *fresh* `Stylesheet` and keeps the old one on error (`css/stylesheet.py:409-430`), so a bad theme degrades rather than crashing. |
| The visual refusal is mistaken for enforcement | Elevation of Privilege | **The named risk of this phase.** A row rendered "refused" must never be the only thing stopping a change. The seam (§8.6) hands a `route` or a `refusal` to the *existing* edit surface, which still goes through `backend.commit()` and the signer. The plan must not add a UI-side allow/deny decision. |
| `render_strips()` (private API) reached from application code | — | Test-only. Enforce with a grep control: `_compositor` must not appear under `ngtui/ngtui/`. |
