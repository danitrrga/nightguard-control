## Pattern Assignments

### `ngtui/ngtui/theme.py` — `style_variables(style) -> dict[str, str]` (new, pure)

**Analog:** `ngtui/ngtui/panel.py:270-300` — `style_view()`. Same signature shape
(one dict in, one flat dict out), same "every key falls back individually" discipline,
same no-Textual-import constraint. This is the function to copy.

**The per-key fallback table** (`panel.py:248-266`) — a module-level dict whose *values*
are the defaults, so the mapper is a loop rather than 20 hand-written `or` chains:

```python
STYLE_FALLBACK = {
    "mode": "dark",
    "name": "",
    "popup_background": "#2d353b",
    ...
    "control_fill_alpha": 0.04,
    "control_border_alpha": 0.4,
    "control_border_width": 1,
    "font_base": 12,
    "spacing_scale": 1.0,
    "spacing_scale_with_font": True,
}

# Style tokens that are plain text rather than colours. Everything else in
# STYLE_FALLBACK that is a string is a hex value and is validated as one.
_STYLE_TEXT_KEYS = frozenset({"mode", "name"})
```

**The mapping loop itself** (`panel.py:284-300`) — type-dispatch on the *fallback's*
type, which is what makes one loop cover bools, hex strings, plain strings and numbers:

```python
    tokens = tokens or {}
    out = {}
    for key, fallback in STYLE_FALLBACK.items():
        value = tokens.get(key)
        if isinstance(fallback, bool):
            out[key] = bool(value) if isinstance(value, bool) else fallback
        elif key in _STYLE_TEXT_KEYS:
            # Plain strings, not colours. Validating these as hex silently
            # dropped every light theme's "light" back to the "dark" default.
            out[key] = value if isinstance(value, str) and value.strip() else fallback
        elif isinstance(fallback, str):
            out[key] = value if isinstance(value, str) and value.startswith("#") else fallback
        else:
            try:
                out[key] = type(fallback)(value)
            except (TypeError, ValueError):
                out[key] = fallback
    return out
```

**Divergence the planner must carry:** `style_variables()`'s output values are all
**strings** (`"4%"`, `"vkey"`, `"#b9bec6"`, `"0"`) because Textual substitutes variables
at the token level. So the numeric branch becomes a format step (`f"{alpha:.0%}"` or
`f"{int(alpha * 100)}%"`), not a `type(fallback)(value)` cast. RESEARCH §"Pattern 2"
forbids emitting `$foreground 4%` as a *variable value* — that raises
`StylesheetParseError — Invalid value ('$foreground') for the background property`.

**Docstring convention** to mirror (`panel.py:270-282`): the docstring states *why the
role exists*, names the failure it prevents, and calls out the one token deliberately
absent. Copy that shape — the project's docstrings are load-bearing, not decorative.

### `ngtui/ngtui/theme.py` — the colour-role pick chains (D-09 / D-11)

**Analog:** `ngtui/ngtui/panel.py:204-222` — `theme_view()`. The `pick(*names)` closure is
exactly the mechanism `_theme_from_colors()` is missing, already written and already swept
by a 28-theme test.

```python
def theme_view(tokens):
    """Map the desktop palette onto the roles the panel paints with.

    Every role falls back individually: a theme that ships a partial colors.toml
    should lose one colour, not the whole palette.
    ...
    """
    tokens = tokens or {}

    def pick(*names):
        for name in names:
            value = tokens.get(name)
            if isinstance(value, str) and value.startswith("#") and _rgb(value):
                return value
        return None

    background = pick("background", "dark_background")
    foreground = pick("foreground", "bright_foreground")
```

and the tail (`panel.py:230-242`), which is where the per-role chains live and where the
final `or FALLBACK[k]` sweep happens exactly once:

```python
    view = {
        "background": background,
        "surface": pick("lighter_background", "selection"),
        ...
        "ok": pick("green", "bright_green"),
        "warn": pick("yellow", "bright_yellow"),
        "alert": pick("red", "bright_red"),
    }
    return {k: (v or THEME_FALLBACK[k]) for k, v in view.items()}
```

**What changes in `theme.py`.** Today `_theme_from_colors()` (`theme.py:237-250`) has no
chain at all — one `.get(key, default)` per role, and the default is `accent`, which is
precisely the verdict-colour collapse the colour-role decision (D-09) names:

```python
def _theme_from_colors(c: dict) -> Theme:
    """Build the omarchy ``Theme`` from a parsed ``colors.toml`` dict."""
    return Theme(
        name="omarchy",
        primary=c["accent"],
        background=c["background"],
        foreground=c["foreground"],
        surface=c.get("color0", c["background"]),
        accent=c["accent"],
        success=c.get("color2", c["accent"]),
        warning=c.get("color3", c["accent"]),
        error=c.get("color1", c["accent"]),
        dark=True,
    )
```

Port `pick()` in, keep the `Theme(...)` call shape, and keep
`_theme_from_alacritty()` (`theme.py:253-277`) routing through `_theme_from_colors` —
its comment "Reuse `_theme_from_colors` so the role mapping lives in exactly one place"
(`theme.py:266`) is the invariant the pick chains must not break.

**Do not** copy `panel.py`'s `_dimmer_than()` measurement (`panel.py:180-202`) unless a
role genuinely needs it — `theme.py` has no `muted` role and the sweep asserts declared
provenance, not contrast.

### `ngtui/ngtui/theme.py` — `hypr_rounding()` (new, subprocess, fail-closed)

**Analog:** `ngtui/ngtui/backend.py:272-285` — the only fail-closed `subprocess.run` in
`ngtui/`. Copy its *posture* (swallow everything, never propagate, comment why), not its
argument list:

```python
        # ... The push is fire-and-forget: check=False and a
        # swallow-all try/except so a missing pkill / absent waybar / any OSError can
        # NEVER flip the bar on a refused commit (T-12-02) nor propagate into or alter
        # the commit result (T-12-03) — the returned dict is built independently below.
        if rc == 0:
            try:
                subprocess.run(
                    ["pkill", "-RTMIN+11", "waybar"],
                    stdout=subprocess.DEVNULL,
                    stderr=subprocess.DEVNULL,
                    check=False,
                )
            except Exception:
                pass
```

**Three gaps between the analog and what `hypr_rounding()` needs** — each is a real
divergence, not a style preference:

1. **`timeout=` is absent from the analog.** `hypr_rounding()` must pass one
   (`timeout: float = 0.4`), which means also catching `subprocess.SubprocessError`
   (`TimeoutExpired`'s base) alongside `OSError` (`FileNotFoundError`'s base).
2. **The analog does not read stdout.** `hypr_rounding()` does, and here is the trap
   RESEARCH measured: **`hyprctl` writes its errors to stdout with a non-zero return
   code.** `HYPRLAND_INSTANCE_SIGNATURE not set! (is hyprland running?)` arrives on
   *stdout* with `rc 1`; a stale socket gives `rc 4` on stdout. So `returncode` must be
   checked **before** `json.loads(out.stdout)`, or the failure path raises
   `JSONDecodeError` instead of returning 0.
3. **`except Exception: pass` is too broad for a value-returning function.** Use the
   narrow tuple the rest of `theme.py` uses (`theme.py:78`, `:93`, `:213`, `:291`) —
   `except (OSError, subprocess.SubprocessError)` on the call and
   `except (ValueError, TypeError, AttributeError)` on the parse, since
   `json.JSONDecodeError` is a `ValueError`.

**Secondary analog, with a warning:** `scripts/linux/verify_browser_lock.py:121-128`
uses `subprocess.run(..., capture_output=True, text=True, timeout=...)` — the closest
match for the *call shape*. Do **not** copy its `out = proc.stdout + proc.stderr`
merge and do not copy its lack of a `returncode` check; for `hyprctl` that merge is
exactly the bug. (That file is also currently untracked — `git status` shows it as `??` —
so it is a weaker precedent than `backend.py`.)

**Full target implementation is already written out** in `12.1-RESEARCH.md`
§"3. Hyprland's live rounding" with all four measured failure modes. Copy it verbatim.

### `ngtui/ngtui/theme.py` — `ThemeWatch` watching `shell.toml` as well

**Analog:** itself, `theme.py:308-340`. The load-bearing property is the re-resolved
`path` property, and its docstring says why — do not regress it into a list of frozen
paths:

```python
    @property
    def path(self) -> str:
        """Re-resolved on every read, so a theme change that also moves the
        directory (an omarchy 3 to 4 upgrade under a running TUI) is still seen.
        An mtime poll by path is what makes that safe: unlike an inotify watch on
        the inner file, re-stat'ing follows the directory omarchy swapped in."""
        return self._fixed_path if self._fixed_path is not None else colors_path()

    def _stat(self) -> float:
        try:
            return os.stat(self.path).st_mtime
        except OSError:
            return 0.0

    def changed(self) -> bool:
        m = self._stat()
        if m != self._mtime:
            self._mtime = m
            return True
        return False
```

Widening to two files means `_stat()` returns a tuple/sum over both paths, and `path`
becomes `paths`. Keep `changed()` consuming the change exactly once —
`tests/test_theme.py:117-131` asserts that (`changed()` → `True`, then `False`).

### `ngtui/ngtui/app.tcss` (stylesheet)

**Analog:** itself, plus one external file for the hex-free idiom.

/* app.tcss — Textual CSS for the StatusScreen.
 *
 * Colour is expressed ONLY through $-variable role names fed by the live omarchy
 * theme (theme.py -> register_theme). No fixed hex appears here: the brand is the

#status-word.success { color: $success; }
#status-word.accent  { color: $accent; }   /* grace word — accent reserved */
#status-word.warning { color: $warning; }

`textual/widgets/_help_panel.py:16-28`, i.e. the framework's own stylesheet does exactly

## Shared Patterns

### Docstrings carry the WHY and the failure they prevent

**Source:** everywhere. `theme.py:322-326`, `panel.py:270-282`, `status.py:250-255`,
`test_theme_sync.py:1-15`, `test_deploy_completeness.py:1-10`.
**Apply to:** every new function, widget and test in this phase.

The house style is a one-line summary, a blank line, then prose explaining *why this
exists* — frequently naming the exact bug that produced it ("This caught exactly that:
appblock.py was written, imported by the watchdog, and missing from the install list.").
Several also name the decision ID (D-05, T-10-05, WR-03, CR-01, PORT-01) and the review
that found it ("Codex + opencode cross-model review, 2026-09-07"). Phase 12.1's identifiers are its
context decisions (D-01…D-16) and its phase requirements (UIX-01…UIX-06).

Per CLAUDE.md's redundancy rule, **the control record stays**: each negative control's
measured failure message goes in the test docstring, not only in the plan.

### Narrow exception tuples, never bare `except`

**Source:** `theme.py:78` `except (OSError, tomllib.TOMLDecodeError)`; `theme.py:213`
`except (KeyError, TypeError, ValueError)`; `theme.py:291`
`except (FileNotFoundError, IsADirectoryError, tomllib.TOMLDecodeError, KeyError)`;
`status.py:92` `except (ValueError, TypeError, OSError)`.
**Apply to:** `hypr_rounding()`, `style_variables()`, the extended `omarchy_style()`.

The two broad `except Exception: pass` sites in the codebase are both *widget query*
guards with a stated reason (`status.py:259-261`, `edit.py:513-516`) or a
*fire-and-forget side effect* (`backend.py:284-285`). A value-returning pure function
uses the narrow tuple.

### Colour reaches a widget as a role *name*, never a value

**Source:** `status.py:31-42` (`_VERDICT_MAP` stores `"error"`, `"success"`, `"accent"`),
`status.py:156` (`classes=role`), `app.tcss:43-46` (the class selectors),
`edit.py:64-84` (`preview_line` returns `(text, role)`), `edit.py:502-505`
(`cell.set_classes(role)`).
**Apply to:** `ControlRow`, `DayRamp`'s permission channel, every new row and chip.

This is the mechanism that makes D-12's hex ban enforceable by a file scan: no widget
module ever names a colour, so `test_no_fixed_hex.py` scanning `widgets/*.py` is
sufficient. The ramp is the single exception — it reads
`app.theme_variables["foreground"]`, a *resolved runtime value*, which is not a literal
and does not trip the scan.

### Meaning never rides on colour alone

**Source:** `status.py:14-16` (module docstring), `status.py:31` (`glyph + word + colour`
in one tuple), `status.py:80` ("reads as filled-vs-hollow even with no colour"),
`edit.py:70-84` (`▼ Tightens` / `▲ Loosens` — the glyph carries direction).
**Apply to:** every new row, the verdict, the ramp's permission channel, the refusal rows.

D-13 restates it and adds the counted 5 % accent guardrail. The existing code is already
compliant; the new widgets inherit the rule, and control #10 is what makes it checkable.

### Compare against the *resolved* value, not the theme file

**Source:** a new rule from RESEARCH, with an in-repo precedent in spirit —
`test_theme_sync.py:86-89`'s provenance set is built from the theme file because
`panel.theme_view` never leaves Python. Textual's colour system **shifts** some roles
(`city-783`'s `accent = "#ad2222"` resolves to `#AC2222` in `app.theme_variables`).
**Apply to:** every Pilot-based assertion about colour — the accent counter, the fill
alpha, the border colour. Read `app.theme_variables[...]`, never `colors.toml`.

### `refresh_css()` is the only sanctioned repaint

**Source:** none in repo — the current code does the no-op. RESEARCH Pattern 1 has the
measured sequence and the seven-row table of what is and is not needed.
**Apply to:** `app.py::_apply_omarchy_theme()` only. No other call site may call
`refresh_css`, `stylesheet.reparse()` or `screen.refresh()`, and it must stay gated on
`self._theme_watch.changed()` because it re-parses the whole stylesheet.
