# Phase 12.1: Native dashboard — pointer-first Omarchy TUI — Context

<domain>
## Phase Boundary

Restyle and re-*behave* the Textual TUI (`ngtui/`) so it reads as a native Omarchy 4
application rather than a terminal form, driven from the live desktop theme's structural
tokens and from one cursor shared between pointer and keyboard.

This phase changes how the existing surface looks and how it is operated. It adds no
editing capability: the set of editable fields is exactly what it is today
(`ngtui/ngtui/widgets/edit.py:216`). The four frozen blocking keys are rendered honestly as
refused, with the seam left for Phase 12.2 to open.

The full visual and interaction contract is `12.1-UI-SPEC.md` in this directory —
approved 6/6 by the design checker. That document is normative; this one carries the
decisions behind it and the fences around it.
</domain>

<decisions>
## Implementation Decisions

### The user's own words — the generation change

> "Realmente lo que estamos haciendo es un cambio de generación, donde también la propia
> manera de interactuar con el producto se siente distinta. Ahora mismo no tenemos que
> utilizar solo teclados, atajos de teclado y tal para moverme con la interfaz. Investiga
> cómo está haciendo DHH lo que son los mini dashboards. Tiene que ser algo parecido,
> realmente como una aplicación de Omarchy nativa. Sigue lo que son los patrones de diseño,
> conducta, bordes y todo, la mayoría, lo que puedas, y manteniendo esta estética que
> acabamos de crear que me gusta mucho. Sobre todo, céntrate en la experiencia de usuario,
> que sea lo menos rudimentaria posible dentro de lo que cabe dentro de Linux, Arch Linux."

- **D-01:** The aesthetic is settled and is not reopened: the device frame, the greyscale
  ASCII density ramp as hero, outline chips with the selected one inverted, corner labels,
  one accent dot. Chosen across four sketch rounds in `.planning/sketches/00{1,2,3,4}-*/`.
  What changes in this phase is the *interaction*, because "it looks like the old one" was
  about behaviour, not pixels.
- **D-02:** The TUI is operated by pointer **and** keyboard, with **one cursor** shared
  between them. Hovering a row moves the keyboard cursor, so the two can never disagree.
  This is the single mechanism that makes the Omarchy panels feel native
  (`hot = containsMouse || hasCursor` plus the `hovered(bool)` signal, read out of
  `/usr/share/omarchy/shell/Ui/Button.qml` and `plugins/panels/monitor/Panel.qml`).
- **D-03:** Every changeable value on the home surface is a control whose **whole row** is
  the click target. No action may require a memorised bracket hint. Keyboard-only operation
  must remain complete — every control reachable and activatable with `Enter`/`Space`.
- **D-04:** Paint priority is pressed > focus > hover/cursor > selected > active > idle,
  each rung taking its fill and border alpha from the theme's own `[controls]` values.
- **D-05:** Borders are **reserved**, not grown: every control reserves the widest border
  any of its states can paint, so hovering never relayouts a neighbour.
- **D-06:** The day is a full-width instrument, not a number: an ASCII density ramp where
  density is hours-until-curfew, with a separate channel for the hours in which a loosening
  is accepted, and a marker for now. Hovering a column reads out that hour and whether a
  loosening would be accepted there — proved workable, see D-14.

### Theme — the real gap this phase closes

- **D-07:** `app.tcss` and the widgets are restyled from the live theme's **structural**
  tokens, not only its colours: `[controls]` state fills and border alphas, `[spacing]`,
  `[font]`, plus Hyprland's live `decoration:rounding`. The parser for those tokens already
  exists (`ngtui/ngtui/theme.py:160`) and its only consumer today is the bar panel feed
  (`ngtui/ngtui/__main__.py:136`), which is why the terminal UI looks old while still
  following the desktop's colour.
- **D-08:** Switching the desktop theme must restyle the **running** TUI, borders and
  fills included. The route is `get_css_variables()` + `refresh_css()`; the naive route
  (theme variables referenced from `app.tcss`) dies at compose with
  `UnresolvedVariableError`. Two constraints came out of probing it: variables must be
  assigned *before* `super().__init__()`, because `get_css_variables()` is called from
  `App.__init__`; and variable substitution is **not recursive**, so a fill must be written
  as a resolved hex plus alpha, never as `$foreground 4%`.
- **D-09:** **The verdict colours are fixed here.** Loading every installed `colors.toml`
  through the shipped loader shows **26 of 28 themes collapse `accent`, `success`, `warning`
  and `error` to one colour**; only `city-783` resolves four distinct, `dos-moos` three.
  The cause is a key vocabulary the loader does not know — 26 themes declare `red`/`green`/
  `yellow` and no `color1/2/3`, which is all `_theme_from_colors`
  (`ngtui/ngtui/theme.py:237`) reads. Probed pick chains take this from 1/28 to 27/28 with
  nothing unresolvable. This inverts the product's own accessibility contract, so it is in
  scope: half the colour contract is meaningless while the colour channel is monochrome.
  The root cause is a **test gap** — there is a theme sweep for the bar panel's mapping
  (`ngtui/tests/test_theme_sync.py`) and none for the Textual role mapping.
- **D-10:** Fix `ngtui/ngtui/theme.py` only. The same class of gap exists in
  `ngtui/ngtui/panel.py:232`, which feeds the out-of-bounds bar panel; leave it, and leave
  its one red test named rather than silently green.
- **D-11:** The theme sweep must not lie, so it asserts what is actually true across the
  28 themes: the three verdict roles distinct from **each other** (not including accent,
  because `dos-moos`' `color2` *is* its accent), and never `surface != background`, because
  on four themes they are legitimately equal — which is also why alpha-on-foreground control
  fills are correct rather than merely stylistic.

### Colour and copy

- **D-12:** No fixed hex anywhere in `app.tcss` or in any widget. The live desktop theme
  is the only source of colour. The Moonlit Indigo palette stays withdrawn.
- **D-13:** The accent reserve is a closed two-item list, and the 5 % guardrail is a
  **counted** assertion against the 6210-cell screen, not a stated ratio. Meaning never
  rides on colour alone: glyph, word and colour travel together so a monochrome terminal
  loses nothing.

### Proved before planning, so the plan treats these as mechanics rather than bets

- **D-14:** Probed headlessly against the installed `textual 8.2.7`, recorded in
  `12.1-NOTES-interaction-probes.md`: the shared cursor works and is assertable
  (hover row 2, then `j`, lands on row 3 rather than row 0); the 135 × 46 overflow
  assertion **discriminates** (passes at 40 and 46 rows, fails at 60), with the caveat that
  `show_vertical_scrollbar` is not a usable overflow signal; and the per-column ramp
  read-out resolves column 107 of 120 to 21:30, the exact curfew start.
- **D-15:** Match the desktop's tooltip delay: `App.TOOLTIP_DELAY` defaults to 0.5 s and
  Omarchy's kit uses 0.4 s. One line, and the default is close enough to look deliberate if
  it is missed.

### Framework chrome

- **D-16:** Remove Textual's `Header` and `Footer`. They are framework chrome and the two
  things that most make this read as a terminal form. Discoverability moves to a `help`
  chip opening the help panel. The **bindings themselves must survive unchanged** —
  `ngtui/tests/test_port01_single_key_bindings.py` is the control.

### Claude's Discretion

- Widget decomposition and file layout inside `ngtui/ngtui/widgets/`.
- Which Textual border glyph set carries which rung, within the sets enumerated in the
  design contract (§9.2).
- Test file organisation, provided each control named in the contract (§13) exists and each
  negative control is demonstrated able to fail.
- Whether the pointer shape hint is set (recommended yes — one CSS line, degrades silently,
  and no test may assert it).
</decisions>

<specifics>
## Specific Ideas

- The window is fixed at `size 875 600` by
  `packaging/omarchy/hypr/nightguard.windowrule.conf:8`, which at CaskaydiaCove Nerd Font
  8pt (a 6.25 × 12.40 px cell) is **135 × 46 cells**. That is the canvas, and the overflow
  test is what keeps it honest.
- One Omarchy behaviour does **not** translate: a terminal cannot change the pointer's
  shape. The hover fill carries the whole affordance instead. Named rather than pretended
  away — it is the ceiling of what Linux gives here.
- Type scale translates to weight, case, dim and glyph mass, not to font sizes.
</specifics>
