<objective>
Wire the structural tokens into the running app, and rewrite the stylesheet they feed.

The shipped live-restyle path is a **no-op**. `App.theme` is a plain `Reactive` without
`always_update`, so assigning the same string never fires `_watch_theme`, which is the only
caller of `refresh_css`. Measured across a theme swap: the border stayed
`('hkey', Color(169,192,191, a=0.4))`, the fill stayed `a=0.04` and the accent stayed
`#7FC9C4` — all three unchanged. That is exactly what `_apply_omarchy_theme()` does today,
and its docstring's claim that reassigning the reactive "forces Textual to refresh every
`$variable` and repaint" is false on the installed version.

Purpose: these two files must land together. Without `get_css_variables()` the stylesheet
cannot resolve `$ng-*` and the app dies at compose with `UnresolvedVariableError`; without
the stylesheet the variables have no consumer. There is no intermediate state where one is
useful alone.
Output: the app restyles itself from the desktop's structure, and the paint ladder exists
for the widgets the next wave builds.
</objective>

    Rewrite `ngtui/ngtui/app.tcss`. Keep the header's shape — a reader must still learn the
    two rules from the top of the file — and rewrite its specifics to name the `$ng-*`
    pipeline and the closed accent reserve.

    **`#frame`**: four per-edge borders, `hkey` top and bottom, `vkey` left and right, all in
    the normal border role, plus `padding: 0 2`. That is 1 row top, 1 row bottom, 1 column
    each side, plus a 2-column inner gutter, and it is why nothing else on the screen needs a
    box. **No region draws its own outline.**

    **The paint ladder, declared in exactly this order, because the order IS the mechanism:**
    `.ctl` → `.ctl.-selected` → `.ctl:focus` → `.ctl.-pressed` → `.ctl.-staged` →
    `.ctl.-refused`. `:focus` counts as a class for specificity, so `.ctl:focus` and
    `.ctl.-pressed` tie and the **later** rule wins — verified: with `-pressed` declared
    after `:focus`, a focused-and-pressed row painted the pressed colour. Each rung takes its
    fill and border alpha from the `$ng-*` variables, never a literal. The cursor rung serves
    pointer and keyboard alike, because in this TUI the cursor *is* focus — which is also
    what the theme intends: `shell.toml`'s own comment on `focus-*` says to mirror the
    hover-cursor values so mouse hover, keyboard cursor and tab focus read as one state.

    `$ng-fill-focus` / `$ng-border-focus` are **not** unused — reserve them for the one place
    where Textual focus means something other than the cursor: a text `Input` in edit mode,
    where the theme's dedicated focus ring is the correct signal. That place is `#inline-edit`
    (currently `border: none`, line 142) and `#commit-pass`. `$ng-fill-selection` styles those
    inputs' text selection. Nothing else in the edit surface is touched — the rest of the edit
    screen is out of this phase's remit.

    **Border reservation.** A `.ctl` row's border is `border-left: vkey`, one column, in
    **every** state including idle, where it is the normal border role and never `none`. The
    row is always `height: 1` and its left inset is always 2 cells. Only the colour changes.
    Nothing on this screen may change size in response to input.

    **Timings.** `transition: background 120ms linear, color 120ms linear` on `.ctl`.
    Add the CSS comment stating that **border colour cannot be animated** — Textual's
    `ANIMATABLE` set contains `background` and `color` but not `border`, so a state change
    cross-fades its fill and snaps its border colour. That comment is there so nobody spends
    a day trying to fix it.

    **Delete all five `border: round`.** `decoration:rounding` is 0 on this box and the
    reference aesthetic wants square. `$ng-radius` selects the family — `0` gives
    `hkey`/`vkey`/`solid`; a non-zero radius permits `round`. Read the token; hardcode
    neither. And do not soften halfway: a rounded border plus a hairline frame is the hybrid
    the reference explicitly calls a mistake. Note that lines 77 and 113 also use
    `$surface-lighten-1`, and `surface == background` on 4 of the 28 installed themes — which
    is the measured reason the ladder uses alpha-on-foreground fills instead of a surface role.

    **Changing the border *shape* is only half of it — change the border *colour* too.**
    Two of those five declarations are accent-coloured and sit on the confirm dialog:
    `#confirm-box` (line 189) and `#commit-pass` (line 229) are both `border: round $primary`.
    Rewriting them to a square family while leaving `$primary` in place keeps the accent
    breach alive under a different keyword, and **no test in this phase would catch it**: the
    accent-cell count (control 10) composes the status screen, and the confirm dialog is a
    modal screen that is never pushed in that test. So wire the popup roles the pipeline
    already produces — `$ng-popup-border` for both borders, with `$ng-popup-bg` and
    `$ng-popup-text` on `#confirm-box` per the popup mapping — and take `$primary` off both.

    Note that `#commit-pass` is **not** in the design contract's list of three accent
    breaches (§6.2). It is a fourth, found while checking the plan against the live file. The
    contract's list was not exhaustive; the grep below is, which is why the criterion is a
    whole-file scan rather than a fixed list.

    **`Rule { margin: 0; color: $foreground 12%; }`** — override both properties. An unstyled
    `Rule` ships `margin: 1 0`, so a keyline would cost **3 rows** instead of 1 and blow the
    row budget by exactly 4 rows; and it paints in `$secondary`, which on the omarchy `Theme`
    equals `$primary` equals `$accent` — a direct breach of the accent reserve's "not a
    keyline", worth about 258 accent cells across two keylines.

    **Fixed-alpha roles need no variable.** Write `$foreground 70%` (caption channel),
    `$foreground 50%` (quiet channel) and `$foreground 12%` (keylines) directly in the file.
    `$foreground 4%` written in `app.tcss` resolves fine — the no-recursive-substitution
    restriction applies only to a *variable's value*. Textual's own `HelpPanel` stylesheet
    does exactly this.

    **`pointer: pointer` on `.ctl`** — one line, progressive enhancement only. It emits the
    Kitty pointer-shape protocol, which `foot` documents but the terminal that actually
    launches `ngtui` is resolved by `xdg-terminal-exec` and is not pinned. Nothing may depend
    on it and **no test may assert it** (OD-3).

    Add the four degradation classes on `#frame` — `-compact`, `-tiny`, `-narrow` — with
    their effects per §7.4. The `on_resize` handler that toggles them arrives in a later
    plan; the rules land now so the stylesheet is written once.

    Add the classes the next wave's widgets need, so `app.tcss` is not reopened per widget:
    `.chip`, `.chip.-primary` (the one filled chip, inverting to `$background` on
    `$foreground` — **not** to the accent), `#ramp`, `#permission`, `#hour-axis`,
    `#readout`, `.section-label`, `.kv-*` as the composition needs them.

    **Zero literal hex.** Control 1 is live and scanning this file.
