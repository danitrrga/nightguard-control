<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| live desktop theme files → the test process | `~/.local/state/omarchy/current/theme/` is outside the repo and rewritten by `omarchy-theme-set` at any moment |
| the test suite → the trust stack | `conftest.py` already repoints `backend.py`'s paths at `tmp_path`; a new fixture must not open a route back to the real `guard.json` |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-12.1-01 | Elevation of Privilege | the UI fixture group | mitigate | `probe_app` pushes a bare probe screen, never `EditScreen`; no fixture may call `backend.commit()`, `preview_change()` or anything under `App.suspend()`. The existing `ng_data_dir` repointing stays the only route to trust-stack state. |
| T-12.1-02 | Tampering | `omarchy_theme_dir` fixtures | mitigate | Fixtures write into `tmp_path` and repoint `OMARCHY_THEME_DIRS` by `monkeypatch.setattr`; nothing writes to `~/.local/state/omarchy/`. Asserted by the fixtures taking `tmp_path` and by no `setenv` of a theme path. |
| T-12.1-03 | Repudiation | the async idiom | mitigate | A bare `async def` is *reported as a failure, not an error* (Pitfall 9), so a silently-never-run visual control would look like an ordinary assertion failure. The canary test is the standing proof the idiom actually executes. |
| T-12.1-SC | Tampering | package installs | n/a | This phase installs **no** package. `textual==8.2.7` is already pinned in `ngtui/pyproject.toml`; `pytest` / `pytest-asyncio` are the project's existing ephemeral invocation. No slopcheck is required because no new package name enters the tree. |
</threat_model>
