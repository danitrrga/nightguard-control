## Decisions Made

- **`ThemeWatch` kept `path` and gained `paths`.** The plan says "`path` becomes `paths`".
  Two shipped tests pin `watch.path` by name (`test_theme.py:207` and
  `test_the_watch_follows_a_directory_move`), so the rename alone would have been two new
  reds for no behavioural gain. `paths` is the watched pair, `path` is the `colors.toml`
  element, both re-resolved per read. When a fixed path is given (tests), its `shell.toml`
  sibling is watched too — the two files always live in the same directory, which is
  precisely why omarchy can swap them atomically as one.
- **`focus` inherits the *resolved* `hover-cursor` values; `selected` and `pressed` do not
  inherit.** `_RUNG_PARENT` holds exactly the two links UI-SPEC §2.3 specifies. Giving
  `selected`/`pressed` a parent would flatten the ladder to one fill on any theme that pins
  only `normal` — which is 26 of 28 of them.
- **A rung's `*-border` falls back through four rungs before giving up:** Hyprland
  dereference (gradient rejected) → colour word → the parent rung's resolved border → the
  rung's own colour. `dos-moos` ships no `*-border` key at all, so this chain is load-bearing
  rather than defensive.
- **`_color_word()` accepts any palette key, not only `foreground`/`accent`/`urgent`.** The
  rule it implements is "not a hex, so look it up"; a word the palette does not declare
  returns `None` and the caller falls back, so the superset degrades identically to the
  three-word version and cannot resolve a non-colour (`mode = "dark"` fails the hex gate).
- **`[spacing]` is emitted in px with Quattro's own 25-token default table.** The px-to-cell
  conversion (UI-SPEC §4) is deliberately not here: cell size is a function of the terminal,
  not of the theme, and a parser that returned cells could not be unit-tested without one.
- **`$ng-border-style` is `hkey` at radius 0 and `round` above it.** §9.2 assigns `vkey` to
  sides and a control row's left spine specifically, so that one stays literal in `app.tcss`;
  the variable carries the *family* the radius selects, which is the thing that must not be
  hardcoded. `BORDER_STYLES` exports the permitted set for the test — `panel` and `tall` are
  excluded (banned and unused respectively).

## Issues Encountered

**`omarchy_style()` now shells out, and six existing tests call it zero-arg.** Each
`theme.omarchy_style()` in `test_theme_sync.py` spawns a `hyprctl` (~7 ms). The suite time
moved 3.31 s → 3.38 s, so it is not a problem today, but the shape is worth naming: a pure
parser became one with a subprocess in it. The mitigation the plan chose is the call-site
discipline (T-12.1-07: construction and *detected* theme change only, never per tick) rather
than a cache, and control 3b monkeypatches `hypr_rounding` so the pure test stays pure. If a
later plan calls `omarchy_style()` on a timer, that discipline is where it will break.

**The generated fixture collapses `$ng-popup-border` and `$ng-tip-border` onto the same
colour**, because neither of its `[hyprland]` keys resolves (one is a gradient, the other is
undefined). The live theme distinguishes them. A stylesheet test that asserts the confirm
card and the tooltip have *different* border colours would therefore pass on the live desktop
and fail on the fixture — worth knowing before writing one.

**`style_variables` emits `ng-border-*-w` widths, a name UI-SPEC §2.3 does not define.** The
spec routes width to "§8.4 reservation" without naming a variable, but control 3b has to be
able to observe the clamp. The name is parallel to the `-a` alpha suffix the spec does define.
If the stylesheet plan wants a different name, this is the place to change it — nothing reads
it yet.
