# Phase 12.1 Plan 09: The Control Audit Summary

**The audit found what an audit is for: a control that could not fail. The no-crypto scan
(PORT-03) — the guard behind the project's claim that the TUI never holds the HMAC key and
never computes an HMAC — had one `parent.parent` too many in its root path, resolved to a
directory that does not exist, and had been scanning zero files for its whole life. Armed
with `import hmac` in a widget, it stayed green.**

## The finding

`tests/test_port03_no_crypto.py` resolved its scan root as

```python
NGTUI_SRC = pathlib.Path(__file__).parent.parent / "ngtui" / "ngtui"
```

`__file__` is `<repo>/ngtui/tests/test_port03_no_crypto.py`, so `.parent.parent` is already
`<repo>/ngtui` and the expression lands on `<repo>/ngtui/ngtui/ngtui` — which does not exist.
`rglob` over a missing directory yields nothing, and all three tests iterated an empty
generator and asserted `[] == []`.

Measured:

```
resolved NGTUI_SRC : /home/danitrrga/dev/Projects/nightguard-control/ngtui/ngtui/ngtui
exists             : False
files it scans     : 0
the real package   : /home/danitrrga/dev/Projects/nightguard-control/ngtui/ngtui  (14 files)
```

Armed with `import hmac` at line 1 of `ngtui/widgets/status.py`:

```
...                                                                      [100%]
3 passed in 0.01s
```

The cause is mundane — the tests moved into `ngtui/tests/` after the path was written, a
sibling of the package rather than a sibling of the repo root. `test_no_fixed_hex.py` gets
the same walk right and says so in a comment ("Two dirname levels, one fewer than
`test_deploy_completeness.py`'s three, because that test reaches a sibling of the repo root
and this one reaches a sibling of its own parent"). Nothing noticed for the same reason a
vacuous scan is dangerous at all: **a scan that finds nothing looks exactly like a scan that
finds nothing wrong.**

### The fix, and why the path correction alone is not it

Corrected to `parent.parent / "ngtui"` — 0 files scanned becomes 14. Then re-pointed at
`ngtui/nosuch` to check the correction was sufficient:

```
3 passed in 0.01s
```

Still green. **The path fix alone leaves the same hole one typo away**, so the fix is three
parts: the correct path, a vacuity guard (the scan must reach at least one file), and a
wrong-tree guard naming five anchor modules (`__init__.py`, `app.py`, `backend.py`,
`theme.py`, `panel.py`) so a directory that has `.py` files but is not the package is loud
too. Same shape as the vacuity guards already in `test_no_fixed_hex.py` and
`test_dashboard_budget.py` — the idiom existed in this phase, it just had not been applied to
a test written two phases earlier.

### Five arms, all seen to fire

| Arm | Message |
|---|---|
| `import hmac` in `widgets/status.py` | `PORT-03 VIOLATION — ngtui source imports crypto module(s): ngtui/ngtui/widgets/status.py:1: import hmac` |
| `read_key()` in `widgets/controlrow.py` | `PORT-03 VIOLATION — ngtui source calls read_key(): ngtui/ngtui/widgets/controlrow.py:602: read_key() call` |
| `.hexdigest()` in `widgets/hero.py` | `PORT-03 VIOLATION — ngtui source calls crypto method(s): ngtui/ngtui/widgets/hero.py:623: .hexdigest() call` |

| pointed at `ngtui/tests/` (36 `.py` files) | `PORT-03 SCAN IS LOOKING AT THE WRONG TREE — …/ngtui/tests holds 36 .py file(s) but is missing ['__init__.py', 'app.py', 'backend.py', 'theme.py', 'panel.py']. That is not the ngtui package.` |

The first three arms name files **this phase created or rewrote** — `status.py`,
`controlrow.py`, `hero.py`. Every one of them was outside the guard's reach for the whole of
the phase.

**No violation exists.** The corrected scan is green on the shipped package against all 14
modules; the guard was blind, the thing it guards was never breached. That distinction is
worth stating precisely, because "the security test was broken" and "the security property
was broken" are very different sentences and only the first one is true here.

## The structural-token keystone (UIX-01) does not close

After eight plans it was still Pending, and it stays Pending. Not a tidying decision — a
measured one.

UIX-01's text names four structural sources: `[controls]` state fills and borders,
**`[spacing]`**, **`[font]`**, and Hyprland's `decoration:rounding`. Three are delivered and
proved (controls 2, 3, 4b, 4c). The fourth and fifth are not:

```

34 emitted, 24 consumed by app.tcss, 10 with no consumer:

The only reader of `[spacing]` and `[font]` in the tree is `panel.py` — the bar panel, out of
bounds by the scope fence and untouched. The two tokens are parsed and then dropped before
they reach the TUI.

Five of the ten unconsumed variables **structurally cannot** be consumed: Textual's box model
has no border-radius, and the reserved-border grid pins a column rather than setting a width.
Those are honest no-ops and plan 04 already recorded them. `[spacing]` and `[font]` are a
different thing — named in the requirement, with no path at all.

Reported as the phase's one incomplete requirement.

The contract said 3.01 s and a 4 s ceiling. It now measures **42.75 s**. That is not a
regression — it is what the phase bought. The contract was written against a suite holding no
Pilot test at all (plan 01's first finding), and the phase added twenty-two.

```

The top five cost 24 s of the 42.75 s and are all registry walks or ladder sweeps — press a
key and settle, sixteen or nine times over. That is the price of asserting against the
composed surface instead of a model of it, which is the decision this phase made repeatedly
and on purpose.

Budget revised to 45 s in `12.1-VALIDATION.md` with the reason recorded. **The sign-off box
is left unticked**, because the box says "under 4 s" and that is false. The sampling property
it protected — feedback inside a single task, so a regression is attributable to the change
that caused it — still holds, and the trust-path subset that must never be deferred runs in
1.60 s.
