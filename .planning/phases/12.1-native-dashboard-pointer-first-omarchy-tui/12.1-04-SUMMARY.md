### Control 2's recipe measures the wrong rung — measured, then corrected

The plan says "assert a `.ctl` row's resolved `styles.background.a == 0.42`". Written against
the first row, with the pipeline **fully working**:

```
E           AssertionError: assert 0.08 == 0.42
E            +  where 0.08 = round(0.08, 4)
E            +    where 0.08 = Color(169, 192, 191, a=0.08).a
```

`0.08` is `$ng-fill-cursor`. Textual focuses the first focusable widget when a screen mounts —
plan 01 recorded this as a harness contract (`app.focused.id == "r0"`) — so `rows[0]` is on

test picked the wrong row" is the expensive kind. The test now asserts the idle rung on
`rows[1]`, the cursor rung on `rows[0]`, and guards both with an explicit
`assert app.focused is rows[0]` so a harness change says so instead of silently moving which
rung is measured.

That second assertion is not decoration: one rung alone cannot distinguish "the ladder is
wired" from "every row paints the same fill".

### Every statement of the sequence armed separately

Plan 03's lesson was that a value defended at two layers stays green when either layer is
removed. The same question asked of a four-statement sequence:

| Statement dropped | Measured |

| `self._style = omarchy_style()` | `border=False fill=False accent=True` — the structural half goes stale while the palette still moves. **This is the colour-only failure the whole control exists for**, and it is caught by the border assertion. |

**`InvalidThemeError` is not in `_apply_omarchy_theme`'s four-exception tuple**, so it

the "cosmetic failure" posture does not cover it.

Statement 3 (`self.theme = "omarchy"`) is a no-op after the first call by design. What the
table shows is that it is *not* a no-op on the first one: it is what makes a missing
`register_theme` loud instead of silent.

## Decisions Made

- **The style-family seam is `hypr_rounding()`, not `shell.toml`.** The plan's control-3
  recipe says to move `[controls] normal-border` "to a different border style". That token is
  a **colour**: `omarchy_style` resolves it through `_resolve_border` / `_color_word`, and no
  `*-border-style` key is read anywhere in `theme.py`. The only style-family variable is
  `$ng-border-style`, which comes from `corner_radius` ← `hypr_rounding()`. Following the
  recipe literally would have produced a test that moved a colour while claiming to assert a
  style — the precise failure the control was written to prevent.
- **Control 3 observes the family on a mounted `.panel`.** The probe screen composes only
  `.ctl` rows, and a `.ctl` row's spine is a literal `vkey` **by design**: D-05 reserves the
  same one-column border in every state, so its style must never move. The test mounts a
  `Static(classes="panel")` — a real shipped rule that consumes `$ng-border-style` — rather
  than assert on a widget that is contractually forbidden to change.
- **A selected row's reserved spine is painted in its own fill.** `selected-border-width` is
  `0` ("fill only") but D-05 forbids giving the column back. Painting it at
  `$ng-border-selected` / 100 % would make *selected* the loudest border on the ladder, above
  the cursor — the opposite of the kit's priority. Painting it in the row's own fill keeps
  the column reserved and reads as absent.
- **`#countdown` keeps `$primary`.** This plan's accounting lists it as one of the two
  permitted reserve uses. §6.2's narrower rule — accent *only when the verdict is GRACE* —
  needs the countdown to follow the verdict role class, which is a composition change and
  belongs to the plan that rebuilds the hero. Flagged, not done here.
- **`.panel` and `#edit-fields` became hairline bands, not boxes.** Both lost `round` and
  both lost `$surface-lighten-1`: `$surface == $background` on 4 of the 28 installed themes,
  which is the measured reason this file fills with alpha-on-ink. They now read
  `border: $ng-border-style $foreground 12%` — the family from the token, the ink from the
  keyline channel.
- **`.dim` moved from `$text-muted` to `$foreground 70%`**, joining the caption channel §5
  defines. `$text-muted` is a Textual-derived role with no relationship to the desktop theme's
  two darkenings.
- **The degradation rules landed without their handler.** `#frame.-compact` / `-tiny` /
  `-narrow` target widgets that do not exist yet. The rules are inert until the composition
  and the `on_resize` handler arrive, and writing them now is what keeps `app.tcss` from
  being reopened once per widget.

## Issues Encountered

**Five emitted variables can never be read from CSS.** The `ng-border-*-w` widths express a
reservation that a character grid states structurally ("always one column, every state")
rather than numerically. They exist so plan 03's clamp is observable to a test. No plan in
this phase can consume them. If the phase ends with them still unread, dropping them is
cheaper than maintaining five variables whose only caller is their own test.

**`omarchy_style()` is now on the app's construction path**, so every `NightguardApp()` spawns
a `hyprctl` (~7 ms). That is the call-site discipline plan 03 chose over a cache, and it is
holding: construction and *detected* theme change only, never per tick. The gate is
`if self._theme_watch.changed():` at `app.py:162` and the acceptance criteria assert one
`refresh_css` call site — both are standing guards on T-12.1-12.

**The confirm dialog is still unvisited by any test in this phase.** Plan 08's accent-cell
count composes the status screen; `ConfirmScreen` is a modal that is never pushed. This plan
fixed two breaches there by grep. A fifth could be added tomorrow and only the whole-file
scan would catch it — which is why that criterion is a scan and not a list.
