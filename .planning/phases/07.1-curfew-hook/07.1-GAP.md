## The gap (one line)
The curfew **verdict engine works**, but **nothing fires it** on Linux, so curfew does not actually block Claude Code sessions.

## Evidence (verified live)
- At 22:54 (curfew is 20:45–05:30), `guard.py` returns:
  `{"decision":"deny","reason":"curfew","grace_remaining_secs":0,...}` exit **1**. The engine is correct.
- `~/.claude/hooks` has **no** nightguard hook; nothing references `guard.py`. So no Claude Code event runs the guard. (Matches the migration memory "LifeOS hooks not wired on Linux — .ps1 hooks untranslated".)
- On Windows this was done by `LifeOS/.agents/hooks/nightguard_adapter.ps1` (9.5 KB), which translated the guard verdict into the Claude Code hook contract. That adapter was never ported to Linux.

- **Canonical config:** read the LifeOS canonical config (`NIGHTGUARD_DIR=/home/danitrrga/dev/Projects/LifeOS/nightguard`), no `~/.claude` drift (mirror WIRE-01).
- **Grace:** outside curfew AND during an active daily grace window → allow. `guard.py` already handles grace (reads `guard.json.grace`, which is user-readable 0644).
- **Shared agent-config caveat:** `~/.claude/hooks` + settings are **regenerated by the LifeOS shared agent-config system on every SessionStart** (see `.claude/AGENT-SYSTEM.md`). Do NOT hand-edit the generated files — wire the hook in LifeOS `config/` and run the generator, or it will be overwritten.
