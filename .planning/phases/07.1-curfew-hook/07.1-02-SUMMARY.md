**Built `LifeOS/hooks/nightguard_adapter.py` — the Linux curfew adapter that translates a `guard.py` `deny` verdict (exit 1) into a Claude Code hard-block (exit 2 + Spanish-butler stderr), honors a leading-token slash-command allowlist, and fails closed on every error branch — and signed `/plan` into `config.yaml curfew.allow_commands` via the root control-CLI (verify all-green).**

## Accomplishments

- Ported `nightguard_adapter.ps1` 1:1 to stdlib-only Python (`json/os/sys/subprocess`), reusing `ngcommon.yaml_load` (single Python stack — no second YAML parser).
- Implemented the load-bearing exit-code translation invariant (D-07/T-071-04): guard `exit 1` -> adapter `exit 2`; **no** `sys.exit(guard_exit)` and **no** `sys.exit(1)` path anywhere (verified by grep gate).
- Implemented the leading-token allowlist (07.1-MATCHER-DECISION.md): `prompt.split()[0] in curfew.allow_commands`, checked BEFORE invoking the guard; free-form args ride along (D-12). This is tighter than the Windows substring match — a prompt merely *containing* `/shutdown` mid-text is now blocked.
- Fail-closed on every branch: missing config / guard crash-or-hang / non-{0,1} exit / unparseable verdict / any uncaught exception -> exit 2 (offline_message, or hardcoded FAIL_CLOSED if config unreadable).
- UTF-8 stderr so the ñ butler text renders; soft mode (the adapter never reads the signing key — T-071-08).
- Signed `/plan` into `config.yaml curfew.allow_commands` via `sudo nightguard_ctl.py commit` (root key, fingerprint-authed) — now live AND signed (watchdog-stable).

## Deviations from Plan

### 1. [Plan assumption wrong] Adding `/plan` to `allow_commands` is a LOOSEN (cost 1 token), not free

- **Found during:** Checkpoint (the human-action sudo commit).
- **Plan expectation:** The plan (and 07.1-PATTERNS.md line 202) asserted `curfew.allow_commands` is registered `list_add` -> tighten/neutral -> `costs_token=False`, so adding `/plan` would be FREE.
- **Actual:** The root signer classified the change as a **loosen and charged 1 weekly token** (now `tokens 1/3 used`). The commit output reads `committed (loosen -1 token)`.
- **Why this is correct (NOT a bug):** Adding an entry to `allow_commands` **widens the curfew escape valve** — more prompts can now bypass curfew. That is a genuine *loosening* of the curfew, so the classifier rightly treats it as a loosen and spends a token. The plan's "free/no-token" expectation was wrong for this specific list.
- **Impact for downstream:** A weekly token was legitimately spent (1/3 used this week). Plan 03 and the phase verifier should NOT treat the token spend as an anomaly. The classifier treats `allow_commands` additions as loosens — note this for any future allowlist edits.
- **No code change required** — the signed commit succeeded and `verify` is all-green; this is a documentation correction only.
