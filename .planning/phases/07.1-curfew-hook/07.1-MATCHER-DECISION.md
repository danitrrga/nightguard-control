# Phase 07.1 — UserPromptSubmit Matcher Decision (resolves RESEARCH Q1)

**Decided:** 2026-06-23
**Resolves:** RESEARCH Open Question Q1 (the phase's top integration risk) — what the Claude Code
`UserPromptSubmit` hook's stdin `prompt` field exposes for skill-backed slash commands on this
runtime (Claude Code 2.1.186).
**Method:** live one-shot probe (`scratchpad/probe_ups.py` wired into `~/.claude/settings.json`
`UserPromptSubmit`, fired from an interactive session in the LifeOS dir where `/plan` and
`/shutdown` resolve; probe captured raw stdin then exited 0 — pure instrumentation).

MATCHER: leading-token

## Captured PROMPT_FIELD values (verbatim)

| # | Submitted prompt | PROMPT_FIELD captured | Form |
|---|------------------|-----------------------|------|
| 1 | `/plan test` | `/plan test` | raw leading token |
| 2 | `/plan test(dont plan anything)` | `/plan test(dont plan anything)` | raw leading token (free-form args ride along) |
| 3 | `/shutdown` | `/shutdown` | raw leading token |
| 4 (control) | `hello world` | `hello world` | plain (non-slash) |

## Verdict

**raw-token.** The `UserPromptSubmit` hook fires **before** slash-command expansion — the `prompt`
field carries the user's raw submitted text, **not** an expanded
`<command-name>/plan</command-name>…` blob. The transcript evidence that earlier suggested an
expanded form (RESEARCH Q1) was the post-expansion record, which differs from the hook's stdin
payload at submit time.

All three escape-valve captures expose the raw `/plan` / `/shutdown` token as the **first
whitespace-delimited token** (`prompt.split()[0]` equals the command). D-12's free-form parameters
(capture #2) ride along after the leading token, as required.

## Decision rule applied (RESEARCH Q1 / Plan 07.1-01)

> Choose `leading-token` ONLY if all three captures show the raw `/plan`/`/shutdown` token as the
> first whitespace-delimited token; otherwise choose `substring` (the fail-safe).

All three captures satisfy the leading-token condition → **MATCHER: leading-token**.

## Rationale

Leading-token is **tighter than substring** and is the safer matcher here: it honors D-11's
"exact slash-command allowlist matched on the leading token" without the substring-match loosening
hole, where any prompt merely *containing* `/plan` or `/shutdown` anywhere in its text would bypass
curfew. Because the probe proves the raw leading token is exposed, the fail-safe substring fallback
is unnecessary — Plan 02 can use the tighter `prompt.split()[0] in allow_commands` check.

## Consumed by

`07.1-02-PLAN.md` adapter allowlist task — read the `MATCHER:` line above. Plan 02 implements the
allowlist as a **leading-token** check (`prompt.strip().split()[0]` membership in
`config.yaml curfew.allow_commands`), with free-form arguments passing through (D-12).
