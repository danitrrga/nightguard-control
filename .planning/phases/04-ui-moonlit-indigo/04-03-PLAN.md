<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| webview (TS) → commands (IPC) | Untrusted YAML strings + command invocations cross into the signer/writer host |
| guard.json / config.yaml on disk (possibly tampered) → get_state | Signed artifacts read and re-verified before any display derivation |
| commands → mutation-engine ordered writer | The only sanctioned write path to the data dir |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-08 | Spoofing | get_state trusts a tampered guard.json (UI looks less-locked than guard) | mitigate | Re-verify state_hmac via compute_state_hmac; on mismatch worst-case weekly_spent=3 / tokens_remaining=0 / grace_available_today=false / maximal_lockout (guard 217-222 parity), applied in the single build_state_dto helper. |
| T-04-09 | Tampering | config.yaml hand-edited but get_state shows it as valid | mitigate | Re-verify config_hmac with constant-time verify_bytes over canonicalize_bytes; config_verified=false → maximal_lockout, never optimistic. |
| T-04-10 | Information Disclosure | timing side-channel on tag compare | mitigate | verify_bytes (subtle-backed constant-time) for the config tag; `==` on tags forbidden (CLAUDE.md). |
| T-04-11 | Elevation of Privilege | commit_change bypasses the quota via a bespoke write | mitigate | Re-check `decision.allowed` in-command (defense in depth, commit.rs:148 parity) AND write only via commit::commit_change (RULE-06 ordered, fd-locked, circuit-breaker-safe). No hand-rolled writer. |
| T-04-12 | Tampering | sign-vs-write race with a guard fire mid-commit | mitigate | Use the engine's `with_commit_lock`-wrapped commit_change / use_grace (sanctioned→guard.json→live order); never write config.yaml first (GARD-05). |
| T-04-13 | Spoofing | grace granted/displayed without true time | mitigate | use_grace uses SntpTrueTime (fail-closed NtpUnreachable); commit_change ledger timestamp also requires true time, fail-closed. App-side display time stays advisory (time_unverified=true). |
