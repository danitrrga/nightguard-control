<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| webview (TS) → Rust host (IPC) | Untrusted UI input (YAML strings, command calls) crosses into the signer/writer host |
| Rust host → filesystem (data dir) | The host reads/writes the signed artifacts the guard also reads |
| DPAPI key at rest (.guardkey) | The 32-byte signing key is loaded into host memory |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Information Disclosure | DPAPI key load in AppCtx | mitigate | Key stays in Rust host memory only; never serialized into any DTO and never crosses the invoke boundary (D-02). AppCtx is `.manage()`d, not returned to JS. |
| T-04-02 | Elevation of Privilege | DPAPI scope drift | mitigate | AppCtx::load uses `trust_kernel::key::load_or_create_key` (Scope::User, None entropy) — the single existing key path; no second key path is added (Pitfall 4). |
| T-04-03 | Spoofing | get_state returns optimistic placeholder | accept (this plan only) | Placeholder DTO ships ONLY in this scaffold plan; plan 03 replaces it with the re-verified read path before any UI asserts lock state. Tracked as a blocking dependency (plan 03 must land before release). |
| T-04-04 | Elevation of Privilege | over-broad fs:scope `**` capability | mitigate (deferred to plan 03) | Capability ships broad here with a TODO; plan 03 tightens fs:scope to the resolved data dir (Pitfall 5 / least privilege). |
| T-04-SC | Tampering | npm/cargo installs (tauri, plugin-fs, @tauri-apps/*) | mitigate | All six packages slopcheck-clean and Approved in RESEARCH Package Legitimacy Audit (official tauri-apps org). No [ASSUMED]/[SUS]/[SLOP] packages → no per-install human checkpoint required. |
</threat_model>
