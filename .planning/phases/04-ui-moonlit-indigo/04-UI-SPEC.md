# Phase 4 — UI Design Contract

> Visual and interaction contract for the Moonlit Indigo UI. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Scope:** A single-screen Tauri v2 (vanilla-TS + Vite) desktop app — the non-authoritative
> display + edit-intent layer. The app is a *reader*; the PowerShell guard is the enforcer.
> Direction is **minimalist, typographic, whitespace-led** (CONTEXT D-11/D-12) — the countdown
> is the hero; everything else recedes. No card soup, no usage-tracker chrome.

## Spacing Scale

8-point scale (all multiples of 4). Whitespace is the primary structural device in this phase
(D-11), so spacing tokens carry more layout weight than borders or containers.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps, inline meter-dot gaps |
| sm | 8px | Compact stacking (label above value), token-dot spacing |
| md | 16px | Default element spacing, edit-field vertical rhythm |
| lg | 24px | Group separation, left-rail item spacing |
| xl | 32px | Section breaks (status block ↔ edit panel) |
| 2xl | 48px | Vertical breathing room around the hero countdown |
| 3xl | 64px | Top/bottom page padding around the centered countdown |

**Exceptions:**
- Left icon-rail width: **56px** fixed (multiple of 4; holds a 24px icon + 16px padding each side).
- Minimum interactive hit target: **40px** height for the "+8 minutes" button and Commit button
  (touch/click affordance; multiple of 4).

## Typography

Roboto only. Exactly **4 sizes**, exactly **2 weights** (400 regular, 500 medium). Type hierarchy —
not boxes — does the structural work (D-11). The countdown is the single Display-tier element.

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Display | 64px | 500 | 1.1 | The hero countdown timer (the only Display element on screen) |
| Heading | 20px | 500 | 1.2 | Lock-status word (LOCKED / OPEN), edit-panel section label |
| Body | 16px | 400 | 1.5 | Field labels, values, reasons, inline feedback, button text |
| Label | 14px | 400 | 1.4 | Captions: next-reset, "today's grace", "time unverified" caveat, dim metadata |

**Tabular numerals:** the countdown and any numeric value (`weekly_spent`, minutes) use
`font-variant-numeric: tabular-nums` so digits do not jitter on the 1-second tick (D-05).

**Notes:**
- No weight above 500 — keeps the surface calm (D-11). Emphasis comes from size + color, not heaviness.
- Letter-spacing on the Display countdown may be set to `0.01em` for legibility at 64px; no other
  tracking adjustments.

## Color

Moonlit Indigo palette, locked in CLAUDE.md (UI-05). Mapped to the 60/30/10 discipline below.
The palette is dark-first; "dominant" is the deep background, "secondary" is the raised surface
used **sparingly** (no card soup — surfaces appear only where a true grouping needs separation,
e.g. the edit panel), and accent is reserved tightly.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#0c0e14` (`--bg`) | App background — the dominant field the countdown floats on |
| Secondary (30%) | `#161a24` (`--surface`) | The single edit-panel surface + left-rail backing; used minimally |
| Border (hairline) | `#242a38` (`--border`) | Hairline dividers between groups (replaces cards, per D-11) |
| Text (primary) | `#e8eaf0` (`--text`) | Countdown, status word, field values |
| Text (dim) | `#8b91a3` (`--dim`) | Labels, captions, inactive token dots, "time unverified" caveat |
| Accent (10%) | `#7aa2ff` (`--accent`) | See reserved list below |
| Destructive / warning | `#f0a35e` (warm amber, derived) | Loosen warning + token-cost text + disabled-commit reason |

**Accent (`#7aa2ff`) reserved for — explicit list (never "all interactive elements"):**
1. The **filled token dots** in the 3-dot weekly meter (remaining tokens).
2. The **"+8 minutes" button** fill when it is *enabled* (active lock + grace available).
3. **Tighten** per-field feedback (the quiet-accent confirmation that a change is safe/free).
4. The **active** state of the selected left-rail icon (status vs edit).

Accent is NOT used for: body text, the countdown (that is `--text`), dividers, plain field
borders, or disabled buttons.

**Destructive/warning (`#f0a35e`) reserved for — explicit list:**
1. **Loosen** per-field feedback (warning + "costs 1 token").
2. The **inline reason** when commit is disabled at 0 tokens.
3. The grace-unavailable / fail-closed caveat text.

This is a **warning** color (loosening weakens the user's own binding), not a delete affordance —
there are no destructive data operations in this phase. The single confirm step (D-08) is on
*loosening commits*, styled with this warm tone, not red.

**Rationale for the amber second semantic:** The template's "Destructive" slot is repurposed as
"loosen-warning" because this product has no delete/destroy actions; the only consequential,
caution-worthy action is *self-loosening*, which the spec treats as the thing to slow down
(REQUIREMENTS core value). Amber over red keeps the Beeminder-style non-punitive tone (v2
GRACE-02 direction) while still reading as "this costs you."

## Copywriting Contract

All copy reflects **hook-enforced reality** (D-03) — never app-local optimism. State vocabulary
mirrors the guard verdict (`scripts/guard/nightguard_guard.ps1`: decision / reason / grace /
reverted / fail_closed). Tone: calm, honest, non-punitive (no "denied"; use "available again
Monday" framing — REQUIREMENTS RULE-04, v2 GRACE-02).

| Element | Copy |
|---------|------|
| Primary CTA (edit panel) | **Commit changes** (loosen variant button label: **Commit (spends 1 token)**) |
| Secondary CTA (grace) | **+8 minutes** (UI-03; enabled only during active lock + grace available, per D-10) |
| Lock status — locked | `🌙 LOCKED` (Heading), with hero countdown to curfew-window end |
| Lock status — open | `OPEN`, with caption "next lock at {time}" |
| Lock status — grace active | `🌙 LOCKED · grace`, hero countdown to grace-window end |
| Empty state heading | **No signed config yet** |
| Empty state body | "Nightguard hasn't been initialized on this machine. Run the app's setup to generate your signing key and first sanctioned config." (no data dir / no `guard.json` found) |
| Error state — verify failed | **State unverified** — "The signed state failed HMAC verification. The guard is treating you as fully locked until the app re-syncs. Open the edit panel to re-sign." (maps to fail-closed / maximal-lockout) |
| Error state — time unverified | **Time unverified** (Label, dim) — "Can't confirm true time right now; the countdown is advisory. The guard re-checks with its own clock." (D-04) |
| Disabled-commit reason (0 tokens) | "Out of weekly tokens — available again Monday." (inline, amber; RULE-04 locked substring) |
| Loosen field feedback | "Loosens curfew · costs 1 token" (amber, per-field, live/debounced — D-07) |
| Tighten field feedback | "Tightens curfew · free" (accent, per-field) |
| No-op field feedback | (no badge; field reads as unchanged — `noop` is silent) |
| Loosen confirm (D-08) | Title: **Spend a weekly token?** Body: "This loosens your curfew and uses 1 of your 3 weekly tokens." Confirm: **Spend token & commit** · Cancel: **Keep current** |
| Token meter caption | "{n} of 3 tokens · resets Monday {date}" |
| Grace caption | enabled: "+8 available today" · used: "+8 used today" · unavailable: "+8 unavailable (not locked)" |

**Destructive / consequential actions in this phase:**
- **Loosening commit** — the only consequential action. Confirmation: single explicit confirm
  dialog (D-08), amber-toned, naming the token cost. Tightening commits proceed without confirm.
- No delete, no reset, no "master-off" (the latter is explicitly out of scope per REQUIREMENTS).

**State-truth invariant (for the executor):** Every label that asserts lock state, token count,
or grace availability is derived from a freshly re-verified `get_state` (D-03), and re-fetched
after any `commit_change` / `use_grace` (D-09). The 1-second tick (D-05) only re-renders the
countdown digits — it never invents a state transition the verified data hasn't confirmed.

## Layout Contract (phase-specific, D-11/D-12)

> Captured here because the minimalist direction supersedes CLAUDE.md's "flat-card" hint for this
> phase and the executor needs the structure to be unambiguous.

- **Shell:** sparse **left icon-rail (56px)** with two items only — *Status* and *Edit* — backed
  by `--surface`; the rest of the window is `--bg`.
- **Status view (default):** vertically centered. **Hero countdown (Display/64px)** is the visual
  center; above it the `🌙 LOCKED / OPEN` status word (Heading); below it the **3-dot token meter**
  + grace caption (Label). Generous 2xl/3xl vertical whitespace. **No cards** — groups separated by
  whitespace, with at most a single hairline `--border` divider above the token meter.
- **Edit view:** a single `--surface` panel (the one sanctioned place a container is justified)
  holding per-field inputs with live tighten/loosen badges and the Commit button. One surface, not
  many cards.
- **Hierarchy:** countdown > status word > token meter > captions. Nothing competes with the countdown.
