<objective>
Wire the instant post-commit bar refresh (BAR-04 / D-11). In
`ngtui/ngtui/backend.py` `commit()`, after the sudo commit subprocess returns and
ONLY when `returncode == 0`, best-effort fire `pkill -RTMIN+11 waybar`. The
`custom/nightguard` module (Plan 04) declares the matching `"signal": 11`. The
signal is fire-and-forget: gated strictly on success, its errors fully swallowed,
never perturbing the commit result or exit code. TDD — the failing test lands
first.

Purpose: the bar reflects a token spend the instant it happens, not on the next
30s poll — without the signal ever faking or corrupting the commit outcome.
Output: a tested, success-only, non-perturbing signal push.
</objective>

From ngtui/ngtui/backend.py — the seam this plan edits:
```python
def commit(proposed_text: str) -> dict:
    ...
    proc = subprocess.run(["sudo","/usr/bin/python3",CTL_SCRIPT,"commit","--from",tmp],
                          stdout=subprocess.PIPE, text=True)
    return {"returncode": proc.returncode, "stdout": (proc.stdout or "").strip()}
```
`subprocess.run` is the mock seam. The signal push must run AFTER `proc` returns
and BEFORE (or after) building the result dict, gated on `proc.returncode == 0`,
inside its own try/except that swallows everything. stderr on the sudo call stays
UNCAPTURED (TTY prompt) — do not touch that.

Existing test idiom (ngtui/tests/test_port02_commit_argv.py) monkeypatches:
`patch("ngtui.backend.subprocess.run", side_effect=fake_run)` where `fake_run`
captures argv. NOTE: with the signal added there are now TWO `subprocess.run`
calls per commit — the mock must branch on `argv[0]` (`"sudo"` = commit,
`"pkill"` = signal).
