<task type="checkpoint:human-verify" gate="blocking-human">
  <name>Task 1: Install the global shim + confirm clean-env resolution and SC-5 readability</name>
  <what-built>
    Plans 01-02 added the key-less `ngtui status --json` subcommand and the TTY-guarded
    router. The `pyproject.toml` already declares `[project.scripts] ngtui = "ngtui.__main__:main"`,
    so `uv tool install` produces a real PATH shim with the new subcommand. This checkpoint
    installs that shim and verifies the packaging-level Success Criteria that can't run in pytest.
  </what-built>
  <action>Manual checkpoint — execute the numbered steps in <how-to-verify> and report results. No code change; this validates the install/PTY boundary (SC-1/SC-3/SC-5) on the live box.</action>
  <how-to-verify>
    1. Install the global command from the project wheel:
       `cd ngtui && uv tool install --python 3.14 .`
       → expect "Installed 1 executable: ngtui"; shim at `~/.local/bin/ngtui`.
    2. Confirm it is on the bare login PATH (SC-1): `bash -lc 'command -v ngtui'` AND
       `fish -lc 'command -v ngtui'` both print `~/.local/bin/ngtui`.
    3. Clean-env status (SC-1 + DESK-02/SC-3): run
       `env -i HOME=$HOME PATH=$HOME/.local/bin:/usr/bin:/bin ngtui status --json`
       → expect a SINGLE-LINE object like `{"text":...,"tooltip":...,"class":"outside_curfew"}`;
       pipe through `| jq -e .` to confirm it is valid JSON (jq exits 0). The `class` must be a
       real verdict (locked/outside_curfew/grace_active/...), NOT `unavailable` (the stack resolves).
    4. Fail-closed sanity (SC-3): run
       `env -i HOME=$HOME PATH=$HOME/.local/bin:/usr/bin:/bin NIGHTGUARD_STACK_DIR=/nonexistent ngtui status --json | jq -e .`
       → expect exactly `{"text":"○ —","class":"unavailable"}`, exit 0.
    5. SC-5 readability flag — confirm the artifacts the status path reads are user-readable
       and the key is NOT: `ls -la "$NIGHTGUARD_DIR"` (or the resolved LifeOS nightguard dir)
       → `guard.json` and `config.sanctioned.yaml` show `root:root` `0644` (you can `cat` them);
       `.guardkey` shows `root:root` `0600` (cat is Permission denied). This is SC-5 GREEN.
    6. TTY guard (SC-4 part 1): `ngtui < /dev/null` → expect a LOUD non-zero failure with a
       "must be run in a terminal" message, NOT a screen of escape codes.
  </how-to-verify>
  <resume-signal>Type "approved" once steps 1-6 pass, or paste the failing output.</resume-signal>
</task>
