<objective>
Build the Rust half of the cryptographic kernel: HMAC-SHA256 sign/verify over raw file bytes, and a DPAPI-backed 32-byte key store. This is the Rust side of the interop contract; Plan 03 proves PowerShell agrees byte-for-byte.

Two locked invariants drive every choice here:
1. HMAC is computed over RAW FILE BYTES, and the key is the 32 RAW key bytes (never its hex/base64 string). Tamper detection must fire on a one-byte change AND on CRLF/BOM/trailing-newline drift — proving we sign exactly what's on disk.
2. The key is stored as a raw `CryptProtectData` blob, CurrentUser scope, with NO optional entropy (None on both sides). Never PowerShell SecureString framing. The dead giveaway of getting this wrong is a "decrypted key" that is 64 bytes (UTF-16 of a 32-char hex string) instead of 32 raw bytes — a test explicitly guards against that.

Purpose: KERN-01 (HMAC) and KERN-02 (DPAPI key) are the two halves of the trust kernel. Getting the byte forms exactly right on the Rust side is the precondition for the cross-language exit gate in Plan 03.
Output: `hmac`, `dpapi`, and `key` modules in the trust-kernel crate, each unit-tested on the Rust side (cross-language proof is Plan 03).
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| hand-editor ↔ HMAC | An untrusted hand-edit of config.yaml crosses here; only a valid HMAC (requiring the DPAPI key) is trusted |
| other user / offline disk ↔ key at rest | DPAPI CurrentUser protects the key from other users and offline disk theft |
| Rust ↔ PowerShell key format | The raw-blob vs SecureString framing boundary (proven in Plan 03) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-05 | Spoofing | forged HMAC tag | mitigate | HMAC-SHA256 over raw bytes with a DPAPI-protected key; a hand-editor lacks the key to forge a valid tag |
| T-01-06 | Tampering | EOL/BOM-laundered edit slips past verify | mitigate | Sign exactly the bytes on disk; tests prove raw-CRLF/BOM/trailing-newline edits fail verification |
| T-01-07 | Information Disclosure | key readable by other users / on stolen disk | mitigate | DPAPI CurrentUser scope (NOT LocalMachine); key never written in plaintext |
| T-01-08 | Tampering | SecureString framing breaks interop silently | mitigate | Raw CryptProtectData blob, no entropy; explicit 32-not-64 length assertion is the canary |
