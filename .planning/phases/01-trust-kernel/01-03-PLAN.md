<objective>
Prove the PHASE EXIT GATE: the DPAPI + HMAC trust kernel works byte-identically across Rust and PowerShell. This is the single genuine technical risk of the whole project (STATE.md blocker for Phase 1). PowerShell protects a key and signs an input; Rust unprotects to identical 32 bytes and verifies the tag — and the reverse — byte-identical both directions.

Locked invariants this gate enforces end-to-end:
- DPAPI: raw `CryptProtectData` blob, CurrentUser scope, NO optional entropy ($null both sides). PowerShell uses `[System.Security.Cryptography.ProtectedData]::Protect/Unprotect` — NEVER `ConvertTo/From-SecureString` (the SecureString trap; tell-tale = 64 bytes back).
- HMAC: over RAW FILE BYTES read with `[System.IO.File]::ReadAllBytes(...)` (NEVER `Get-Content`). Key = 32 RAW bytes (never its hex/base64 string). Tags compared as lowercase hex.

Purpose: KERN-01 and KERN-02 are only truly satisfied when both languages agree on the same key and the same tag. Plan 02 proved the Rust half; this plan proves cross-language equivalence and closes the Phase 1 exit gate.
Output: A Rust `interop_cli` binary + a PowerShell harness that runs the full both-direction round-trip and tamper assertions, exiting non-zero on any divergence; plus a human-verified run on real Windows DPAPI.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Rust ↔ PowerShell (DPAPI blob) | The two languages must read each other's raw CryptProtectData blob; SecureString framing breaks this silently |
| Rust ↔ PowerShell (HMAC bytes) | Both must hash the identical raw file bytes; Get-Content or re-serialization breaks parity |
| editor/Git ↔ signed file | EOL/BOM rewrites by an editor or Git autocrlf must be caught as tamper, not silently accepted |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-10 | Tampering | cross-language key format divergence | mitigate | Gate asserts PS [ProtectedData] blob ↔ Rust dpapi round-trips to exactly 32 bytes (64-byte canary fails loud) |
| T-01-11 | Tampering | HMAC input canonicalization drift | mitigate | Gate asserts Rust and PS tags match over ReadAllBytes; CRLF/BOM mutated copies must read as tampered both sides |
| T-01-12 | Spoofing | a hand-edit producing a matching tag | mitigate | Tamper checks prove cosmetic EOL/BOM edits diverge the tag; only the keyed signer reproduces it |
| T-01-13 | Repudiation/Honesty | gate implying the system is unbreakable | accept | README states the honest ceiling (DPAPI ≠ protection against the user themselves); gate proves interop, not invulnerability; no obfuscation added |
| T-01-SC | Tampering | PowerShell only uses framework crypto APIs | mitigate | No third-party PS modules installed; only .NET [ProtectedData]/[HMACSHA256]; Rust deps already audited in Plan 02 |
</threat_model>
