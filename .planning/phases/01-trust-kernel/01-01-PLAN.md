<objective>
Scaffold the Nightguard trust-kernel as a plain Rust library crate (NOT a Tauri app — Tauri arrives in Phase 4) and implement the two foundations every later crypto guarantee rests on: deterministic byte canonicalization and crash-safe atomic file writes.

The HMAC input form for this whole project is locked to RAW FILE BYTES (not a canonical-JSON projection): the Rust app is the sole deterministic writer, so any hand-edit is precisely what we want the guard to trip on. For that to hold, the writer MUST emit one and only one byte form: UTF-8, no BOM, LF line endings, exactly one trailing newline. This plan builds that writer and proves it is deterministic and crash-safe, before any HMAC code touches it.

Purpose: Without a deterministic writer and atomic store, the HMAC layer (Plan 02) and the cross-language interop gate (Plan 03) cannot produce byte-identical results, and an interrupted write could corrupt the very config the guard reverts to.
Output: A buildable Cargo workspace with a `trust-kernel` library crate exposing `canon` and `store` modules, fully unit-tested.
</objective>

This crate is `trust-kernel`, a plain Rust library (lib crate), a member of the root
workspace. It is NOT a Tauri crate and pulls in NO Tauri dependency. The Phase 4 Tauri
app will later depend on this crate and call its public API.

Public API to expose from `crates/trust-kernel/src/lib.rs`:

```rust
pub mod canon;
pub mod store;

// canon.rs
/// Normalize arbitrary input into the one canonical byte form the whole
/// project signs over: UTF-8, no BOM, LF-only line endings, exactly one
/// trailing newline. Idempotent: canonicalize(canonicalize(x)) == canonicalize(x).
pub fn canonicalize_bytes(input: &[u8]) -> Vec<u8>;

// store.rs
#[derive(Debug, thiserror::Error)]
pub enum StoreError { /* Io(std::io::Error), ... */ }

/// Write `bytes` to `path` atomically: write to a temp file in the SAME
/// directory, flush, then rename over the target. On any failure the prior
/// file at `path` is left fully intact. Used for config.yaml, config.sanctioned.yaml,
/// guard.json, and the .guardkey blob.
pub fn atomic_write(path: &std::path::Path, bytes: &[u8]) -> Result<(), StoreError>;

/// Convenience: canonicalize text content then atomic_write it. Used for the
/// human-readable YAML artifacts so they always hit disk in canonical byte form.
pub fn write_canonical_text(path: &std::path::Path, content: &str) -> Result<(), StoreError>;
```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| disk ↔ kernel | The library reads/writes config and key files on local disk; an interrupted write or a hand-edit crosses here |
| process crash ↔ file integrity | A crash mid-write must not corrupt the revert target |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Tampering | config.yaml byte form | mitigate | Canonicalize to one byte form (UTF-8/no-BOM/LF/one-trailing) so any hand-edit is detectable later by HMAC; `.gitattributes -text` stops Git autocrlf from rewriting bytes |
| T-01-02 | Denial of Service | atomic_write interrupted | mitigate | temp-then-rename in same dir; prior file left intact on failure; unit-tested |
| T-01-03 | Tampering | supply chain (cargo) | mitigate | Only `thiserror` added this plan; no crypto/DPAPI deps yet; pins verified against STACK.md "What NOT to use" |
| T-01-04 | Information Disclosure | runtime secret files committed to git | mitigate | `.gitignore` excludes `*.guardkey`, `guard.json`, `config*.yaml`, `tamper.log` |
