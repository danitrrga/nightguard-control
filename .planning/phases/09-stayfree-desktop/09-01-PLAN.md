<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| AUR maintainer + upstream GitHub → local `/usr/bin/stayfree` | A closed-source prebuilt AppImage crosses into the user session with X11/accessibility + libsecret access. |
| StayFree (user session) → nightguard trust kernel | MUST be a hard wall: StayFree never receives `.guardkey`, signing, or config-write authority. |
| Late-night user → the spike decision | The adversary benefits from a falsely-recorded PASS that builds a keep-alive around a non-blocking tracker (false sense of enforcement). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-SC | Tampering | AUR `stayfree-desktop` install (closed-source AppImage) | mitigate | Blocking human-verify checkpoint (Task 1) verifying AUR page + upstream release + pinned 3.4.0/sha256 before install; never auto-approvable. |
| T-09-01 | Elevation of Privilege | StayFree given any trust-kernel role | mitigate | Explicit invariant in objective + notes: StayFree gets NO `.guardkey`/signing/config-write role; it is an untrusted user-session app only. |
| T-09-02 | Repudiation / false-assurance | A recorded PASS that overstates blocking | mitigate | Verdict criteria are observable and decisive (Step-4 GUI blocking, repeatable); web-block PASS recorded separately so it cannot mask an app-block FAIL; PARTIAL treated as FAIL for the guarantee. |
| T-09-03 | Information disclosure | StayFree auth token / cloud account | accept | Token sits in Secret Service (libsecret), separate from and irrelevant to `.guardkey`; no nightguard secret changes. Low-value to the nightguard threat model. |
