# Phase 12.2.1 — UI Design Contract

> This is a **conformance contract, not a taste contract.** There is no palette to invent,
> no scale to choose and no five-family exploration to run. The panel already exists
> (`packaging/omarchy/plugins/danitrrga.nightguard/NightguardPanel.qml`, 650 lines) and
> already consumes the shell's live tokens. This document specifies exactly which token
> each **new** element binds to, which library component each **new** editable row is, and
> the layout / copy / interaction rules for the four editable blocking keys and the commit
> flow that gates them.
>
> Every component, token, glyph and exit code below was read off this box on 2026-09-13 and
> is cited `file:line`. Nothing here is aspirational and nothing here is invented.

## How this document diverges from the template

| Template asks for | This target has instead |
|---|---|
| shadcn / registry | `qs.Ui` — the shell's own component library at `/usr/share/omarchy/shell/Ui/` (34 components). Not installable, not versioned, read from disk at runtime. Registry-safety section is answered under §11. |
| An 8-point px spacing scale | `Style.space(px)` — a *scaled-rem function*, not a grid (`Commons/Style.qml:213-223`). Multiples of 4 would fight the shell. See §3. |
| 3–4 fixed px font sizes | Eight derived tokens off `[font] base-size` (`Commons/Style.qml:327-334`). The contract picks four of them for new elements. See §4. |
| A 60/30/10 hex palette | Five palette roles, all theme-supplied (`Commons/Color.qml:19-23`), zero fixed hex permitted. See §5. |
| Font weights 400/600 | The kit exposes `font.bold` only — exactly two weights and no third is reachable. |

## 1. Design System

| Property | Value |
|----------|-------|
| Tool | none (the desktop shell *is* the design system) |
| Component library | `qs.Ui` — `/usr/share/omarchy/shell/Ui/` |
| Token singletons | `qs.Commons` — `Color.qml`, `Style.qml`, `Border.qml` |
| Icon library | Nerd Font glyphs resolved through the `monospace` fontconfig alias (`Style.qml:269-275`). No icon package, no borrowed brand marks. |
| Font | `Style.font.family` (= `Style.fontFamily`, default `"monospace"`). Inside this plugin, read `bar.fontFamily` first and fall back to `Style.font.family` — the existing file's `root.fontFamily` (`NightguardPanel.qml:43`). |
| Live restyle | Automatic. `Color`/`Style` are singletons re-populated by `applyShellValues()` on theme IPC (`Style.qml:384-440`); every binding through them repaints with no restart. **This is the whole reason the surface moved from a terminal to QML.** |

### 1.1 The one binding rule

Every new visual value MUST be a binding to `Style.*` / `Color.*` / `Border.*` or to a
`root.*` property that is itself such a binding. A literal pixel number, a literal hex
colour or a literal font size in the new code is a defect, not a style preference.

Two literals are permitted and only these two, both already precedented in the file:
`Style.space()` returns `0` for non-positive input, so `Math.max(1, Style.space(n))`
(`NightguardPanel.qml:215`, `BarWidget.qml:271`) and `Math.max(2, Style.space(3))`
(`NightguardPanel.qml:192`) keep a hairline visible at tiny density scales. The literal is
the *floor*, never the value.

## 3. Spacing

### 3.1 The scale is a function, not a grid

`Style.space(px)` multiplies by `effectiveSpacingScale` (theme `[spacing] scale` × font
scale) and rounds, with a floor of 1 (`Style.qml:213-223`). Themes make the whole shell
denser or roomier by changing that one multiplier. **A hardcoded 8-point grid would be the
single element on screen that does not respond to `omarchy theme set`** — which is the
failure mode that got Phase 12.1 rejected.

### 3.2 Semantic tokens — use these first

Where `Style.spacing.*` has a token for the job, use the token, never `space(n)`
(`Style.qml:231-261`):

| Token | Default | Use for |
|---|---|---|
| `Style.spacing.rowGap` | 8 | Vertical gap between rows inside one section |
| `Style.spacing.rowPaddingX` | 12 | Horizontal inset of a row's content from its own edges |
| `Style.spacing.controlGap` | 8 | Gap between a field and its trailing action button |
| `Style.spacing.controlPaddingX` / `controlPaddingY` | 10 / 6 | Padding inside a `Button` chip |
| `Style.spacing.inputPaddingY` | 7 | `TextField` vertical padding (leave at default unless the row is compact) |
| `Style.spacing.controlHeight` | 28 | Reference height for a control row |
| `Style.spacing.labelGap` | 4 | Label → value gap inside a stacked cell |
| `Style.spacing.xs` / `sm` / `md` / `lg` | 3 / 4 / 6 / 8 | Generic small gaps when no semantic token fits |

### 3.3 The `space(n)` ladder — closed set

When no semantic token fits, `n` MUST come from the set already in use in this file:
**`2, 3, 4, 5, 6, 7, 8, 10, 12, 14, 16`**. Adding a value to this set is a contract change,
not an implementation detail.

Fixed by precedent and not re-litigated here:
- Section gap (the `Column` spacing): `Style.space(12)` — `NightguardPanel.qml:348`.
- Gap between a `PanelSectionHeader` and its first row: `Style.space(6)` — `network/Panel.qml:1302`.
- Card inner padding: `Style.space(8)` on each side with `implicitHeight + Style.space(16)` —
  `NightguardPanel.qml:438-452`.

### 3.4 No reflow

Carried from 12.1 D-05, and free here: every kit component reserves its widest border via
`BorderSurface` + `Border.controlSpec()`, so hover/cursor/focus change colour only.
**New rows must not change `implicitHeight`, `width`, padding or margin as a function of
hover, cursor or focus.** A row that grows when the cursor lands on it relayouts its
neighbours and is a defect.

The one permitted height change is *state*, not *hover*: a list row expands when its inline
editor opens, which is the network panel's own behaviour
(`network/Panel.qml:1668` — `implicitHeight: rowBody.implicitHeight + (isPasswordOpen ? … : 0)`).

## 4. Typography

### 4.1 The tokens

`Style.font.*` derives eight sizes from `[font] base-size` (default 12) unless a theme pins
one (`Style.qml:321-339`). **New elements use exactly four of them:**

| Role | Token | Default px | Weight | Used for |
|---|---|---|---|---|
| Section header | `Style.font.caption` | 10 | bold + `letterSpacing` from `PanelSectionHeader` | Section titles. Supplied by the component; never set by the caller. |
| Caption / secondary | `Style.font.caption` | 10 | regular | Machine facts, entry counts, refusal detail, staged-cost line |
| Body-small | `Style.font.bodySmall` | 11 | regular | List entry text, `InfoRow` label and value |
| Body | `Style.font.body` | 12 | regular | `TextField` input text (the component's own default), `ButtonGroup` chip labels |
| Row title | `Style.font.subtitle` | 13 | bold | `Toggle.label` (the component's own default, `Toggle.qml:34`) |

`Style.font.heading` (dial headline) and `Style.font.display` (hero glyph) are **pre-existing
and untouched** — they belong to the hero, and the new sections must not reach for them.

### 4.2 Weights — exactly two

`font.bold: true` or nothing. The kit exposes no numeric weight and no third step. Emphasis
beyond bold is carried by colour role and glyph, never by a weight the kit cannot render.

### 4.3 Line height

Not a settable property on `Text` in this kit and not set anywhere in the shell. Multi-line
copy uses `wrapMode: Text.WordWrap` and the font's natural leading — the existing precedent
(`NightguardPanel.qml:487, 601, 614`). Do not introduce `lineHeight`.

### 4.4 Plain text, always

Every `Text` MUST carry `textFormat: Text.PlainText`. This is not cosmetic: user-entered
blocklist entries and process names are rendered here, and `AutoText` would let a hostile or
merely unlucky entry promote itself to rich text. The existing file sets it on all 21 of its
`Text` elements; `PanelSectionHeader.qml:17` documents the same reasoning.

## 5. Colour

### 5.1 Roles only — the hex ban stands

`Color` exposes exactly five base roles (`Color.qml:19-23`): `foreground`, `background`,
`accent`, `urgent`, `muted`, plus per-surface groups (`Color.popups.*`, `Color.tooltip.*`).
**There is no `success` and no `warning` role.** The four-role verdict palette 12.1 fought
for does not exist on this surface, and inventing one with a fixed hex is banned.

The panel's local derivations, already declared and reused as-is (`NightguardPanel.qml:39-43`):

| Local | Expression | Meaning |
|---|---|---|
| `root.foreground` | `bar.foreground` ?? `Color.foreground` | Primary text |
| `root.urgent` | `bar.urgent` ?? `Color.urgent` | Refusal, closed, tamper, destructive |
| `root.dim` | `Qt.darker(foreground, 1.55)` | Secondary text |
| `root.track` | `Style.selectedFillFor(foreground, Color.accent)` | Inert track / spent pip |
| `root.alpha(c, a)` | `Qt.rgba(…)` | Tinting helper |

### 5.2 The 60 / 30 / 10 split, as this surface expresses it

| Share | Value | Where |
|---|---|---|
| Dominant (~60%) | `Color.popups.background` | The `KeyboardPanel` card itself — supplied by the component, never painted by this plugin |
| Secondary (~30%) | `Style.normalFillFor(foreground, accent)` (α 0.04 on foreground) and `root.dim` text | Cards, control fills, all secondary copy |
| Accent (~10%) | `Color.accent` | The closed list in §5.3 |
| Second semantic | `root.urgent` | The closed list in §5.4 |

### 5.3 Accent reserve — the closed list

The existing file already gives `Color.accent` one consistent meaning: **the weakening
channel — the finite thing and the door it goes through.** New uses must join that meaning
or not exist.

Accent is permitted on, and ONLY on:

1. The edit-window inner arc on the dial (existing, 193).
2. The `editable HH:MM–HH:MM` legend dot (existing, 420).
3. The open-padlock glyph `󰌿` and the fill/border of the gate card when the window is open (existing, 441-462).
4. Remaining token pips (existing, 517).
5. **NEW** — the direction marker `▲` and its cost text on a staged change that loosens (§8.2).
6. **NEW** — the total-cost line above the commit button, when the total is non-zero (§8.3).
7. **NEW** — the selected chip's fill in the app-mode `ButtonGroup`, and the `ToggleSwitch`
   knob/track when checked. Both are painted by the components themselves from
   `Style.selectedFillFor(foreground, accent)` (`ToggleSwitch.qml:82-95`) and are not
   separately authored here.

**Not accent, deliberately:** a tightening. A tightening is free and unremarkable and is
drawn in `root.foreground`. Making every direction marker coloured would spend the accent
budget on the case that costs nothing.

**Control:** a grep over the new QML must find `Color.accent` / `accent:` bindings only at
the sites enumerated above. The count is checkable; "the accent looks about right" is not.

### 5.4 Urgent reserve — the closed list

1. The curfew arc on the dial (existing, 177).
2. The `cerrado` legend dot (existing, 400).
3. The closed-padlock `󰌾` and the gate card's fill/border when the window is shut (existing, 442-462).
4. The `n / 3` counter when zero tokens remain (existing, 528).
5. Warning cards (existing, 587-598).
6. **NEW** — `hoverColor` on a list row's remove button (§7.3).
7. **NEW** — a refused staged change and the disabled commit button's reason line (§8.2, §8.4).
8. **NEW** — a commit failure result line (§9.3).
9. **NEW** — the `ConfirmDialog` confirm button, painted by the component itself
   (`ConfirmDialog.qml:100-112` hardcodes `Color.urgent` on index 1). Not overridden: every

   irreversible button is correct rather than merely tolerated.

### 5.5 Meaning never rides on colour alone

Carried from the accessibility rule of Phase 12.1 (D-13) and mandatory. Every state that colour distinguishes must also be
distinguished by **glyph and word**:

| State | Glyph | Word | Colour |
|---|---|---|---|
| Tightening, free | `▼` | `refuerza · gratis` | `root.foreground` |
| Loosening, allowed | `▲` | `debilita · cuesta 1 ficha` | `Color.accent` |
| Refused | `✕` | the signer's own reason | `root.urgent` |
| No change | `·` | `sin cambios` | `root.dim` |

A monochrome rendering of this panel loses nothing a user needs.

## 6. Interaction contract

### 6.1 One cursor, shared by pointer and keyboard

Carried forward from 12.1 (UIX-02, D-02) and native here. The kit's contract is explicit in
`CursorSurface.qml:4-13`: *items must NOT read `containsMouse` for colour/border; mouse hover
updates the panel's cursor state at the root, and visuals derive from `hasCursor`.* That is
what guarantees one highlight on screen.

Every new interactive element therefore:

- Declares a cursor identity in the panel's own state machine (see §6.2).
- Binds `hasCursor: root.cursorActive && root.focusSection === "<section>" && root.cursorIndex === <i>`.
- Reports hover upward: `onHovered: function(on) { if (on) root.setCursor("<section>", <i>) }`
  (network's idiom, `network/Panel.qml:1584-1589`).
- Never paints from its own `containsMouse`.

`Toggle`, `Button`, `ButtonGroup`, `ToggleSwitch`, `TextField`, `PanelActionButton` and
`CursorSurface` all expose `hasCursor` and all emit `hovered(bool)` — no wrapper is needed
and none may be written.

### 6.2 The cursor model this panel gains

The existing panel has **no cursor at all**: `PanelKeyCatcher` routes Enter/Space to
`refresh()` and mnemonics `r`/`o` to the two buttons (`NightguardPanel.qml:314-326`), with a
comment saying a cursor was not worth building for two buttons. With four editable sections
that reasoning expires. The panel gains the first-party model:

```
property bool cursorActive: false      // false until the first j/k or hover
property string focusSection: "apps"   // "apps" | "allow" | "sites" | "commit"
property int cursorIndex: 0
```

Walk order, top to bottom, matching visual order:

| # | Section | Stops |
|---|---|---|
| 1 | `apps` | app-blocking toggle → mode chips → game toggle → each blacklist entry → the add field |
| 2 | `allow` | each allowlist entry → the add field |
| 3 | `sites` | site-blocking toggle → each blocked-url entry → the add field |
| 4 | `commit` | discard button → commit button |

`onMoveRequested(dx, dy)`: `dy` walks stops and crosses section boundaries at the ends;
`dx` walks *within* a stop that has lateral parts — the mode chips, and a list entry's
row ⇄ remove-button pair (`network/Panel.qml:1056-1061` is the shape to follow).
`onActivateRequested` activates the current stop. `onDeleteRequested` (`x`, free from
`PanelKeyCatcher.qml:78-80`) removes the list entry under the cursor — a keyboard path to
removal that does not require reaching the trailing button.

Keyboard-only operation must remain **complete**: every stop reachable with `j`/`k`, every
action on it reachable with `Enter`/`Space`/`x`, no action requiring the pointer.

### 6.3 Text entry blocks the key catcher

`PanelKeyCatcher` takes keys **before** its descendants (`Keys.priority: Keys.BeforeItem`,
`PanelKeyCatcher.qml:47`). A `TextField` inside it receives nothing until the panel sets
`blocked: true` — this is documented in the component itself (`PanelKeyCatcher.qml:24-32`)
and is how network's passphrase field works (`network/Panel.qml:996`).

Contract: `blocked: root.editingEntry !== "" || confirmDialog.opened`. While blocked, the
field owns every key; `Esc` cancels the entry (`Keys.onEscapePressed` on the field itself,
`network/Panel.qml:1859`) and `Enter` submits (`onAccepted`). Getting this wrong produces a
text field that silently eats nothing and a `j` that scrolls the panel instead of typing —
which is exactly the "rudimentary" failure this phase exists to end.

### 6.4 The confirm dialog has no precedent — wire it this way

Verified on this box: `ConfirmDialog` is used in exactly two places
(`plugins/menu/Menu.qml:1119`, `plugins/clipboard/Clipboard.qml:400`) and **neither uses
`PanelKeyCatcher`** — both are full-screen surfaces with their own `Keys.onPressed`, where
`dialog.handleKey(event)` is the first branch (`Clipboard.qml:355`). No first-party *bar
panel* has ever hosted one. This composition is new and must be specified rather than
improvised.

Prescribed wiring — route the catcher's semantic signals into the dialog instead of calling
`handleKey`, which has no event object to receive here:

| Catcher signal | When `confirmDialog.opened` |
|---|---|
| `onCloseRequested` | `confirmDialog.canceled()` — never `root.close()`; Esc must dismiss the dialog, not the panel |
| `onMoveRequested(dx, dy)` | `if (dx !== 0) confirmDialog.selectedIndex = confirmDialog.selectedIndex === 0 ? 1 : 0` |
| `onActivateRequested` | `confirmDialog.selectedIndex === 0 ? confirmDialog.canceled() : confirmDialog.confirmed()` |
| `onTextKey` | swallowed — `r`/`o` must not fire behind an open dialog |

This reproduces `ConfirmDialog.handleKey`'s own semantics (`ConfirmDialog.qml:23-39`) exactly.
Mount it `anchors.fill: parent; z: 10` inside the `PanelKeyCatcher`, as Clipboard does
(`Clipboard.qml:400-403`).

**Cancel is the default.** `selectedIndex` opens at `0`. The component's own default is `1`
(`ConfirmDialog.qml:11`) — overridden here, because this dialog's confirm spends a finite
weekly token and a stray `Enter` must not spend it.

### 6.5 Timings

Take the kit's, do not invent: `ColorAnimation` 60 ms for cursor fills
(`CursorSurface.qml:38-40`), 100 ms for `Toggle` (`Toggle.qml:55`), 120 ms for the switch knob
(`ToggleSwitch.qml:87-98`). Tooltips are `PanelToolTip`, wired automatically by any component
with `tooltipText` set — never hand-built.

### 7.3 The editable-list row — one shape, used three times

```
CursorSurface (whole row is the target)
  ├─ Text        entry text, bodySmall, elide: Text.ElideRight, left
  ├─ Text        machine fact for this entry, caption, root.dim, right of the text (§7.5)
  └─ PanelActionButton  󰅙  hoverColor: root.urgent   tooltipText: "Quitar"
```

- A **staged removal** is not deleted from view. The row stays, its text goes `root.dim`, and
  a `✕` marker with `root.urgent` precedes it. A removal you cannot see is a removal you
  cannot reconsider, and reconsidering is the product.
- A **staged addition** appears at the end of the list with a `+` marker in `Color.accent`
  (adding to an allowlist loosens) or `root.foreground` (adding to a blocklist tightens) —
  the direction comes from `ngtui preview`, never from a rule written here.
- The **add row** sits last: `TextField` anchored between the section's left edge and the
  add button, `placeholderText` per §9.1. `Enter` stages, `Esc` cancels, the button stages.
- The allowlist **floor** (entries the allowlist cannot shrink below, from the machine facts)
  renders with **no remove button at all** and the caption `del suelo` in `root.dim`. A
  disabled button the user can aim at and get nothing from is worse than no button: the
  refusal is structural, so show it structurally.

Empty list → §9.2's empty-state copy in place of the rows, never a blank gap.

### 7.4 Section: `CAMBIOS PENDIENTES`

`visible: root.stagedCount > 0` — the section and its separator are absent entirely at zero
staged changes, so the panel at rest is exactly the dashboard it is today.

- One `InfoRow` per staged change: `title` = the human field name, `value` = the direction
  line from §5.5 built from `ngtui preview`'s `dirs` + `decision`.
- Then the total line (§9.1), caption size.
- Then a `Row` of two `Button`s, both `bordered: true`: `Descartar` then `Aplicar cambios`.

### 7.5 BLK-03 — what the machine knows and the config cannot

These facts are the requirement, not decoration. The fact vocabulary is inherited from
12.1's `home_controls()` (`ngtui/ngtui/widgets/controlrow.py:260-291`) and carries forward
unchanged in *meaning*:

| Fact | Where it renders | Copy shape |
|---|---|---|
| `unmatched_apps` | Per-entry caption on a blacklist row | `no coincide con nada` in `root.urgent` |
| `games` (detected titles) | `Toggle.description` on game blocking | on: `N títulos detectados`; off: `N títulos instalados, sin cubrir` in `root.urgent` when N > 0 |
| `always_allowed` floor | Per-entry caption on an allowlist row | `del suelo` in `root.dim`, no remove button |
| `enforcement` | A caption line under the apps section | `STRONG` → `jaula cgroup`; `WEAK` → `solo SIGTERM — más débil` in `root.urgent` |
| `browsers`, `policy_restored` | Caption under the sites section | `N navegadores` · `política restaurada {ts}` |

**Honest degradation is mandatory.** STATE records that eight of nine of these facts had no
reader in 12.1 and *degraded to their documented defaults*, and that the WEAK alarm was
raised only when enforcement had actually been read. That rule is law here: a fact that was
**not read** renders as `—` in `root.dim` — never as its default, and never as an alarm.
A panel that says `solo SIGTERM` because nobody asked is lying in the direction that makes
the user trust the tool less.

## 8. The commit flow — cost before authentication (BLK-04)

### 8.1 Order of operations, as a contract

```
stage an edit
   → ngtui preview --from <tmp>          (unprivileged, no auth, no writes)
   → render direction + cost + any refusal on the row and in the total
   → user presses "Aplicar cambios"
   → ConfirmDialog states the consequence in one sentence
   → user confirms
   → ngtui commit --from <tmp>  →  pkexec  →  Omarchy's polkit agent dialog
   → result line, verbatim from the CLI
   → re-read state; never optimistic
```

**No polkit dialog may ever appear for a change the signer has already refused.** The commit
button is `enabled: false` whenever `decision.allowed === false`, and the reason is on
screen beside it before it is pressed.

### 8.2 The preview is the only source of direction and cost

`ngtui preview` returns `{dirs, loosening, decision}` — `preview_change`,
`ngtui/ngtui/backend.py:200-221` — where `decision` carries `allowed`, `costs_token`,
`reason` and `effective_spent` from the signer's own `quota_decide`. The panel **renders**
these. It never classifies a direction, never counts a cost and never decides a refusal.
`BLK-05` is this sentence.

Per-row rendering is §5.5's table. A refused row shows `decision.reason` **verbatim** — the
signer refuses for more than one reason (weekly quota, clock window) at different hours, and
copy that hardcodes one reports the other wrongly. That exact bug is on the record in
`edit.py:50-58`.

### 8.3 The total line

| Case | Copy | Colour |
|---|---|---|
| Free | `N cambios · gratis` | `root.foreground` |
| Costs | `N cambios · cuesta M fichas · te quedarán K` | `Color.accent` |
| Refused | `✕ no se puede aplicar: {decision.reason}` | `root.urgent` |
| Preview unavailable | `No se pudo calcular el coste. No se aplica nada hasta que se pueda.` | `root.urgent` |

`K` is `WEEKLY_TOKENS - (effective_spent + M)` — computed from the signer's numbers, floored
at 0, never an optimistic local guess (`edit.py:155-165`).

`M` follows BLK-02's per-list rule as the **signer** implements it. If that open decision
resolves to "one token per list touched", `M` is the count of lists touched and this line
needs no change; the panel reads `decision`, so the rule living in the signer is exactly
what keeps this contract stable either way.

### 8.4 Fail closed when the preview fails

If `previewProc` exits non-zero, times out, or emits unparseable JSON: keep the staged edits
visible, render the preview-unavailable line, and **disable the commit button**. A commit
whose cost could not be computed is a commit whose cost the user was not told — which is the
one thing the cost-before-authentication requirement (BLK-04) forbids. Do not fall back to a locally computed guess.

Give `previewProc` and `commitProc` the same 10-second watchdog `Timer`s the existing
`Process`es have (`BarWidget.qml:155-156`): a `Process` still running cannot be relaunched,
and a preview that never returns would freeze every subsequent edit.

### 8.5 Where the preview runs

On stage/unstage, not on the poll tick (CONTEXT, "Established Patterns"). The 30 s status
poll and the 5 s open-panel detail poll stay exactly as they are (`BarWidget.qml:158-173`).

## 9. Copywriting contract

**Language: Spanish (es-ES).** Derived, not chosen: the surface being extended is entirely
Spanish — `EL DÍA`, `FICHAS DE LA SEMANA`, `BLOQUEADO EN CURFEW`, `Puedes debilitar el
curfew`, `hasta que abra`, `Abrir ngtui`, `Actualizar`. English rows inserted into it would
be a visible defect. The register is the existing one: lower-case captions, upper-case
section headers, second person, plain, never punitive, never cute.

**One exception, deliberate: the signer is never translated.** Its `REFUSED (…)` and
`committed (…)` lines are surfaced verbatim inside a Spanish frame (§9.3). Translating a
refusal would put words in the trust boundary's mouth.

|---|---|---|
| Blocked apps, empty | `ninguna aplicación bloqueada — el watchdog no tiene nada que terminar` | `root.urgent` |

### 9.3 Errors and results

| Situation | Copy | Colour |
|---|---|---|
| Signer refuses (exit 1, stderr `REFUSED (…): …`) | `✕ rechazado — {última línea de stderr, verbatim}` | `root.urgent` |
| Nothing to write (exit 0, stdout `no-op: …`) | `· sin cambios: la configuración ya era esa` | `root.dim` |
| Committed (exit 0) | `✓ aplicado — {stdout, verbatim}` | `root.foreground` |
| **polkit dialog dismissed (exit 126)** | `✕ cancelado — no se autorizó nada, no se ha escrito nada` | `root.dim` |
| **polkit auth failed / not authorized (exit 127)** | `✕ no autorizado — no se ha escrito nada` | `root.urgent` |
| `ngtui` / CLI missing or unparseable output | `Detalle no disponible: el ngtui instalado no conoce «{subcomando}». Ejecuta el despliegue.` | `root.dim` |

126 and 127 are `pkexec`'s own, verified from `man pkexec` on this box: 126 = the user
dismissed the dialog, 127 = not authorized or an error occurred. The signer CLI returns only
0, 1 and 2 (`nightguard_ctl.py`, all `return` sites), so the two ranges cannot be confused —
and a user who *chose* to cancel must not be told he was refused. That distinction is why
these are two rows and not one.

The existing `detailFailed` copy at `NightguardPanel.qml:610` is the template for the last
row and stays.

### 9.4 Destructive confirmations

| Action | Confirmation |
|---|---|
| Commit that **loosens** | `ConfirmDialog` — `Esto DEBILITA tu pacto. Cuesta {M} de 3 fichas semanales. Después te quedarán {K}.` · cancel `Cancelar` · confirm `Aplicar` · `selectedIndex: 0` |
| Commit that only **tightens** | `ConfirmDialog` — `Esto REFUERZA tu pacto. No cuesta fichas.` · same buttons |
| Remove an entry from a list | No dialog. Staging is the reversible step; the commit dialog is the gate. The row stays visible, dimmed and `✕`-marked (§7.3). |
| Remove a floor entry | Structurally impossible — no button exists (§7.3). |
| `Descartar` | No dialog. Discarding costs nothing and restores the sanctioned state. |

Both commits confirm, not only the loosening. 12.1's TUI skipped the dialog on a
tighten-only commit (`STATE`, 04-05). Here it does not: every commit goes through `pkexec`
and a real authorisation dialog, so a silent path to that prompt would surprise the user
with an authentication request he did not ask for.

## 10. Accessibility and honesty

- **No colour alone** — §5.5, enforced by the glyph + word columns.
- **Whole rows are targets** — carried from 12.1 D-03. `Toggle` (`Toggle.qml:106-112`) and
  `CursorSurface` rows take the click anywhere; the trailing `PanelActionButton` is the only
  nested target and it sits outside the row's own `MouseArea`, as network does
  (`network/Panel.qml:1670-1679`).
- **No memorised bracket hints.** `r` (refresh) and `o` (open TUI) survive as mnemonics
  because they already exist, but every new action has a visible target. Nothing new is
  keyboard-only.
- **Pointer shape** — `Qt.PointingHandCursor` on every interactive element, and
  `Qt.ArrowCursor` when disabled (`PanelActionButton.qml:86`). Unlike the terminal, this
  surface *can* change the pointer; the affordance 12.1 had to give up is available here and
  must be taken.
- **A fact not read is `—`, never a default** — §7.5.

## 12. The controls this contract must pass

Each must be **armed and seen to fail** before being made to pass — the standard set in
`12.1-VALIDATION.md` and restated in CONTEXT's canonical refs.

1. **No fixed hex / no literal size.** A scan of the plugin's `.qml` finds zero `#rrggbb`
   literals and zero numeric `font.pixelSize` / `spacing:` values outside the `Math.max(1, …)`
   floors of §1.1. Arm it by injecting a literal and seeing it caught.
2. **Accent reserve.** Every `Color.accent` / `accent:` site in the new code is on §5.3's list;
   the count is asserted. Arm by adding an accent to a tightening row.
3. **Live restyle.** Two real `omarchy theme set` switches with the panel open repaint the new
   sections — fills, borders, chip selection and switch knob included — with no restart.
   This is ROADMAP success criterion 4 and is a human gate.
4. **One cursor.** Hover a list row with the pointer, then press `j`: the cursor lands on the
   *next* row, not on row 0. The 12.1 probe shape, now against QML.
5. **No reflow.** Every new row's `implicitHeight` is identical with and without `hasCursor`.
   Arm by giving one row a hover-only padding.
6. **Cost before auth.** With a staged loosening and 0 tokens, the commit button is
   `enabled: false`, the reason is on screen, and **no `pkexec` process is spawned** — assert
   on the process, not on the button, because a disabled-looking button that still fires is
   precisely the failure.
7. **Preview failure fails closed.** A `previewProc` forced to exit non-zero leaves the commit
   button disabled and the preview-unavailable line visible.
8. **126 ≠ 127 ≠ 1.** Three synthetic exits produce three distinct result lines, and the 126
   line does not say "refused".
9. **Text entry owns its keys.** With the add field focused, typing `jkx` enters `jkx` and
   moves no cursor; `Esc` returns keys to the panel.
10. **Dialog defaults to cancel.** The dialog opens with `selectedIndex === 0`, and a bare
    `Enter` on open cancels. Arm by leaving the component's default of 1.
11. **Unread facts render `—`.** With the fact readers stubbed to "not read", the enforcement
    line shows `—` and the WEAK alarm does not appear.
12. **Nothing existing regressed.** The hero, dial, legend, gate card, pips and warnings
    render identically to the pre-phase panel on the same fixture. The `IpcHandler.state()`
    seam (`BarWidget.qml:212-237`) is how this is asserted without a human looking at a
    screen; extend it with the staged-change count and the commit button's enabled state so
    controls 6, 7 and 10 are machine-checkable too.
